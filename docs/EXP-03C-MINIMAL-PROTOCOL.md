## 1. 固定问题、参数与威胁模型

### 1.1 参与方

- **D（数据所有者/索引发布者）**：建立索引与授权元数据，发布承诺根与签名；**本轮假设 D 在发布阶段诚实**，不研究 D 被攻破。
- **S（服务端）**：持有共享向量索引、节点属性、邻接表与认证路径；**可恶意**，可偏离协议任意行为。
- **C（查询客户端）**：持有秘密谓词 \(P\) 与授权凭证；不得读取未授权向量或元数据；本轮若仅诚实客户端被建模，则 C 的恶意行为只在凭证模型（§3）中单独处理。

查询 \(q\) 公开，预算 \(E\) 固定，避免同时引入查询隐私。搜索算法为确定性、固定预算的过滤 ANN 状态机；**不宣称全局精确 Top-K**。

### 1.2 固定参数

\[
N=10{,}000,\quad d=128,\quad E=100,\quad M=16,\quad K=10,\quad B=100
\]

并记 \(a\) 为谓词涉及的属性数量（本轮保留为符号）。\(\lceil\log_2 N\rceil = 14\)，\(\log_2 B \approx 6.64\)。

### 1.3 被固定的正确性目标

只追求 **G3-alg**：输出等于"指定过滤 ANN 状态机在承诺索引上执行 \(E\) 轮"的结果。G3-exact（全局授权精确 Top-K）继续按 EXP-03A §5 的失败结论排除，不在本轮重开。

## 2. 完整 Query 协议定义

### 2.1 发布阶段（D，一次性）

\[
R_I = \operatorname{Commit}(I) = H\big(\operatorname{root}_{MT}(I)\big),\qquad \sigma_D = \operatorname{Sign}_D(R_I,\ \text{ver},\ \text{params})
\]

其中索引记录为

\[
v_i = (id_i,\ \mathbf{x}_i,\ A_i,\ T_i,\ \mathcal{N}_i),
\]

\(\mathbf{x}_i\in\mathbb{F}^{d}\)，\(A_i\) 为 ACL 属性，\(T_i\) 为 TTL，\(\mathcal{N}_i\) 为邻接表。D 同时发布公开承诺参数与版本 `ver`。**注意**：若 Merkle 根仅是哈希，\(R_I\) 绑定的是"某个索引"，要绑定"正确构建的索引"还需 D 的构建过程可被审计；本轮按任务包假设 D 发布诚实，不展开。

### 2.2 Query 协议（十项必答）

记号：\([x]\) 表示两方秘密共享状态；\(S_t=(Q_t,V_t,R_t)\) 分别为候选优先队列、已访问集合、当前授权结果集。所有状态均保持在 2PC 内，任一方不得单独得到匹配位、访问地址或队列顺序。

1. **索引如何进入 RAM-2PC**
   两种入口，本轮选 **(i)** 作为主路线：
   - (i) 一次性初始化：双方以 S 提供的 \(I\) 作为其私有输入，运行 RAM-2PC 的 `Initialize`，把 \(N\) 条记录加载进 ROM/WOM。加载完成后在 MPC 内计算承诺并与 \(R_I\) 比较，不一致则中止。成本为 \(O(N(d+M+a))\) 规模的一次性开销，按任务包要求单独计入初始化，不摊入单次查询。
   - (ii) 惰性读取：每次秘密读出节点块时由 S 附带认证路径，在 MPC 内验证后使用；避免初始化，但每读一次付一次认证成本。§4 比较两者。

2. **索引根如何与每次实际读取绑定**
   \(\sigma_D\) 在协议开始时由 C（或公开验证者）验证，得到可信 \(R_I\)。若采用 (i)，初始化阶段一次性检查 \(\operatorname{Commit}(I)=R_I\)；若采用 (ii)，每次读出后在 MPC 内重算该区块到根的哈希路径并与 \(R_I\) 比对。**两种方式都不把验证放到 C 的外部**，否则 C 会看到访问地址 \(id_i\)，从而读到未授权节点标识。

3. **如何防伪造、遗漏、替换、旧版本**
   - 伪造/替换：由 (2) 的承诺/路径检查发现，MPC 内中止。
   - 旧版本：凭证绑定 `ver`，查询消息携带 `ver`；承诺根与版本一并签名，S 无法用旧 \(R_I\) 响应。
   - 遗漏：协议按固定 \(E\) 轮、每轮固定读块数执行，消息长度固定；S 不响应或提前中止只会造成可检测的中止（DoS），不能产生"看起来成功的错误结果"。
   - 注意：恶意中止的处理见第 10 项，它牵涉严格策略隐私，不能一句"检测到了"带过。

4. **距离计算如何执行**
   在 MPC 内对公开 \(q\) 与秘密读出的 \(\mathbf{x}_i\) 计算定点平方欧氏距离；坐标乘法/加法与比较都在秘密共享上完成。距离的定点误差边界需作为算法参数公开固定，否则比较结果可能依赖实现细节。规模 \(EMd=204{,}800\) 个坐标级运算（上界），见 §7。

5. **授权谓词如何参与搜索**
   \([P]\) 为 C 的秘密输入；在每一轮，对候选的 \([A_i],[T_i]\) 计算秘密匹配位 \([m_i]\)。\([m_i]\) 不以明文出现，直接作为下一阶段队列插入与结果插入的控制位。**这是与 Compass 式"解密后本地过滤"的分水岭**，也是 C1/C2 合取成立的关键。

6. **秘密队列如何更新**
   两种实现：
   - RAM 堆：以秘密比较与秘密 RAM 写维护 \(B\) 大小优先队列，每次插入 \(O(\log B)\) 次秘密访问；
   - 有界批处理队列：每轮把新候选与当前 \(B\) 个条目合并，用固定大小的 oblivious sort/select 网络产生下一轮 top-\(B\)，完全在电路内完成，不产生秘密 RAM 写。
   本轮把后者作为"专用结构"候选（§6-C），但目前**没有证明**它优于前者。

7. **如何隐藏地址、匹配位、停止状态、候选顺序**
   - 地址：来自 RAM-2PC 的秘密地址 \(\alpha\)，由 DPF/ORAM 隐藏；不向 S 或 C 单独揭示。
   - 匹配位：\([m_i]\) 以秘密共享存在，仅以无分支 `cmux`/`select` 进入状态转换。
   - 停止状态：不按"找到第 \(K\) 个授权候选"提前停止；固定运行 \(E\) 轮，结果不足 \(K\) 时用哑记录补齐。
   - 候选顺序：队列内部顺序仅以秘密排列存在；输出前不代理解密。

8. **如何固定执行预算和消息长度**
   - 固定 \(E\) 轮；每轮固定读 \(M\) 个邻居块（不足补哑块）。
   - 候选队列固定容量 \(B\)；结果固定 \(K\) 条，不足用哑记录补齐。
   - 所有协议消息按最大长度填充；中止与否本身是唯一可能的可变信号（见第 10 项）。

9. **如何只向客户端输出授权结果**
   2PC 采用**单方输出**模式：只有 C 得到 \(R_E\) 的 top-\(K\)。S 不接收结果，也不接收结果数量（数量固定为 \(K\)）。若真实授权结果不足 \(K\)，哑记录须在密文层与真实记录不可区分，否则 C 能推断"授权集合大小"这一超出结果的信息；这是输出编码层面的额外约束，不能省略。

10. **服务端恶意中止时如何处理**
    可检测中止：协议中止则 C 无输出，S 不能把它伪装成成功结果。但**中止信号是否泄露 \(P\)** 是严格策略隐私的核心问题：若采用 Zhang 2024 的 one-bit leakage 协议，敌手可通过最终 `Check` 的通过/中止获得一个关于全部输入与中间状态的谓词比特；这不能写成"没有泄露"。严格隐私路线必须改用无额外泄露的恶意 RAM-2PC（§5.2）。

## 3. 授权凭证模型（不得假设客户端任意提交谓词）

### 3.1 问题

若 C 可提交 \(P(x)=\mathrm{TRUE}\)，则即使 2PC 完全安全，客户端也能索取全部数据。这只解决谓词隐私，**不构成访问控制**。因此必须区分两个研究问题；本报告把它们分开处理。

### 3.2 最小可信授权方模型

D（或独立授权方 A）在查询前签发：

\[
\text{Cred} = \operatorname{Sign}_{D}\big(h_P = \operatorname{Commit}(P),\ \text{ver},\ \exp,\ id_C\big),
\]

其中 `ver` 绑定索引版本，`exp` 为过期时间。查询时：

1. C 把 \(P\) 与 `Cred` 作为秘密输入交给 2PC；
2. 在 MPC 内计算 \(h_P\) 并验证签名与 `ver/exp`；
3. 验证失败即中止，不进入搜索状态机。

服务端在整个过程中只看到固定长度消息，不知道 \(h_P\) 的语义和 \(P\) 的内容。

### 3.3 成本与开放点（必须单独报告）

- 在 MPC 内做公钥签名验证不是免费的；它属于**新增成本**，与 ANN 状态机无关，不能藏进"2PC 内顺带完成"。
- 若把验证移到 MPC 外（C 向 S 做 ZK 证明"我持有对 \(h_P\) 的有效签名"），可减少电路成本，但必须证明 ZK 中承诺的 \(h_P\) 与 2PC 中使用的 \(P\) 是同一个值；这需要一个兼容的承诺方案与绑定证明，同样不是零成本。
- 凭证过期与索引版本绑定意味着每次索引升级都要重签或引入可更新凭证；本轮不研究授权方自身的安全性，但这项开销必须计入完整协议成本。

**结论**：凭证模型可以最小化地写出，但它把"谓词隐私"变成了"带授权绑定的谓词隐私"，成本上升且属于独立子问题；不能把凭证验证当作已有 RAM-2PC 的附带能力。

## 4. 认证 RAM 设计

### 4.1 两种入口的成本对照

| 方案 | 绑定方式 | 认证成本 | 主要风险 |
|---|---|---|---|
| 初始化一次性认证 | 加载 \(I\) 时在 MPC 内算 \(\operatorname{Commit}(I)\) 与 \(R_I\) 比 | \(O(N)\) 一次性；之后读取无需逐块认证 | 初始化成本不可摊薄到单次查询；S 在加载时提供错误数据会被发现但查询已中止 |
| 逐读认证 | 每个秘密地址读出后验证 Merkle 路径 | 每读 \(O(\log N)\) 次 MPC 内哈希，共 \(EM\lceil\log_2 N\rceil=22{,}400\) 次 | 读取成本随 \(E,M\) 线性增长；路径验证放在 MPC 外会泄露地址给 C |

### 4.2 路径验证位置

- **MPC 内验证**（本轮主路线）：S 提供路径节点与兄弟哈希作为辅助输入，MPC 内重算根并与 \(R_I\) 比较。优点是不向 C 泄露访问地址；缺点是把哈希电路塞进 2PC。
- **MPC 外验证**：由 C 验证 Merkle 路径。C 立刻学到 \(id_i\)，即未授权节点标识，违反 C1。**排除**。
- **折中候选**：用向量承诺/多项式承诺把本次所有秘密读取位置批处理为一次 opening，在 MPC 内验证一次证明。这能把 \(EM\) 次路径验证压缩，但证明生成由 S 完成、验证电路仍在 MPC 内；本轮没有找到可引用的"现成低成本构造"，因此只作为候选记录，**不作为已解决**。

### 4.3 对"每节点单独验证完整路径"的判断

在现有材料下无法避免"每个秘密读都要以某种方式绑定承诺"：要么一次性把整个索引装进 RAM 并承诺，要么逐读带证明。批处理承诺是可能的优化方向，但本报告不声称它已经给出可证明的复杂度优势。

## 5. 安全游戏与证明目标

### 5.1 诚实地写明两个原语能提供什么

**Afshar 2015**（摘要与作者报告，全文受限）：

> "we present the first practical protocols for evaluating RAM programs with security against malicious adversaries."
>
> "For statistical security \(2^{-s}\), our protocol without preprocessing achieves a ratio of \(s\); our online-offline protocol has a pre-processing phase and achieves online ratio \(\sim 2s/\log T\), where \(T\) is the total execution time of the RAM program."

其安全目标是标准恶意安全（公开摘要与报告未声明额外泄露函数）；作者报告还明确把 "preventing selective aborts" 与 "ORAM initialization" 列为需要处理的问题。**全文受限，故本报告不对其常量成本作强断言。**

**Zhang 2024**（开放全文）：

> "We are able to prove that the protocol has end-to-end one-bit leakage."
>
> Figure 7（\(F_{\mathrm{RAM2PC}}\)）的 `Check` 命令：敌手提交一个谓词 \(P:\mathbb{F}_2^{|I|}\times\mathbb{F}_{2^\kappa}^N\to\mathbb{F}_2\)，若 \(P(\cdot)=0\) 则中止；且 "This command is allowed to be called only once."
>
> §7.3："our protocol has a one-bit leakage to the overall protocol (not each access operation)".
>
> §2.1 / §6：摊销通信 \(O(\log N + s + N/s)\)，最优 \(O(\sqrt N)\)；每次访问 \(O(\log N)\) 轮；内存为 ROM、WOM 与 stash 三部分，stash 满时执行 \(O(N)\) 的 Refresh。

这些是**原语事实**，不是对我们的协议的安全性保证。

### 5.2 严格策略隐私定义

服务端视图：

\[
\mathrm{View}_S = (\text{public params},\ q,\ E,\ \text{transcript},\ \text{abort status})
\]

**严格策略隐私游戏**：对任意两个都通过凭证验证的秘密谓词 \(P_0,P_1\)，即使敌手控制 S 并选择中止策略，\(\mathrm{View}_S(P_0)\) 与 \(\mathrm{View}_S(P_1)\) 仍不可区分（允许公开输入与固定输出长度带来的必然信息）。

**判定**：Zhang 2024 的 one-bit leakage **违反**此定义。其 `Check` 允许敌手把"是否中止"作为关于全部输入与中间状态的一个位；写成 \(\operatorname{Leak}_S(P)=0\) 是错误陈述。可改写为有界泄露模型：

\[
\operatorname{Leak}_S^{(t)}(P_0,P_1) \le t \ \text{bits},
\]

其中 \(t\) 为查询轮数内累计预算；**不能**把一次执行的"一位"自动视为永远一位：不同查询是不同 RAM 执行，除非把它们合并为一次执行并把输出分别交付，否则安全论证不自动跨执行成立。本轮不把这种合并当作已解决——多客户端单方输出与批处理交付会引入新的输出编码问题。

**严格路线**只能采用 Afshar 型无额外泄露恶意 RAM-2PC，或直接以电路型恶意 2PC 实现全部状态机；前者成本更高，后者在 \(N=10^4\) 下受随机访问限制。**这不是文字区别，而是协议选型的硬分叉。**

### 5.3 证明目标分层

| 目标 | 含义 | 本轮状态 |
|---|---|---|
| P1 谓词隐私（严格） | 上述游戏成立，含中止 | 仅 Afshar 型路线可满足；成本未闭合 |
| P2 索引绑定期货 | 读到的块确为 \(R_I\) 承诺的索引内容 | §4 构造可写，成本已列 |
| P3 执行完整性 | \(E\) 轮状态转换在恶意 S 下正确 | RAM-2PC 的恶意安全提供；需把 ANN 状态机编码为 RAM 程序 |
| P4 访问控制 | C 只能使用有效凭证绑定的 \(P\) | §3 可写，但签名验证成本单列 |
| P5 输出最小性 | C 只得到 \(K\) 条授权结果，无额外未授权元数据 | 需哑记录不可区分；可写 |

**不做** G3-exact 的证明（EXP-03A 已排除）。P1–P5 的可满足性在纸面上都能写出，但 P1 与成本的组合仍未闭合。

## 6. 三种实现路线

### A. 通用恶意安全 RAM-2PC

- 是否能跑完整状态机：**能**。把 \(S_t=(Q_t,V_t,R_t)\) 作为 RAM 内秘密状态，每轮执行 `access` 电路；Afshar 2015 与 Zhang 2024 都给出恶意安全 RAM 程序执行。
- 内存初始化与索引绑定：Afshar 的公开摘要/报告把 ORAM 初始化列为显式成本；Zhang 的 `Initialize` 要求双方共同初始化 \(N\) 个位置，若由 S 提供初值，需额外承诺检查（§2.2 第 1 项）。两者都不是"免费加载"。
- 秘密队列与 ORAM 访问：若用 RAM 堆，队列更新产生 \(EM\log B\) 次秘密 RAM 写；每次写要付 ROM/WOM/stash/Refresh 成本，不能按普通 \(O(\log N)\) 访问估算。
- 单方输出：Zhang 的 RAM-2PC 功能本身不直接规定单方输出语义；可在 2PC 最后一步只向 C 交付，但需见 §2.2 第 9 项的哑记录编码。Afshar 全文受限，单方输出细节未核实。
- 中止泄露：Zhang 有；Afshar 按公开摘要为标准恶意安全（无显式泄露函数）。
- 严格策略隐私：Afshar 路线可行但成本未知；Zhang 路线不可行。

### B. 2PC + 认证 RAM

- Merkle 根绑定 RAM：如 §4.1，一次性或逐读。
- 每读是否需要完整路径：**是**（除非采用批处理承诺候选，但那仍是未落地的优化）。
- 路径验证位置：必须在 MPC 内；外部验证泄露地址给 C（§4.2）。
- 更合适结构：向量承诺/多项式承诺批处理 opening 是候选，但本轮没有可引用的低成本现成结论；不宣称已解决。
- 避免逐节点完整路径：**未做到**；只能把成本固定为 \(EM\lceil\log N\rceil\) 次 MPC 内哈希，或等待批处理承诺的专门设计。

### C. 专用过滤 ANN 状态机

- **有界秘密堆**：\(B=100\) 很小，可考虑把队列实现为固定大小排序数组，用 oblivious sort/select 网络每轮重排，避免 RAM 堆的 \(EM\log B\) 次秘密随机写。这是对通用 RAM-2PC 的**结构级改写**，不是新增密码学原语。
- **多候选批处理**：每轮最多 \(M=16\) 个新邻居，可把距离与谓词计算按 \(M\) 批量化；但向量坐标运算仍是 \(O(EMd)\)，批处理只改常数与电路深度。
- **减少秘密随机访问**：唯一有实质希望的点是"用电路内排序换掉队列的 RAM 写"。以 \(EM=1600\) 计，完整 bitonic 排序约 \(EM\log^2(EM)\approx 1.8\times10^5\) 个比较器，换取省去约 \(10^4\) 次秘密 RAM 写；后者按 Zhang 摊销成本约每次 \(O(\sqrt N)\approx 10^2\) 场元素，量级 \(10^6\)。**这只是符号层面对比，比较器与场元素的实际代价不可直接相除**，因此不能据此宣称胜利。
- **固定预算的特殊结构**：\(E\) 固定、\(B\) 固定、每轮读块数固定，天然支持固定消息长度与固定轮数；这点与通用 RAM-2PC 的安全需求一致，不是额外创新。
- **明确的复杂度优势**：**尚未给出**。只能给出上述候选对比，不能给出可证明或可实测的优势结论。

## 7. 参数化成本估算

记 \(A=EM=1600\) 为候选上界，\(\ell=\lceil\log_2 N\rceil=14\)，\(\log_2 B\approx6.64\)。

| 项目 | 符号 | 代入参数 |
|---|---:|---:|
| 候选距离计算 | \(EMd\) | \(204{,}800\) 次坐标级乘加 |
| ACL/TTL 比较 | \(EMa\) | \(1600a\) 次秘密比较 |
| Merkle 路径哈希 | \(EM\ell\) | \(22{,}400\) 次 MPC 内哈希 |
| 堆式队列比较 | \(EM\log B\) | \(\approx 10{,}600\) 次秘密比较 + 同量级秘密 RAM 写 |
| 批处理队列比较（候选） | \(EM\log^2(EM)\) | \(\approx 1.8\times10^5\) 次比较，**无 RAM 写** |
| 索引秘密读 | \(EM\) | \(1{,}600\) 次 RAM 读 |
| 单次访问摊销通信（Zhang） | \(O(\log N+s+N/s)\) | \(s\approx\sqrt N=100\) 时约 \(10^2\) 量级场元素/次 |
| 初始化（单独计） | \(O(N(d+M+a))\) | \(\approx 10^4\times(144+2a)\) 场元素 + \(N\) 次承诺哈希 |
| 通信轮数（Zhang） | \(O(\log N)\) / 访问 | DPF 生成主导；不可写成常数轮 |

**网络主要组成**：初始化阶段的整块 ROM/WOM 传输；每次访问的 DPF 生成消息、ROM 读、stash 线性扫描、WOM 写；stash 满时的 Refresh（\(O(N)\)）；最终单方结果交付。认证路径哈希与队列比较消息叠加其上。

**明确不写**：不编造毫秒数、不把上述符号量换算成运行时间、不把构造性估算宣称为渐近下界。

**成本判断**：队列 RAM 写与逐读 Merkle 验证是两项可检查的主导项；专用队列与批处理承诺分别是针对它们的候选优化，但都还没有给出可核验的净收益。这是"有可计算的问题"，还不是"已解决的问题"。

## 9. 最终判决：**HOLD**（收窄到唯一问题）

### 9.1 判决

**HOLD**。本轮成功构造了一个**可闭合的最小协议**（§2–§5），没有再出现 witness 位置错误：\(P\) 是 C 的 2PC 秘密输入，S 不单独持有；秘密队列与匹配位以共享状态更新；索引根逐读或初始化绑定；输出单方交付；恶意中止被显式建模。

但它**仍然是通用原语的直接组合**：RAM-2PC 跑状态机 + Merkle/承诺绑定 + 凭证签名验证。按任务包规则，直接组合不构成 GO。

### 9.2 唯一需要继续解决的问题

> **在不接受 one-bit 中止泄露（即满足 §5.2 严格策略隐私）的前提下，把固定预算过滤 ANN 的"有界队列 + 批量认证读取"做成专用机制，能否在显式符号成本上优于通用恶意 RAM-2PC？**

这不是"再找一批论文"，也不是"加一个密码学组件"。它只要求一次纸面对比，且必须同时满足：

1. 严格隐私路线按 Afshar 型无泄露恶意 RAM-2PC 计价，不接受 Zhang 型 one-bit 泄露作为替代；
2. 专用队列以 §6-C 的有界批处理队列为基准，给出门数/场元素通信的显式表达式；
3. 认证读取按 §4 逐读或批处理承诺二选一，成本不得隐藏在"顺带验证"里；
4. 凭证验证成本单列，不得并入 ANN 贡献。

### 9.3 明确停止标准（这一次写完就判）

对上述唯一问题给出显式符号对比后：

- 若专用结构在主导项上**没有可核验的优势**（例如队列 RAM 写被消除但比较器通信反而更大，或严格隐私路线的恶意开销完全吸收收益），则 **NO-GO，关闭 PA-VFANN**，不再进入原型。
- 若专用结构在主导项上给出**可核验的渐近或明确常数优势**，且严格隐私成本不抵消该优势，才允许 **GO** 并进入最小原型。
- 不再因为"还有相邻工作没查"而延长 HOLD；本轮已经把相邻工作范围固定为 §8。

### 9.4 与上一轮 NO-GO 的关系

EXP-03B 的 NO-GO 针对的是"泛化政策隐藏可验证过滤 ANN"选题；本轮 PA-VFANN-14 是在用户重新收窄后，对**一个具体最小协议骨架**的再检验。两轮结论不冲突：上一轮关闭的是选题包装，本轮保留的是唯一一个仍可形式化且可反驳的协议问题，并给它配了停止标准。
