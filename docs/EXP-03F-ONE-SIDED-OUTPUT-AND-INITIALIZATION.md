## 1. 问题设置与结论摘要

参与方：\(P_1=C\) 客户端持秘密策略 \(P\) 与凭证；\(P_2=S\) 服务端持索引 \(I\)。双方执行固定预算过滤 ANN 的 RAM 程序；只向客户端输出结果 \(z\)。允许泄露 \(L_S=(R_I,\mathrm{ver},q,E,\text{public params})\)，服务端自己的私有输入 \(I\) 作为腐败方辅助输入。

本轮分水岭的四项答案：

| 分水岭 | 本轮答案 |
| --- | --- |
| 输出隐私：服务端完整视图能否不依赖 \(z\) 模拟 | **未闭合**：§2.3 的 w-key 泄露面 + §5.2 的模拟器 z 依赖 |
| 输出完整性：客户端能否验证每条结果线标签 | **有条件**：batching 版可用 label 成员检查；streaming 版需改 w-key 结构（§2.3） |
| 索引完整性：\(R_I\) 是否绑定到服务端参与计算的 RAM | **未构造**：\(x_2\) 进入 st、M 初始全零，需显式初始化程序（§3） |
| 执行隐私：固定逻辑访问是否足以隐藏物理访问 | **结构性论证**：语义 A 可行；1600 不是物理访问数（§5.3） |

## 2. Task 1：单方输出设计

### 2.1 O1 的可行性基础（结果线只向客户端解码）

**[P]** §2.2：输出 label \(Y\) 解码为 \(\operatorname{lsb}(Y)\oplus\tau(D)\)；若只公开 \((\mu,\tau(D)\land\mu)\)，评估者只学到 \(\mu_i=1\) 的位，且"such an adversary's view is then independent of \(f(x)\land\mu\)"。这直接支持：对结果线令 \(\mu=0\)，服务端拿不到结果位。

**[P]** §3.4：每个内存位 \(P_1\) 存两个 label + decommitment，\(P_2\) 只存一个；§4.4 streaming 版为 \(P_1\) 存 \(2S\) 个、\(P_2\) 存 \(S\sim2S\) 个。因此 garbler（客户端）持有完整结果线 wire-label 描述 \(D\) 与 \(\tau(D)\)。

**[D]** 因此 O1 的解码步骤在概念上成立：\(P_2\) 把结果线活动 label 交给 \(P_1\)，\(P_1\) 用自己持有的 \(D\) 与 \(\tau(D)\) 解码；\(P_2\) 因未获结果线 \(\tau\) 而不能解码。这**不是** Afshar 原论文给出的单方输出定理，而是对 §2.2 部分解码性质的协议扩展。

**[P]** §4.5 提供了一个方向性证据："at this stage, P2 only learns the labels for the final output but not the actual value"——论文在 cheating-recovery 变体中确实考虑过"持有 label 但不解码"的状态，但该变体最终仍为双输出，不能直接复用。

### 2.2 O1 必须逐项回答的六个问题

| 问题 | 回答 |
| --- | --- |
| \(P_1\) 能否可靠解码？ | **[D]** 能：\(D,\tau(D)\) 由 \(P_1\) 生成并持有，公式见 §2.2。 |
| \(P_2\) 能否从活动 label 恢复结果？ | **[D]** 不能从 label 本身：缺 \(\tau\)(result)；lsb 是 select bit，与真值独立。**但**可通过 §2.3 的 w-key 交叉泄露恢复，见下。 |
| §4.2 output-auth 能否扩展到结果线？ | **[U]** 不能原样扩展；见 §2.3。 |
| 需要哪些新增承诺/密钥/检查？ | **[C]** 至少：结果线独立的 w-key 族、与 inst 线分离的 \(\Delta\)、检查线程对结果线的验证规则、\(P_1\) 侧成员检查；具体结构待证明。 |
| 恶意 \(P_2\) 伪造/跨线程拼接/选择性提交/结果相关 abort？ | **[D]** batching 版（§3.2 3(g)）\(P_1\) 可做 label 成员检查；streaming 版（§4.2(j)）目前只检查 w-key。跨线程拼接因各线程 \(D(t,i)\) 独立而应被成员检查捕获 **[C]**；结果相关 abort 因 \(P_2\) 不解码结果而不可行 **[D]**，但 w-key 泄露一旦成立即失效。 |
| 恶意 \(P_1\) 模拟是否仍成立？ | **[U]** 需重证：\(P_1\) 作为 garbler 可控制结果线 label 与 w-key；原模拟器（§3.3/§4.3，\(P_1\) 腐败分支）假设双方都解码 z，扩展到单方输出后须重写。 |

### 2.3 ★新识别的泄露面：streaming w-key 跨线程共享

**[P]** §4.2(f)（p.719）：每个 timestep \(t\)，\(P_1\) 选随机 \(\Delta_t\)，对每个 inst-output 位 \(j\) 选 \(w(t,j,0),w(t,j,1)\)，**"the same across all threads"**，满足 \(w(t,j,0)\oplus w(t,j,1)=\Delta_t\)；对每个线程 \(i\) 用结果 label 加密 \(c_{i,j,b}=\mathsf{Enc}_{v_{i,j,b}}(w(t,j,b))\)。

**[P]** §4.2(i)（p.720）：检查线程中 \(P_2\) 解密 \(c_{i,j,b}\)（\(b\in\{0,1\}\)）恢复 \(w(t,j,b)\)，并检查 \(w(t,j,0)\oplus w(t,j,1)\) 在所有 \(j\) 上一致。

**[D]** 推导链：

1. w-key 在线程间共享，且检查线程明确向 \(P_2\) 揭示 \(w(t,j,0)\) 与 \(w(t,j,1)\) 两个值；
2. 若把同一机制原样扩展到结果线，检查线程将向 \(P_2\) 揭示结果线的两个 w-key；
3. 评估线程中 \(P_2\) 用活动 label 解密对应的 \(c_{i,j,b}\)，得到其中一个 w-key；
4. 与检查线程揭示的两个值比对，\(P_2\) 即可确定该结果位是 0 还是 1，**无需 \(\tau\)(result)**。

**[U]** 原文是否因 \(\tau\) 与 select-bit 的绑定而阻止这一步、以及 full version 是否对结果线另设 w-key，本轮无法核验（full version 受限）。因此该泄露面是**结构风险**，不是已实测泄露；但在补齐证明前，**不能声称 O1 在 streaming 协议上成立**。

**可修复方向（均为猜想级）**：结果线使用与 inst 线不同且**不跨线程共享**的 w-key；或改用 batching 版 §3.2 3(g) 的 label-成员检查路径（\(P_2\) 回传 label、\(P_1\) 对照 \(D\) 检查），跳过 w-key；或把结果线认证推迟到 cheating-recovery 电路（§4.5）内一次性完成。三者都需新的模拟器证明。

### 2.4 O2（XOR mask）单独审计

- **[D]** \(\rho\) 由 \(P_1\) 采样并作为自己的秘密输入；电路中 \(z'=z\oplus\rho\)；\(P_2\) 得到 \(z'\)，\(P_1\) 用 \(\rho\) 恢复 \(z\)。
- **[D]** 结果线 \(\tau\) 对 \(P_2\) 可开放到 \(z'\) 而不泄露 \(z\)（因为 \(\rho\) 对 \(P_2\) 未知）。输出真实性检查针对 \(z'\) 线，与单方输出功能一致。
- **[U]** 但 O2 仍继承 §2.3 的 w-key 泄露面：若 \(z'\) 线用 streaming w-key 认证，\(P_2\) 可恢复 \(z'\)，虽不等于 \(z\)，但 \(z'\) 的固定性仍可能构成允许泄露之外的信息；需明确列入 \(L_S\) 或修复。
- **[D]** O2 额外成本：\(|z|\) 个 XOR 门 + \(\rho\) 的输入一致性检查；不比 O1 天然更便宜。结论：若 O1 的路径能闭合则优先 O1；O2 不是退路上的免费方案。

## 3. Task 2：索引初始化与承诺绑定

### 3.1 论文事实与问题定位

**[P]** §2.1：RAM 内存 \(M\) "initially set to \(0^n\)"；执行时 \(st:=x_1\|x_2\|0^n\)。即 \(x_2\)（服务端输入）进入**内部状态**，不自动进入内存。

**[P]** §1/§3.1：ORAM 初始化是一次性、与内存规模成正比的计算；§3.2 3(d)/§4.2(a) 中未初始化读走 `GetInputpub(...,0^n)`，只有"最近写入该地址的块"才通过 solder 传 label。

**[D]** 因此"服务端持有索引"≠"索引已进入 RAM 内存"。必须显式增加初始化阶段，把 \(I\) 的每个块写进 ORAM，否则后续查询读到的是全零或旧块。

### 3.2 候选 I：RAM-2PC 初始化程序逐块写入

设计 **[C]**：把一个初始化 RAM 程序 \(\Pi_{\text{init}}\) 作为同一 RAM-2PC 的前 \(T_{\text{init}}\) 步，\(P_2\) 以 \(x_2=(I,\text{seed})\) 提供块，程序逐块执行 `(write, addr, block)`；写后内存 label 由 §3.2 3(d)/§4.2(a) 的 solder 机制自然传承。

- **[D]** 优点：与 Afshar 的 label 复用机制兼容，不需要新原语；初始化后查询可复用同一状态。
- **[U]** 问题：\(x_2\) 通过 `GetInput2` 的 \(s\)-wise OT 输入（§3.2 3(c)、§4.2(d)），其长度 \(|I|\) 巨大，初始化 OT 与电路规模均为 \(O(s|I|)\)，须单列为一次性成本。
- **[U]** 问题：写入过程中服务端可写入与 \(R_I\) 不一致的块；必须有电路内检查。

### 3.3 候选 II：认证承诺/可验证初始化

设计 **[C]**：由 \(D\) 发布 \(R_I=\mathsf{Commit}(I)\) 与每个块的认证路径；\(P_2\) 逐块以 \(x_2\) 输入，\(\Pi_{\text{init}}\) 在电路内重算 \(\mathsf{Commit}\) 并与 \(R_I\) 比较；或采用认证 RAM/向量承诺使每次读都在 MPC 内验证路径。

- **[D]** 关键边界（用户强调）：**不能假设 commitment root 自然等于 RAM memory root**。Afshar 的内存是 wire-label 表示，承诺是对明文 \(I\) 的；二者之间必须由电路内的"明文块→承诺→\(R_I\)"检查建立可验证关系。
- **[U]** 每次读都验证 Merkle 路径的成本见 EXP-03C；本轮不重复设计，只指出：若采用逐读验证，则 §3.2 3(d) 的 solder 传承仍需保留，否则状态一致性断裂。
- **[D]** 回滚/版本：需在 \(R_I\) 中包含 \(\mathrm{ver}\)，并在电路内把 \(\mathrm{ver}\) 绑定到初始 st；否则服务端可在查询间回滚到旧 wire-label 状态。**Afshar 原协议无跨执行状态概念** **[P]**，这是新增需求。

### 3.4 承诺—状态绑定的最小验证关系（待证）

**[C]** 命题：存在电路内检查 \(\mathsf{CheckBind}(I_{\text{loaded}},R_I,\mathrm{ver})=1\)，使得通过检查后，后续所有读到的 wire-label 块都对应承诺 \(R_I\) 的明文块。要证明它需回答：

1. 初始化承诺重算在 MPC 内的门数与 OT 数是否可承受（\(O(|I|)\) 量级，参数未知）；
2. 写入后 label 状态与明文块的对应由谁保证——solder 只保证 label 连续性，不保证明文含义；
3. 多查询复用时版本计数器如何进入 st 且被客户端验证。

**[D]** 这三点全部未闭合，因此索引完整性目前是**最大缺口**，不是小细节。

## 4. Task 3：安全定义（草案）

### 4.1 理想功能

\[
\mathcal F_{\text{FilteredANN}}:\quad D:(R_I,\mathrm{ver}),\ S:I,\ C:(q,P,\mathrm{Cred},E)
\]

- 验证 \(\mathsf{VerifyCred}(\mathrm{Cred},P,\mathrm{ver},C)=1\)；
- 计算 \(z=\mathsf{FilteredANN}(I,q,P,E)\)，固定 \(K\) 条，不足用不可区分哑记录；
- 输出：\(S\mapsto\bot\)，\(C\mapsto z\)。

### 4.2 允许泄露与四种性质必须分开

\(L_S=(R_I,\mathrm{ver},q,E,\text{public params})\)，加上服务端自己的 \(I\)。必须分别定义且不可互相替代：

1. **无结果**：服务端 view 不含 \(z\) 或 \(z'\)；
2. **无谓词**：服务端 view 不含 \(P\)；
3. **无轨迹推断**：逻辑与物理访问序列不因 \(P\) 不同而分布可区分；
4. **无篡改**：客户端能验证 \(z\) 等于承诺索引上指定状态机输出（G3-alg，不是全局精确 Top-K）。

### 4.3 模拟器

**[C]** 目标：\(\mathcal S(1^\lambda,I,L_S)\) 模拟恶意 \(P_2\) 的完整 view，不含 \(P,z\)。输入含 \(I\) 与 \(L_S\)，不含 \(z\)。恶意 \(P_1\) 模拟器另需处理 garbler 控制结果与 w-key 的情形。

### 4.4 中止与多查询

- **[D]** 拒绝服务不可阻止；只要求中止不泄露 \(P\)；
- **[U]** 多查询下 \(\rho\)、查询 nonce、\(\mathrm{ver}\) 如何累积泄露未定义；
- **[D]** 固定 \(E\) 与消息长度是必要条件；但 §5.3 提醒逻辑固定 ≠ 物理固定。

### 5.2 模拟器 z 依赖的症结

**[P]** §2.1：ORAM 模拟器 \(\mathcal S(1^\lambda,z)\) 输出与 \(I(\Pi,M,x_1,x_2)\) 不可区分，即以最终输出 \(z\) 为输入。

**[D]** 我们的目标是 \(\mathcal S(1^\lambda,I,L_S)\) 且**不含 \(z\)**。语义 A 的逻辑序列与 \(P\) 无关，因此逻辑层面可以用公开参数模拟；但完整 view 还含物理访问、w-key 中止等分量。只要 §2.3 泄露面存在，模拟器中止与 w-key 分支就依赖结果位，而结果位依赖 \(P\)，模拟立即失败。**因此 §2.3 与 §5.2 是同一个缺口的两面。**

### 5.3 逻辑读 1600 的物理展开

\(E\cdot M=100\times16=1600\) 是逻辑邻居读。一次逻辑读展开为 ORAM 实例的物理 block 读写序列，次数 \(=O(\log N)\) 量级但依实例而变 **[P]** §2.1 只定义抽象。**不得把 1600 当物理访问数。**

## 7. 最终判决与停止规则

### 7.1 判决：HOLD

三个具体缺口，均可修复但均未闭合：

1. **输出认证**（§2.3）：streaming w-key 跨线程共享可能把结果位泄露给 \(P_2\)；需改为结果线独立 w-key 或 batching label 成员路径，并重写模拟器；
2. **索引初始化与绑定**（§3）：\(x_2\) 进 st 而 M 全零，需显式初始化 + 电路内 \(\mathsf{CheckBind}\)+ 版本防回滚；Afshar 无跨执行状态；
3. **无 z 完整视图模拟**（§5）：ORAM 模拟器以 z 为输入，物理访问与中止分支尚未在无 z 下模拟。

不判 NO-GO：没有出现"严格隐私与合理成本必然冲突"的证明；三项都是协议扩展问题。不判 GO：三项同时未闭合，且 §2.3 是新增的具体风险。

### 7.2 进入原型的门槛（全部满足才可 GO）

- 给出结果线输出认证构造，并证明 \(P_2\) 视图与结果位独立（含跨线程检查）；
