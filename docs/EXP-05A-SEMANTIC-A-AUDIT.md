## 1. 独立判断（结论先行）

**替换命题 (R) 在算法层成立，且本轮把证据从"函数签名检查"强化到"传递闭包静态证明"；但它在电路层的成立依赖一条此前未被显式陈述的结构条件，而完整视图的分布正确模拟仍未闭合。**

必须区分三个力度层级，不能混为一谈：

| 层级 | 本轮结论 | 证据强度 |
| --- | --- | --- |
| L1 算法层：逻辑轨迹与 \(P\) 无关 | **ACCEPT** | 强：源码 + 内置测试 + AST 传递闭包 |
| L2 电路层：garbled 电路 Π 的地址线不扇入 \(P\) 派生 wire | **结构性可接受，但依赖显式设计条件，未给出门级证明** | 中：原文 Π 公开固定 + 状态分区论证 |
| L3 完整视图：对全部允许输入生成联合分布正确的视图 | **UNKNOWN** | 弱：物理 ORAM + 联合分布两个缺口未闭合 |

## 2. 审计框架：为什么必须分三层

用户的核心担忧（第 2 点）是："如果策略 \(P\) 仍然影响内部状态转换，替换命题 R 就不能直接成立。"

这句话有一个必须先澄清的歧义——**内部状态 \(S_t=(Q_t,V_t,R_t)\) 不是铁板一块**：

- \(Q_t\)：搜索优先队列（距离键），驱动下一扩展节点与地址；
- \(V_t\)：已访问集合，驱动去重与 dummy 规则；
- \(R_t\)：结果累加器（授权结果集），驱动最终输出。

\(P\) **必然且允许**影响 \(R_t\)（结果本来就是按谓词过滤的）；但替换命题 R 只要求**地址序列**与 \(P\) 无关，而地址由 \(Q_t,V_t\) 及 RAM 内存读取驱动。因此：

> **(R) 的精确表述应为**：令 \(\mathrm{Addr}_t=\) 第 \(t\) 轮控制线解码出的逻辑地址。要求对所有允许 \((I,q,E,P)\)，\(\mathrm{Addr}_{1..E}=F(I,q,E)\) 与 \(P\) 无关；**允许** \(R_t\) 依赖 \(P\)，条件是 \(R_t\) 不进入任何地址线的组合扇入，且 \(R_t\) 走 \(\mu=0\) 隐藏的 result 线。

把"\(P\) 影响 \(R_t\)"误当成"\(P\) 破坏 R"，或反过来把"\(R_t\) 依赖 \(P\) 无所谓"当成"无需隔离证明"，都是错误的。这是本轮最重要的概念澄清。

## 3. 逐点审计（用户五问）

### 3.1 第 1 问：每一步状态转换是否只依赖 \(I\)、\(q\)、\(E\)？

**算法层（L1）：ACCEPT。** 硬证据三条：

1. `src/pa_vfann/search_common.py:87–97`：`plan_fixed_trace(query_distances_row, graph, budget)` 的 docstring 明写 "No policy, authorization label, match bit or legal-result count is available to this function. This is the E3 trace-invariance property."
2. `tests/test_algorithms.py:62–64`：`test_e3_plan_signature_has_no_policy_parameter` 用禁词集合 `{policy, policy_mask, authorization, authorized, mask, bits, legal_count}` 强制签名不含策略参数；`:67–73` 用两种不同策略断言 `visited_nodes`/`stop_position` 完全相等；`:76+` 的 `ForbiddenMask` 守卫一旦 plan 触碰授权位即抛异常。
3. **本轮新增静态验算**：对 `plan_fixed_trace → best_first_search` 调用闭包做 AST 分析，闭包为 `{plan_fixed_trace, best_first_search}`，两函数体内禁词标识符命中为空（`TRACE_PLAN_POLICY_FREE: True`）。这是比签名检查更强的传递闭包证据——即使策略参数被藏在辅助函数里也会被检出。

输入对应关系：`query_distances_row = f(q, I)`（查询到节点向量的距离）、`graph = I` 的邻接结构、`budget = E`。故算法层轨迹 \(=F(I,q,E)\)，与 \(P\) 无关。

**电路层（L2）：结构性可接受，未给门级证明。** 原文 §2.1（提取文本 105–111）：RAM 程序由**确定性电路 Π** 刻画，`st := x₁‖x₂‖0ⁿ`，每轮 `r ←{0,1}ⁿ; (st, inst, block) := Π(st, block, r)`。地址编码在 `inst` 里，P2 每轮经 §3.2 step 3(f) 开放 \(\tau(inst(D))\) 解码得到。由于 Π 是**公开固定**电路，只要 Π 被设计为"地址输出线的组合扇入不含 \(x_1=P\) 的任何 wire"，则地址与 \(P\) 无关就是**可静态验证的电路属性**，且 cut-and-choose 保证诚实执行用的是这个公开 Π。**但仓库尚无该电路的门级实现，故这条目前是设计约束，不是已验证事实。**

### 3.2 第 2 问：\(P\) 是否影响地址、队列更新、候选排序或停止状态？

这是决定性一问。四个对象必须分开回答：

| 对象 | 语义 A 下的答案 | 依据 / 边界 |
| --- | --- | --- |
| 地址 \(\mathrm{Addr}_t\) | **不影响**（算法层已证，电路层需扇入条件） | §3.1 全部证据 |
| 队列更新 \(Q_t\)（搜索优先队列） | **不影响**——这是语义 A 的定义性约束 | EXP-03E §7.2：\(P\) 只影响结果插入的匹配位与 \(R\) 内容，不影响 \(\ell_{1..1600}\) 与操作码序列 |
| 候选排序（**结果排序**） | **影响**——但允许，且必须隐藏 | `secret_filter.py` 对授权子集按距离排序得 `result_ids`；走 result 线、\(\mu=0\)，不在 P2 视图内 |
| 停止状态 | **不影响** | 固定 \(t=E\)，dummy 补齐；EXP-03E §7.2 第 7 项；原文 `do until halt` 改写为强制 \(t=E\) halt |

**关键发现（必须登记）**：EXP-03C §5 早期把匹配位 \([m_i]\) 写成"直接作为下一阶段**队列插入**与结果插入的控制位"——那是**语义 B**（谓词感知搜索），会让 \(P\) 进入 \(Q_t\) 的键，进而改变下一扩展节点与地址，使 (R) 失效。EXP-03E §7.4 已明确否定语义 B，并在 §7.2 把语义 A 收敛为 post-filter（\(P\) 不进队列）。**因此 R 成立的前提是最终实现采用语义 A 而非语义 B 的队列语义**；这不是可选项，是硬分叉。若为了召回率把匹配位重新塞进队列键，就退回语义 B，(R) 立即失效——召回率与轨迹隐私在此直接冲突（EXP-03A 已排除全局精确 Top-K）。

**结论**：在选定语义 A 的前提下，\(P\) 不影响地址、搜索队列更新、停止状态；只影响结果排序，而结果排序被隔离在 \(\mu=0\) 的 result 线。第 2 问不构成对 R 的反例，但**"必须采用语义 A 队列语义 + result 线严格隔离"是 R 的两个必要条件**。

### 3.3 第 3 问：客户端私有随机数是否影响服务器视图？

需区分三个随机源：

| 随机源 | 来源 | 是否进入 P2 视图 | 条件 |
| --- | --- | --- | --- |
| \(r\)（每轮 RAM 随机带） | 原文 `r ←{0,1}ⁿ`，§3.2 step 3(b) 经输入线注入 | 若 \(r\) 进入地址线则影响 | best-first 是确定性的（tie-break by node id），Π 必须显式令 \(r\) 不参与地址计算；否则 \(\mathrm{Addr}=F(I,q,E,r)\)，R 失效。**这是待写入电路规范的约束，当前未写。** |
| \(\rho\)（输出掩码，\(z'=z\oplus\rho\)，O2 方案） | 客户端私有 | 不影响，条件于严格隔离 | EXP-03F：\(\rho\) 只作用于 result 线且 \(\mu=0\)；若 \(\rho\) 进入 w-key 中止分支则泄露（EXP-03F §2.3 结果位依赖） |
| OT / `GetInput1` 选择位（\(x_1=P\)） | P1(garbler) | 不直接影响 | P2 只见 OT 输出 label，不见选择位语义（§2.2 point-and-permute + label 隐藏） |

**结论**：客户端随机数对 P2 视图的影响可以被限制住，但依赖两条**显式规范**：(i) 随机带 \(r\) 不进入地址线；(ii) \(\rho\) 严格限于 result 线且不参与任何 P2 可见分支。这两条在当前材料中是"设计意图"，不是已验证的电路规范，登记为 L2 待补项。

### 3.4 第 4 问：Solder/majority/check-eval 是否与轨迹发生额外耦合？

**关键辨析**：EXP-05 §4.1 的无 \(z\) 采样验算针对的是 **result 活动 label + solder 差值**；而轨迹经**控制线** \(\tau(inst\_ctrl)\) 解码。两者是不同 wire 分区（EXP-03G §2：`inst_ctrl` 开放、`result` 不开放）。

- **Solder**：原始结构下（EXP-03L：独立 \(\tau\)、跨电路独立 \(\Delta\)）solder 只开放差值 \(\Delta[i,b]=A[i,b]\oplus A'[i,\delta\oplus b]\)，是 label 域关系，与语义值无关。控制线与 result 线是不同 wire、独立 label，solder 本身不引入 \(P\to\) 地址的耦合。
- **majority**：同一逻辑 wire 的多电路结果取多数；控制线多数值 = 正确地址，result 线多数值 = 正确结果，两者独立 wire。只要 \(\tau(result)\) 不开放（\(\mu=0\)），result 的 \(P\)-依赖不会经 majority 混入控制线。
- **check/eval**：check 电路用随机输入检查电路正确性（非真实 \(P\)），全开不泄露真实策略——此为 Afshar §3.2 预处理语义，EXP-03L 已核对；eval 电路才用真实输入，且 eval 电路不全开。

**结论**：在原始随机结构 + 控制/结果分区 + \(\mu=0\) 三重条件下，Solder/majority/check-eval **不引入**额外的 \(P\to\) 轨迹耦合。但这是**分量级**论证（与 EXP-05 §6 缺口 3 一致）：同一 bucket 内控制线与 result 线经同一 `Adjust`/majority 流程，其**联合分布**未被形式化证明独立——分量独立推不出联合独立。登记为 L3 缺口。

### 3.5 第 5 问：模拟器能否生成"分布正确的完整视图"，而非只是"一条合理轨迹"？

**这是本轮必须最诚实回答的一问：不能。**

当前能生成的分量：

| 视图分量 | 能否由 \((I,L_S)\) 生成 | 状态 |
| --- | --- | --- |
| 逻辑地址序列 | 能（L1 已证，L2 结构成立） | 可生成 |
| 控制线 \(\tau\) 揭示 | 能（GC equivocation，EXP-05 §5） | 可生成 |
| result 活动 label | 能（无 \(z\) 采样器，λ=3 验算） | 组件级可生成 |
| **物理 ORAM 访问序列** | **不能确定性生成** | 需选定 ORAM 实例 + "逻辑序列→物理序列"模拟定理；Afshar §2.1 模拟器输入是 \(z\)（提取文本 122–124 行），我们要的是输入逻辑序列的版本，更强，未证（B4） |
| 消息长度 / 数量 / 中止 | 不能保证 | 定长规范 Afshar 未写，需新增（B4）；\(\rho\) 中止独立性未证（B3/EXP-03F） |
| **联合分布正确** | **不能** | 分量可模拟 \(\nRightarrow\) 联合可模拟（EXP-03G §4.2 条件 c）；控制线与 result 线出自同一 bucket 经 majority 耦合 |

因此：**"生成一条看起来合理的访问序列"与"对所有允许输入生成分布正确的完整视图"之间存在一道未跨越的鸿沟。** 前者本轮已强化到接近完成（L1+L2），后者仍是三个缺口的合取（物理 ORAM + 定长/中止规范 + 联合 hybrid）。任何把语义 A 审计通过写成"完整模拟器已构造"的说法都是过度声称。

## 5. 相对 B1 的增量（本轮真正的新东西）

1. **证据升级**：把 (R) 的算法层支撑从"函数签名检查"升级到"AST 传递闭包静态证明"，覆盖策略参数被藏进辅助函数的情况（`TRACE_PLAN_POLICY_FREE: True`）。
2. **概念澄清**：证明"\(P\) 影响内部状态"必须分区讨论——\(R_t\) 依赖 \(P\) 允许且必然，\(Q_t/V_t\) 不得依赖 \(P\)；把用户第 2 问的歧义消解为两个必要条件。
3. **新结构条件（核心增量）**：显式提出 (R) 在电路层的成立条件——**Π 的地址输出线组合扇入与 \(x_1=P\) 派生 wire（含 \(R_t\)、匹配位）不相交**，且随机带 \(r\) 不进入地址线。这是可在门级静态验证的属性，此前所有报告均以"结构性论证"一笔带过，从未精确陈述。
4. **语义 A vs 语义 B 硬分叉再确认**：EXP-03C §5 的"匹配位入队列键"属语义 B，与 R 不相容；最终实现必须用语义 A 的 post-filter。召回率代价是效用问题，不是安全问题，但构成选题权衡。
5. **力度约束**：明确"生成合理轨迹 ≠ 生成分布正确完整视图"，把 L1/L2/L3 三层钉死，防止把本轮通过误读为完整模拟器已构造。

## 6. 停止条件与下一步

**按用户设定的三条边界**：

- 若证明成立（\(P\) 不可避免影响服务器视图被证伪且完整模拟可建）→ 进完整联合模拟器：**本轮未达**，L2/L3 未闭合。
- 若发现 \(P\) 或客户端秘密状态不可避免影响服务器视图 → 判断有限修改：**本轮未发现**，无需修改检索语义。
- 若必须改变检索语义或引入不可接受成本 → 停止：**本轮不触发**。

**建议的下一优先级**（仍属用户后续决定，本轮不预承诺）：

1. **L2 门级条件**：给出 Π 的地址线扇入图 / 状态分区证明，或说明为何 cut-and-choose + 公开 Π 已足够——这是 (R) 的最后一块地基，且失败则 B1 替换失效。
2. **L3 联合 hybrid**：在选定 ORAM 实例后补"逻辑→物理"模拟定理与控制/result 联合独立性。
3. 之后才是 B3（恶意 P1）、B2（索引绑定）、B5（成本）。

**项目级口径不变**：原始 Afshar 直接单方输出仍为 REJECT（EXP-04 §2.2）；PA-VFANN 核心研究问题继续 HOLD。本轮的语义 A 通过仅指算法层地基 + 电路层结构条件，不外推为完整协议安全，也不复活任何已 NO-GO 的具体贡献。
