## 2. §2.5 的收紧：跨 bucket 结论改为条件性

### 2.1 严格适用范围（保留）

符号引理 \(\varphi_r\) 的严格对象限定为：**单个 EvalBucket** \(B_t\)（head \(h\) 与 eval 电路集 \(J\)）内，控制线 \(c\)、结果线 \(r\)、Solder 差 \(\{\delta_j[r]\}\)、\(\{\Delta_j[r,\cdot]\}\) 与活动标签的联合视图。原报告 §2.1–§2.4 的双射证明、条件纤维论证，以及 §2.5 的前两条推广继续成立：

- 同一 bucket 内多条结果线：令 \(\varphi_r\) 同时翻转所有结果线 \(\tau_e[r_i]\)，(T⊥) 逐 wire 独立保证联合测度保持；
- 同一 bucket 内跨 wire / 跨位相关：\(\Delta_e\) 贯穿该 bucket 全部 wire，\(\varphi_r\) 不动任何 \(\Delta_e\)，故 \(\Delta_j\oplus\Delta_h\) 跨 wire 恒定这一相关完整保留。

这两个推广**不依赖**任何跨 bucket 假设，维持 ACCEPT。

### 2.2 被收紧的部分

原报告 §2.5 第三条“结果累加线 \(R_t\)”写道：“对任何 \(\tau\) 隐藏的 wire，把 §2.3 中的 \(z\) 换成该 wire 的任意真值 \(v\)，同一 \(\varphi\) 证明其活动标签与 Solder 视图与 \(v\) 无关”，并据此称为语义 A 在 \(\lambda\) 一般情形下的符号版本。

**该表述在此收紧。** 对**单个 bucket 内**、\(\tau\) 隐藏的一条 wire，把真值从 \(z\) 换成任意 \(v\)，双射的代数部分确实逐点成立；但 \(R_t\) 是**跨 bucket 累加**的状态量，把它称为“已覆盖”隐含了一个未证明的前提：跨 bucket 的状态标签可以通过同一套单 bucket 变量与双射同时处理。用户指出这缺少明确的全局构造，具体三个未决问题为：

1. **状态标签的身份**：不同 bucket 的状态标签究竟是同一个随机变量，还是通过 Solder 关系连接的**不同**随机变量？原报告 §3.2 G9 写“上一 bucket 输出 label 焊到下一 bucket 输入”，但未定义这是否等同、以及经哪次 Solder、以哪个 head 为中介。
2. **双射的跨域作用**：上一个 bucket 的输出标签进入下一个 bucket 时，\(\varphi_r\) 如何**同时**作用于两侧？若两侧标签是同一变量，翻转一次即可；若经 Solder 连接，则需验证翻转 head 侧 \(\tau\) 后，Solder 公开量与下一 bucket 的 \(\delta,\Delta_j\) 仍逐点不变——这超出单 bucket 的 \(\Omega\)。
3. **跨 bucket 额外共享**：多个 bucket 的随机变量是否存在额外共享关系（同一 \(\Delta_e\) 被多个 bucket 复用、同一 head 跨 bucket 承接等）？若存在，变换是否仍保持**全部**联合约束？

### 2.3 收紧后的表述

> **跨 bucket 的隐藏状态标签（含 \(R_t\) 累加线）联合视图**：暂不单独 ACCEPT。单 bucket 内的局部代数不变性成立，但把它提升为跨 bucket 联合结论需要全局标签关联关系（§2.2 三问），该关系依赖 H3 的假 GC / 跨 bucket 一致性构造，而会议版 §3.3 只给 overview、full version 受限。**因此该推广从“符号引理覆盖”降级为“条件性、依赖跨 bucket 标签关系”，不写成已证。**

这一收紧消解了原报告 §3.2 第 3 点（承认跨 bucket 一致性需 H3）与 §2.5（把跨 bucket 纳入覆盖）之间的边界不一致：现在两处口径统一为“跨 bucket 属于 H3，不在 §2 的 ACCEPT 范围”。

## 3. §4.3 的收紧：H2 判决限定为单 bucket

原报告 §4.3 的替换对象写“对每个 bucket 的结果线（含 \(R_t\) 累加线）……”，依据引用“§2.5 把它推广到多结果位与跨 bucket 的隐藏 \(R_t\) wire”，判决为 ACCEPT。收紧如下：

- **H2（收紧后）**：在每个 bucket **内部**，把 result 线的活动 label、\(\delta_j[r]\)、\(\Delta_j[r,\cdot]\) 与该 bucket 已固定的 control 视图**联合地**重采样为不含 \(z\) 的采样器输出。判决：**ACCEPT（单 bucket、wire-label / Solder 层、任意 \(\lambda\)、条件 (T⊥)+P 原始结构）**。
- **H2 不再包含**跨 bucket 的 \(R_t\) 状态标签传递。该部分从 H2 的 ACCEPT 范围移出，归入 H3 的跨 bucket 联合一致性依赖（与原报告 §3.2 第 3 点、§4.4 M2 一致）。
- 原报告 §4.6 汇总表中 H2 行“result / \(R_t\) 标签 + Solder → 无 \(z\) 采样 … ACCEPT”相应理解为**仅单 bucket**；\(R_t\) 跨 bucket 部分不在该行覆盖内。
- 原报告 §1 结论表“H1→H2 result 标签 + Solder 视图替换 … ACCEPT”“§5.2 局部引理已闭合 … 跨 bucket 隐藏 wire 覆盖”两处，按本修正作同样限定。

**力度边界不变**：H2 的 ACCEPT 是可见标签层的分布相等，不是计算不可区分，也不覆盖 GC 表本身。

1. **EXP-07 冻结**：原报告 `a6ae5b8` 与本修正报告并列存档；本修正之后不再改动任一文件、不再启动 EXP-08、不再围绕同一局部双射做新枚举或新实例化实验。
2. **PA-VFANN 仍是 HOLD，不是已找到可写论文的协议**：本轮的可复用成果是一个**局部数学引理**（单 bucket 任意 \(\lambda\) 双射）；完整方案的可模拟性（H3/H4）、初始化绑定（B2）、真实电路忠实性（缺口①）均未闭合。
3. **本轮不是白忙**：排除了一个潜在的局部泄露担忧（result 与 control 联合视图不依赖 \(z\)，且已一般化到任意 \(\lambda\)），并把剩余问题准确落到完整构造（跨 bucket 标签关系、假 GC 等价码、ORAM 接口、物理网表），而不是停在小域实验里打转。
4. **项目级口径维持**：原始 Afshar 直接单方输出 REJECT（EXP-04）与已 NO-GO 的具体贡献（03B/03D）不变；核心研究问题（严格策略隐私 + 服务端持索引 + 客户端秘密谓词 + 单方输出过滤 ANN）继续 HOLD，未关闭。局部 ACCEPT 不外推为完整协议安全，也不构成论文贡献已确立。
