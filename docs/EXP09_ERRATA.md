# EXP-09 报告勘误（EXP-09.1 附带产出）

- 适用范围：仅记录 `docs/EXP09_REPORT.md` 与 `results/tables/exp09_summary_overall.csv` 中已确认的四处口径/表述问题。
- 本文件**不修改**任何历史报告、历史原始 CSV、历史汇总表或 EXP-01 文件；历史预注册结论（T2 未通过门禁）保持不变。
- 证据等级：`[原文]` 指代码/配置/CSV 中的直接内容；`[实测]` 指本轮重新运行代码或重算 CSV 得到；`[推导]` 指基于二者的算术判断。

## 1. `d10(t)` 单调性解释错误（报告 §3）

**原表述** `[原文]`：`docs/EXP09_REPORT.md:39` 写"best-first 访问序列的距离**非单调**（例如 query 0 的 d10 在 160.68–200.71 之间波动），因此 d10 收敛判据不是退化恒等式"。

**问题**：报告把"单个新访问节点的距离波动"与"`d10(t)` 的波动"混为一谈。

**代码事实** `[原文]`：`src/pa_vfann/policy_oblivious_stop.py:125-135` 用 `bisect.insort` 把新访问节点距离插入**已访问节点距离的有序列表**，`:134` 取第 10 小值；`:149-150` 由 `d10(t−m)` 与 `d10(t)` 计算 `Δ_t`。访问集合满足 `S_t ⊆ S_{t+1}`，因此：

\[
d_{10}(t+1)=\operatorname{kthmin}_{10}(S_{t+1})\le \operatorname{kthmin}_{10}(S_t)=d_{10}(t),\qquad t\ge 10
\]

即 `d10(t)` **必然单调不增**，`Δ_t ≥ 0` 恒成立（代码中分母取 `max(|d10(t−m)|, 1e-12)`）。

**独立复算** `[实测]`：用冻结配置重建计划后，对 query 0 / 1 / 50 逐个前缀按定义重算 `d10(t)`（`t=10..500`）：

| query | 单调不增 | 上升违约次数 | `d10(10)` | `d10(500)` |
|---|---|---:|---:|---:|
| 0 | 是 | 0 | 174.26 | 166.06 |
| 1 | 是 | 0 | 200.99 | 188.79 |
| 50 | 是 | 0 | 179.41 | 168.55 |

同一批查询的前 12 个**单节点**距离确实上下波动（如 query 0：`155.9, 171.7, 166.1, 164.8, 165.2, 160.0, …`），这才是报告里 160–200 区间的来源。

**正确结论**：T2 的 `Δ_t` 检测的是"已访问集合第 10 近邻距离的改善速率趋近于零"，不是距离上升/下降的振荡信号。本勘误只修正解释；T2 实现、停止位置与所有实验结果均不改变。

## 2. `random/clustered` 不是图拓扑（报告 §4/§5/§6）

**原表述** `[原文]`：`docs/EXP09_REPORT.md:45` 写"拓扑 random/clustered × 选择率 …"，§5、§6 亦沿用"拓扑×选择率组"。

**代码事实** `[原文]`：

- `src/pa_vfann/dataset.py:32-43`：只有一种数据集 `standard_normal`，10,000×128，seed 2026，无拓扑开关。
- `src/pa_vfann/graph.py:73` `build_graph(dataset, config)` 与 `config/experiment.yaml` 的 `graph:` 段：单一精确 kNN 图（出度 16、反向边并入），无 random/clustered 分支。
- `src/pa_vfann/policies.py:35-84` `build_policy(dataset, distribution, selectivity, sigma, n_centers)`：参数名即 `distribution`，取值 `random` / `clustered`，生成的是**授权标签掩码** `Policy.mask`；clustered 只是按到 3 个中心的 L2 距离加权抽样。
- `experiments/exp_common.py:109-116` `policy_for(...)` 对应 `policies.types: [random, clustered]`。

**正确表述**：random / clustered 是**两种授权策略分布**（授权标签的空间分布类型）；图、查询、种子和底层向量完全相同。后续文档应使用"授权策略分布"；历史 CSV 中的列名 `topology` 为兼容保留，**不重命名、不改数据**。

## 3. T1 `c=0.80` 分组门禁的浮点比较误判（汇总表）

**事实** `[原文]`：`results/tables/exp09_summary_overall.csv` 中 T1 `c=0.80` 的 `groups_passing_both=0`；`exp09_summary_by_group.csv` 中该配置 18 组 `visit_reduction` 均显示为 `0.2`，但 `gate_visit_020` 全为 0。T1 实现 `src/pa_vfann/policy_oblivious_stop.py:60` 用 `round(0.8·B)`，实际访问数为 80 / 160 / 400（预算 100 / 200 / 500）`[实测]`。

**原因** `[推导]`：汇总计算 `1 - 80/100`、`1 - 160/200`、`1 - 400/500` 的浮点结果均为 `0.19999999999999996`，与 `0.20` 直接比较得到假。

**容差重算** `[实测]`：以 `1e-9` 容差重算 18 组，`recall_drop ≤ 0.05 + tol` **且** `visit_reduction ≥ 0.20 − tol` 的组数为 **14/18**（严格比较为 0/18）。用户估计的"约 15/18"应修正为 14/18；未通过的 4 组为 clustered/1%/500 (0.108)、clustered/10%/100 (0.112)、random/1%/500 (0.089)、random/10%/100 (0.113) 的召回下降超限。

**不改变整体结论** `[推导]`：T1 `c=0.80` 平均召回下降 0.0353（≤0.05）、平均访问下降 0.2（≥0.20），但最大单组下降 0.113 > 0.10，预注册的整体条件仍失败；本报告不把容差修正写成"整体通过"，也不改历史汇总文件。

## 4. 时延结论缺 C0 p95 与执行顺序控制（报告 §6/§7）

**事实** `[原文]`：`results/tables/exp09_summary_overall.csv` 仅有 `c0_lat_ms`（C0 中位数 5.941 ms）与 T1/T2 的 `p95_lat_ms`，**没有 C0 p95 列**。从 `results/raw/exp09_confirmation_results.csv` 的 C0 `wall_ns`（1,800 行）直接计算：中位数 5.983 ms、`p95 = 16.776 ms` `[实测]`；同表 T2 的 `p95_lat_ms` 为 5.970–6.422 ms。

**额外局限** `[原文]`：`experiments/run_exp09.py:167-169` 的方法顺序固定为 `C0 → T1 → T2`，每个 `(条件, query)` 循环内 C0 总是先执行；本轮没有随机化方法顺序、没有交错多轮重复测量、没有预热分离。

**结论**：`unique_visited_count` 的下降是确定性、可复核的观察（访问序列与预算严格对应）；墙钟时延的相对改善（约 30%）在当前环境下只能视为**初步结果**，可能受冷启动/执行顺序与进程噪声影响。不据此宣称稳定的端到端性能优势。
