## 1. 最终回答

**在当前 synthetic exact-kNN 工作负载中，策略无关停止"总体上有空间，但不是普遍可行"。**

- 以 `δ=0.05`（要求前缀召回不低于该查询完整召回减 0.05）衡量，**63.22%** 的查询存在同时满足两类授权策略的 `≤0.8B` 稳健前缀（95% CI 60.78%–65.56%）；`δ=0.10` 时为 **85.44%**（83.44%–87.44%）。按任务书判据的第二分支：**多数查询能够在 0.8B 内达标，因此 T2 的失败不等于所有策略无关停止信号都不可行**。
- 但空间分布很不均匀：在 **1% 选择率 / 预算 500** 这一稀疏授权 + 大预算档，Oracle 平均需 `0.9188B` 才能稳健达标，`≤0.8B` 的查询仅 **8%**（3%–14%）；**10% / 100** 档也仅 13%。这些档位上 20% 的稳健访问节省存在**结构性困难**，即使离线知道全部召回曲线也无法达到。
- 困难**主要不是两类授权策略相互冲突**：`t*_random/B` 与 `t*_clustered/B` 的配对均值差仅 `-0.0055`（CI `-0.0155`–`0.0051`，跨零）；`t_robust` 相对单策略均值只增加约 0.046B。真正困难来自"稀疏授权 × 大预算 × 具体查询"下召回曲线本身很慢。

## 2. 方法与一致性核验

对每个 `(query ∈ 100..199, policy ∈ {random, clustered}, selectivity ∈ {1%,10%,30%}, budget ∈ {100,200,500})`：

1. 用冻结 config / seed 2026 重建同一图、查询距离表与授权掩码（`src/pa_vfann/policies.py:35-84`），用 EXP-09 的 `FullBudgetStopper` 重建**完整 E3 访问轨迹** `[原文]`。
2. 从 `t = ceil(0.6B)` 起按 E3 原访问顺序逐点取前缀，调用原 `truncate_outcome` + `simulated_secret_filter` + `recall_at_k` 计算 `R_{q,p}(t)`；授权掩码只进入**事后过滤与召回评估**，从不传入遍历/停止逻辑 `[原文]`。
3. 计算：
   \[
   t^*_{q,p}(\delta)=\min\{t\ge 0.6B: R_{q,p}(t)\ge R_{q,p}(B)-\delta\},\qquad
   t^{\text{robust}}_{q}(\delta)=\max_{p}t^*_{q,p}(\delta)
   \]
   `δ ∈ {0.05, 0.10}`；比较使用 `1e-12` 容差，避免浮点边界误判。
4. 以 query ID 为配对单位做 bootstrap（2,000 次），对均值、比例与配对差异给出 95% CI。

## 5. 判据回答与下一步含义

1. **是否有空间**：有。多数查询在 `δ=0.05`（63%）与 `δ=0.10`（85%）下存在 `≤0.8B` 的稳健前缀；因此不能从 d10 的失败推出"所有策略无关停止信号都不可行"。
2. **是否受授权策略差异的结构性限制**：不是主要限制。配对差异接近 0 且 CI 跨零；`t_robust` 与单策略 `t*` 几乎相同。结构性困难来自稀疏授权与大预算组合（1%/500、10%/100），这类档位即使 Oracle 也无法给出 20% 的稳健节省。
3. **本轮不做什么**：没有设计新停规、没有调参、没有加授权位或密码学机制；本轮结果只能用于判断"是否值得继续研究停止信号"，不能作为新算法的证据。
4. **若后续继续（需另行裁决）**：任何候选停规必须在 **1%/500** 与 **10%/100** 两个困难档单独报告，不能用总体均值掩盖；同时须保持策略无关性不变量，并报告 C0 的 p95 与随机化执行顺序（见 `EXP09_ERRATA.md` §4）。若在这些档位仍无法在不读授权信息的前提下识别"合法候选是否已足够"，则应关闭该机制。

## 6. 边界与不可主张内容

- Oracle `t*` 使用完整 E3 召回 `R(B)` 与两类策略的**事后**召回曲线，是**不可部署的理想上界**；不提供在线可实现性。
- `R(t) ≥ R(B) − δ` 是**相对**判据：困难档 1%/500 的 `R(B)` 本身只有 0.465 / 0.559，早停达标并不等于绝对召回足够。
- 授权掩码仅用于离线评估；本轮不声称查询隐私、输出隐私或完整访问模式隐私；停止位置仍随查询变化。
- 样本为 100 个确认集查询、合成精确 kNN 图、固定 seed 2026；结论不外推到真实 Agent 工作负载。
- 单次分析 2,000 次 bootstrap、固定 seed；CI 只反映 query-level 抽样变异，不含实现/硬件噪声。
