# PA-VFANN-10 / EXP-02 实验报告

**基线** `0145cca`（EXP-01，未修改） · **分支** `exp02-no-distance-oracle` · **日期** 2026-11-22
**目标** 去除全局距离预言机后，重新测量固定轨迹过滤 ANN 的召回、计算与通信代价。

报告中所有数值均来自 `exp02/results/`；【实测】= 直接测量，【解释】= 基于测量的推断，【猜想】= 尚未验证。

## 0. 实验设置与完整性

- 环境：CPython 3.14.0；numpy 2.x、pandas、matplotlib、pyyaml、pytest（见 `requirements.txt`）。
- 数据：10,000 × 128 向量、200 查询、种子 2026；精确 kNN 图（出度 16 + 反向并集，连通分量 1），与 EXP-01 同源。
- 授权：Random / Clustered，选择率 1/5/10/30%（实际授权数 100/500/1000/3000）。
- 预算：**一次节点扩展 = 1 预算单位**；取值 20/50/100/200/500/1000；E2 的 r ∈ {1,2,4}。
- 固定公开入口 `entry_node_id = 8817`，由种子离线生成并写入配置；测试验证它与查询、策略、授权标签无关。
- 搜索阶段无全库距离表；距离在节点发现时惰性计算并缓存，每个查询每个节点只算一次。
- 测试：**19 passed**（含 15 项任务包必测与 CSV 完整性测试）；全量运行命令：
  `python exp02/scripts/run_all.py`；单独诊断：`python exp02/experiments/equal_cost_check.py`。
- 原始 CSV **51,600 行**（48,000 选择率 + 3,600 策略对泄露），失败查询未删除；GT 为空时 Recall 为 N/A；汇总表 5 张、图 5 张。

## 1. 实验模型修正

【实测】EXP-01 的 `squared_l2_to_all()`、`np.argmin(row)` 与“任何节点距离可免费读取”已从所有搜索路径移除；全量精确距离只在独立的 `ground_truth.py` 中出现，不计入任何 ANN 成本列。源代码审计测试确认搜索模块不含全库距离计算。

【实测】新成本口径把“发现 / 访问 / 扩展 / 邻居检查”分开记录；`distance_evaluations` 等于实际惰性调用次数，且在每个查询中等于唯一发现节点数。

【解释】因此 EXP-01 的“访问节点数”不是完整检索成本，EXP-02 的距离计算数与候选传输字节数才是可比的成本口径。

## 2. 核心实测结果

### 2.1 召回与达标成本（均值，200 查询）

| 选择率 | E3 达 0.90 的最小扩展预算 | E3 距离计算 | E3 传输（ID+元数据） | E2 r=1 距离计算 | E2 r=1 传输 |
|---:|---:|---:|---:|---:|---:|
| 1%（Random/Clustered） | 200 / 200 | 7,635 | 61,083 B | 744 / 889 | 5,954 / 7,117 B |
| 5%（Random/Clustered） | 100 / 100 | 5,694 | 45,555 B | 2,202 / 1,388 | 17,620 / 11,110 B |
| 10%（Random/Clustered） | 100 / 100 | 5,694 | 45,555 B | 1,825 / 1,779 | 14,602 / 14,233 B |
| 30%（Random/Clustered） | 100 / 100 | 5,694 | 45,555 B | 3,859 / 3,786 | 30,875 / 30,289 B |

【实测】E3 在预算 100 时召回：Random 1/5/10/30% = 0.826 / 0.907 / 0.924 / 0.963，Clustered = 0.870 / 0.925 / 0.931 / 0.963；预算 200 时 1% 达到 0.950 / 0.968，其余 ≥ 0.978；预算 500 全部 ≥ 0.996。

【实测】E1 在全部 2×4 个格子中 **NOT_REACHED**（平均召回最高 0.624）；其早停率在预算 500 时均为 100%，总是在第 20 次扩展后停止，距离计算约 2,110、传输约 16,880 B。

【实测】E2 的 r=1 在全部格子达到 0.90；r=2、r=4 也全部达到，但距离计算随 r 单调上升（10% Random：1,825 / 3,451 / 4,695 / 5,694，依次为 r=1/2/4/E3）。

【实测】P95（预算 100）：E3 距离计算 6,473、传输 51,787 B；（预算 500）9,645 与 77,160 B。E1 的 P95 距离计算约 2,789，显著低于 E3，但其召回不足。

### 2.2 轨迹与输出泄露（策略对 × 200 查询 × 预算 100/500）

【实测】E3 在三组策略对上，`discovery / visit / expansion` 序列完全一致率 = 1.000，`L_set = L_seq = 0`，停止位置差 = 0，候选数与返回数差 = 0。

【实测】E3 的**输出 ID 泄露**仍为 0.942（Random 10% vs Clustered 10%）、0.994（Clustered 1% vs 30%）、0.997（Random 1% vs 30%），与 E1/E2 同量级。

【实测】E2 r=2 的发现集合泄露为 0.334–0.554、访问集合泄露 0.141–0.525；E1 的泄露约 0.000–0.001，因为它在三种策略下几乎都在第 20 次扩展处停止，但这是靠牺牲召回得到的。

## 3. 报告指定问题的回答

**Q1. 去掉全局距离预言机后，E3 的 Recall@10 下降多少？**
【实测】不能直接用相同“预算数字”相减：EXP-01 的预算是访问节点数、过滤对象是访问集；EXP-02 的预算是扩展次数、过滤对象是发现集，且每次扩展平均发现约 57 个节点（100 次扩展 → 5,694 个距离计算）。因此 EXP-02 在“预算 100”下的名义召回反而高于 EXP-01（如 Random 1%：0.826 vs 0.091）。这是成本口径改变造成的，不能解释为算法变强。
【实测】按**真实距离计算数**归一的补充诊断（`equal_cost_check.csv`）：约 221 次距离计算时 E3 召回仅 0.00–0.09；约 1,218 次时 0.23–0.41；约 2,111 次时 0.39–0.62。
【解释】固定入口而非全局最近点确实使近距离查询的起点变差，但“发现集过滤”大幅增加了同等扩展预算下的候选覆盖；两者共同作用，名义召回上升而真实计算成本上升。就“相同距离计算量”而言，固定轨迹方案仍明显落后于 EXP-01 中“免费全局距离 + 全局最近入口”的理想化设置。

**Q2. E3 达到 0.90 Recall 需要多少距离计算？**
【实测】1% 选择率约 7,635 次（预算 200）；5/10/30% 约 5,694 次（预算 100）。P95 分别为 8,218 次（预算 200，1%）与 6,473 次（预算 100，5–30%）。

**Q3. E3 的候选传输成本是否可接受？**
【实测】默认 ID+距离元数据（8 B/候选）为 45,555 B/查询（5–30%）和 61,083 B/查询（1%）；仅 ID 为 5,694–7,635 B；ID+完整向量（516 B/候选）约 2.94–3.94 MB/查询。
【解释】元数据模式在当前 10k 库上属于“单查询几十 KB”，是否可接受取决于应用带宽与批处理能力；完整向量模式明显不可接受，应避免。

**Q4. E1 的提前停止是否真正降低总计算成本？**
【实测】是：预算 500 时 E1 实际只扩展 20 次、距离计算约 2,110，而 E3 扩展 500 次、距离计算约 9,466（约 4.5×）。但 E1 从未达到 0.90 召回（最高 0.624）。在预算 20 时 E1 与 E3 的召回完全相同（E1 的早停尚未触发）。
【解释】早停降低了成本，却因固定入口下的局部候选池而把召回钉死；它不是一个有效的强基线。

**Q5. E2 的桥接机制在不同选择率下是否有效？**
【实测】r=1/2/4 均达到 0.90 目标；r 越大，距离计算与传输字节越高、边际召回增益越小。10% Random 达标预算均为 100，r=1/r=2/r=4/E3 距离计算为 1,825/3,451/4,695/5,694。
【解释】受控桥接在低选择率下特别有效（1% 用 744–889 次距离计算即达标，E3 需 7,635）。r=1 是该轮最有效的成本—召回点，代价是明显的轨迹泄露。

**Q6. Random 与 Clustered Policy 是否产生明显差异？**
【实测】同预算召回差通常 ≤ 0.02（如预算 100、1%：0.826 vs 0.870）；E2 的泄露指标有可测差异（r=2 发现集合泄露 0.554 vs 0.534 等）。
【解释】本轮聚类的空间相关性不足以改变总体结论，不能据此外推到更强聚集的授权分布。

**Q7. E3 的轨迹不变性是否仍然成立？**
【实测】成立。三组策略对 × 200 查询 × 预算 100/500：发现/访问/扩展序列完全一致，L_set = L_seq = 0，停止位置差 0。单元测试直接验证 E3 搜索不接收授权掩码。

**Q8. 哪些输出信道仍然泄露授权信息？**
【实测】输出记录 ID 的集合差异 0.942–0.997；E3 的候选数与返回数差为 0（因发现集规模与 K=10 固定），停止位置差为 0。轨迹信道被隐藏，输出内容信道没有。

**Q9. 哪个环节是当前最大的成本瓶颈？**
【实测】距离计算与候选传输同步增长（8 B/候选），预算 100 时 E3 为 5,694 次距离计算 / 45,555 B；高选择率下 E2 r=1 优于 E3，低选择率下 E2 优势更大。
【解释】主导因素是“每个扩展发现大量候选 → 每个候选都要算距离并传输”，而不是扩展次数本身。图的高反向度（最大无向度较大）放大了这一效应。

**Q10. 是否值得进入真实 ANN 索引实验？**
【判断】**有条件值得，但不应直接进入密码学构造。** 前置条件是先把成本模型搬到真实索引：惰性距离、按扩展计数、候选传输与客户端过滤分开计量。若真实 HNSW/过滤索引上 E3 仍需在 5k–8k 距离计算或 45–60 KB/查询才能达标，则应优先做候选压缩 / 分批过滤（用户给出的“修改”路线）；若届时 E2 的成本优势继续扩大而 E3 的轨迹隐私收益无法证明必要，则转向有限泄露的可验证过滤感知搜索（“转向”路线）。

## 4. 局限与边界

【实测】本轮使用受控精确 kNN 图模拟器，**不是 HNSW**，结果不得冒充真实索引性能；授权策略只覆盖两种分布与四种选择率；`secret_filter` 是模拟接口，不是密码学协议。

【解释】输出 ID 泄露、带宽成本与“轨迹一致性 ≠ 完整策略隐私”三项问题均未解决。EXP-01 与 EXP-02 的预算单位不同，跨版本名义召回不可直接比较；本报告用 `equal_cost_check.csv` 做了距离计算量归一。

【猜想】候选压缩、分批过滤或更小的客户—服务端交互协议可能显著降低传输成本；真实 HNSW 的分层结构可能改变 E2/E3 的相对成本；这些都没有在本轮验证。

## 5. 建议

本轮结论是“**E3 的轨迹不变性成立，召回可用，但计算与通信代价明显高于 E2，且输出仍泄露**”。建议进入 **EXP-03：候选压缩 / 分批客户端过滤的代价评估 + 真实索引的成本保真迁移**，在获得这批数据前不引入 MPC / ORAM / ZK，也不把当前模拟器结果包装为真实 ANN 性能。
