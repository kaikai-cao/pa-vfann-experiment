## 0. 本阶段定位与研究问题

### 0.1 从 3A.8 到 3A.9 的推进逻辑

3A.8 是一个**可行性**结论：在单个固定目标位置上，可以构造严格只差一个授权
位的反事实对 (A0, A1)，并可让两份 ACL 在同一索引、同一查询下实际运行 C0/C1/C2。
它观察到：C0/C1 的 observer trace 在 A0/A1 间逐字节相同；C2 不同。

**该现象尚不是统计证据。** 单个 ACL pair 不能给出方差、功效或可反驳的假设。
本研究的目标是把"观察到一个有意思的现象"推进为"可被独立样本验证、可被反驳
的统计假设"。

### 0.2 核心假设

- **H1（主要假设）**：在相同 HNSW 索引、查询与 ACL 过滤机制下，加入 K-hit stop
  （C2）比普通过滤搜索基线（C1）产生更高的**授权成员状态可区分性**。
- **主要比较量**：

\[
\Delta_{\mathrm{BA}} = \mathrm{BA}_{C2} - \mathrm{BA}_{C1}
\]

- **零假设**：\(H_0: \Delta_{\mathrm{BA}} \le 0\)
- **备择假设**：\(H_1: \Delta_{\mathrm{BA}} > 0\)（**单侧**）

BA = balanced accuracy，衡量攻击分类器区分目标成员授权状态的能力，
**不是**物理泄露量的直接测量。C0 保留为普通 `searchKnn` 对照，**不改变**
C1 与 C2 的主要比较关系。

### 0.3 三层结果必须分开（继承 3A.8）

| 层次 | 可得出的结论 | 本阶段状态 |
| --- | --- | --- |
| 配对完整性 | A0/A1 是否真的只差一个授权位 | 已验证（3A.8） |
| 观测可行性 | 目标是否进入 observer 可见范围 | 已验证（3A.8，单 pair） |
| Trace 敏感性 | 单比特变化是否伴随可观察轨迹变化 | 已观察（3A.8，**非**统计证明） |

本阶段要设计的是把第三层升级为**统计检验**的协议。第一、二层是准入前提，
不是攻击结果。

## 3. A. 统计单位与数据结构

### 3.1 定义

- **独立 ACL instance**：一次独立 CSPRNG 采样得到的 base ACL 位图（N=200），
  它是生成配对的唯一随机源。
- **ACL pair（配对）**：由一个 base ACL 派生的两份位图 \((A_0, A_1)\)，满足
  \(A_0[u]=0\)、\(A_1[u]=1\)、\(\forall i\ne u: A_0[i]=A_1[i]\)。pair 是**唯一
  的独立统计单位**。
- **观察样本（bundle）**：某一 ACL 状态下，同一组固定 6 条查询
  \(Q_1,\dots,Q_6\) 的 observer proxy trace 集合，作为**一个**特征向量。
  每个 pair 产生两个 bundle：A0-bundle（标签 0）与 A1-bundle（标签 1）。
- **pair ID**：仅用于分组（grouping），**绝不作为分类器特征**。

数据结构（概念示意）：

```
pair p                         ← 一个独立单位，一个分组标签
├── A0 bundle (label=0)
│   ├── Q1 observer trace
│   ├── ... 
│   └── Q6 observer trace
└── A1 bundle (label=1)
    ├── Q1 observer trace
    ├── ...
    └── Q6 observer trace
```

### 3.2 为什么六个 query 不能当六个独立样本

六条 query 共享同一 ACL 位图、同一索引、同一组搜索参数、同一目标成员状态。
它们**不是**独立 ACL instance。把它们当独立样本会把每 pair 的有效样本量从
1 虚增到 6（或 12），人为压窄置信区间、抬高显著性——这正是最容易把结果做
虚高的地方。本协议规定：

- bundle 内部 6 条 query 只用于**特征聚合**（见 6.2），不构成独立观测；
- 训练 / 验证 / 测试划分、bootstrap 重采样、功效计算**全部以 pair 为单位**；
- 若做了 query 级敏感性分析（见 6.4），其分组变量仍是 pair ID，**不是** query ID。

### 3.3 pair ID 的使用边界

pair ID 只出现在：分组标签、bootstrap 抽样单元、审计 manifest。
pair ID **不进入**任何特征向量、不进入模型、不进入任何可观察字段关联。

## 4. B. 数据集构造与随机性

### 4.1 每个 pair 的生成顺序（顺序本身是协议的一部分）

1. 目标选择**先于**任何 ACL 生成：用公开 seed 从完整成员集合确定 \(u=103\)。
   目标选择函数只接收公开量，不接收 ACL、位、距离、K-hit 位置、trace 或任何
   搜索结果。
2. 用 CSPRNG（`secrets.randbelow`，逐位）独立采样一个 base ACL（先验 \(p=0.1\)）。
   **不同 pair 的 base ACL 必须相互独立**；不得复用、不得由前一对派生。
3. 由该 base ACL 调用 `derive_target_pair` 同时派生 (A0, A1)，严格只翻目标位。
4. 校验不变量：成员数相等、`diff_indices(A0,A1) == [u]`、A0[u]=0、A1[u]=1、
   其余位逐位相同。任一失败则该 pair 作废并记为结构失败（见 10.2），**不得**
   通过换目标或改规则补救。
5. 用同一冻结 harness 对 A0、A1 分别运行 C0/C1/C2，写入**不同**输出目录。
6. 保存 internal diagnostics 与 observer proxy，但严格分层；只把 observer proxy
   交给后续特征构造。

### 4.2 随机性与可复现

- 目标选择：公开 seed，确定性、可复核。
- ACL 采样：系统 CSPRNG，**不可复现是特性而非缺陷**（保证 pair 间独立）；
  但为审计，须在私有 manifest 中记录每 pair 的派生 blob 摘要（仅用于完整性
  校验，**绝不**进入分类器或提交到仓库）。
- 索引与查询：冻结 seed=2026，所有 pair 共用同一确定性索引与查询集。因此
  pair 间的随机性**仅来自 ACL 采样**——这既保证了独立性，也意味着结论以该
  单一索引/查询为条件（见 11.2）。

### 4.3 私有材料的保存与防泄漏

- 所有私有 ACL blob、internal diagnostics、完整 manifest、trace 只在调用方
  指定的**私有临时目录**生成（执行阶段用 pytest `tmp_path` / 仓库外目录）。
- driver 只打印结构摘要，不打印位图内容、私有路径或授权计数。
- 提交前必须核对：`git status` 无任何 `*.bin` / `*.jsonl` / manifest；测试中已
  有 `test_private_artifacts_not_in_repository` 作为护栏，执行阶段必须保留同类
  检查。不得仅依赖 `.gitignore` 作为唯一防线。

### 4.4 版本、配置与环境记录（私有 manifest，不提交）

每个执行批次须在私有 manifest 记录：3A.4–3A.8 相关代码与 harness 的 commit SHA、
hnswlib 头文件 SHA（pristine 与 RM2 instrumented）、编译器及版本、全部公开 seed
与冻结常量、OS/CPU、运行时间戳。manifest 只用于复核，不进入仓库、不进入模型。

### 4.5 严禁提供给分类器的信息

`ACL bitmap`、任意授权位、目标真值、`internal_diagnostics` 全部字段、
pair ID、公开 seed 派生的目标排名。分类器**只能**接收 observer proxy 中
白名单字段的派生量。

## 5. C. 训练 / 验证 / 测试划分

### 5.1 划分方案（DEV / PILOT / CONFIRM 三阶段命名空间）

协议要求把 pair **在生成前**划分为三个**互不相交**的命名空间，用固定公开 seed
一次性确定并记入私有 manifest；**顺序不可颠倒，pair 不可跨阶段复用**：

| 阶段 | 命名空间 | 唯一用途 | 参与模型/特征选择 | 进入确认性检验 |
| --- | --- | --- | --- | --- |
| 开发 | `DEV` | 调试数据管线；分组 CV 选特征 / 超参 / 模型；训练并**冻结主模型**（6.3） | 是（唯一允许） | 否 |
| 方差先导 | `PILOT` | **仅**用已冻结主模型计算 \(d_i\)、估计 \(\sigma_d^2\) 与流程稳定性（10.2） | 否 | 否 |
| 确认性 | `CONFIRM` | 锁定测试集；模型冻结后**只评估一次**，计算 \(\Delta_{\mathrm{BA}}\) 与 pair 区间 | 否 | 是（唯一） |

- 三个命名空间的 pair ID 必须互不相交，随机流不同；不得把 DEV 或 PILOT 的 pair
  复用于 CONFIRM，也不得把 PILOT 的 pair 用于调参。
- `DEV` 内部再做 train / val 的**按 pair 分组**重复交叉验证（`GroupKFold`，
  `groups=pair_id`）。A0-bundle 与 A1-bundle 的 `group` 均为其 pair ID，因此
  必然同折，不会跨集合。
- `CONFIRM` 一旦锁定只评估一次；不得用于特征选择、模型选择、超参调整、种子选择
  或 \(\delta\) 的确定。
- `PILOT` **必须在主模型冻结之后运行**。若在 PILOT 之后改动特征 / 模型 / 超参 /
  种子，则原 PILOT 方差作废，必须用全新 PILOT pair 重新估计（10.2 第 5 步）。

### 5.2 为何不用单一 60/20/20

若只有 train / val / test 三组，方差先导要么取自 val（造成同一批 pair 既调参又估
方差、双重使用），要么取自 test（污染锁定测试集）。两者都不可接受，因此本协议
把 `PILOT` 独立成第三个命名空间。此外，在 pair 数量可能很小时，单次 holdout 的
划分方差过高，故 `DEV` 内部仍用分组 CV 而非单次切分。

若后续样本量足够大且审查组偏好简单设计，`DEV` **内部**的分组 CV 可改为一次性
train / val 划分，但**必须**同样按 pair 分组；DEV / PILOT / CONFIRM 三阶段隔离
本身不得简化。任何变更须在冻结协议前决定，不得看了结果再改。

### 5.3 绝对禁止

- A0 在训练集、A1 在测试集（同一 pair 拆散）；
- 同一 pair 的 query 分散到不同集合；
- `DEV` / `PILOT` / `CONFIRM` 命名空间重叠或 pair 跨阶段复用；
- 用 PILOT 或 CONFIRM 的 pair 做特征 / 模型 / 超参 / 种子选择；
- 在 PILOT 之后改模型却继续沿用原 \(\sigma_d^2\)；
- 根据测试集结果修改特征 / 模型 / 目标 / 查询；
- 先观察测试表现再挑选"表现最好"的目标位置、query 子集或随机种子。

## 6. D. 分类器与特征设计（只设计，不写代码）

### 6.1 攻击者可观察字段（白名单，来自 observer proxy）

允许进入特征构造的字段：

- `query_id`、`event_index`（R1 稠密观察序号）、`group`、`event_type`；
- 仅 `distance_eval` 事件额外携带：`external_id`、`level`、`dist_bits`。

**明确禁止**（即使它们出现在任何文件或派生量中）：
`extra`、`internal_id`、`auth_hits`、`khit_event_index`、`n_filter_ok`、
`n_filter_check`、`result_all_authorized`，以及任何 internal diagnostics 字段、
ACL 位图、pair ID。

说明：`group`（C0/C1/C2）是**分层维度**，不是特征——本协议为每种策略单独
训练/评估分类器（C1 一个、C2 一个，C0 作对照），不得把 group 混进输入。

### 6.2 特征构造（R3 已冻结；执行阶段不得改）

对每条 query 的 observer trace 计算固定统计量（仅用白名单字段）：

- 观察者事件总数；按 `event_type` 的计数（`distance_eval`、`candidate_consider`、
  `candidate_pop`、`stop_check`、`search_stop` 等；内部专用类型本就不在 proxy 中）；
- 目标可见性：`external_id == 101751` 是否出现在任一 `distance_eval`（0/1）、
  出现次数、首次与末次出现的观察序号；
- 若目标出现：其 `dist_bits`（按 float 位模式解释后的数值）与 `level`；若未出现，
  用固定哨兵值（协议冻结，不得按结果调整）；
- `search_stop` / `stop_check` 是否出现、次数、首次出现的观察序号；
- 末事件类型的 one-hot（取值域冻结为 proxy 实际可能出现的类型集合）；
- `distance_eval` 的 `level` 与距离分布摘要（min/max/mean）。

把 6 条 query 的上述量用**固定聚合算子**合并为一个 bundle 向量。

**R3 冻结的聚合与编码规则**（设计选择，依据为协议自身的可辨识性与去冗余逻辑，
非由数据反推；可审查推翻，但冻结后执行阶段不得改）：

- **聚合算子**：对每个跨 query 数值序列统一取 `mean / min / max / std` 四个统计量
  （**不含 sum**：query 数固定为 6，sum ≡ 6×mean，含二者引入完全共线冗余）；
  对出现次数 / 序号类整数序列同样取这四个统计量。
- **额外标量**：直接加入"目标可见的 query 数"（0–6）。
- **哨兵值**：目标未出现时 `dist_bits`（按 IEEE-754 位模式解释后的数值）取 \(-1.0\)，
  `level` 取 \(-1\)，首次 / 末次观察序号取 \(-1\)；这些值均在各自取值域之外
  （距离非负、level ≥ 0、序号 ≥ 0），不会与真实观测混淆。缺失值不做插补、不学习填充。
- **末事件 one-hot 取值域**：冻结为 observer proxy schema 实际枚举的
  `event_type` 集合，即 `distance_eval`、`candidate_consider`、`candidate_pop`、
  `stop_check`、`search_stop` 五类；执行时以 3A.7/R1 冻结 schema 为准并一次性写死，
  末尾若出现 schema 之外类型则记为 schema-change 停止条件（11.3），不得动态扩域。
- **标准化**：bundle 向量在 `DEV` 训练折上拟合标准化（标准化参数随主模型一并冻结）；
  PILOT / CONFIRM 只套用，不重拟合。

上述配置在冻结文件（16.1）中逐项记录；**不得在看到 PILOT / CONFIRM 数据后再选**。
冻结后执行阶段不得更改；任何改动须另开勘误阶段并说明对 H1 的影响。

### 6.3 主分类器方案（唯一冻结主模型）

- **主分析模型（唯一）**：L2 正则化逻辑回归，输入为标准化后的 bundle 特征向量，
  正则强度 \(C\) 在 **`DEV`** 的分组 CV 中选取，候选网格冻结为
  \(C\in\{0.01,0.1,1,10,100\}\)（五个数量级，覆盖从强到弱正则；设计选择，非数据反推）。
  类别天然平衡（A0/A1 各半），判定阈值固定 0.5 用于 BA。分别对 C1、C2 各训练
  **一个**主模型（C0 作对照）。
- **主随机种子（唯一）**：主分析只使用**一个预先冻结的主随机种子**训练出的**单一
  冻结模型**。该模型的身份（主种子、\(C\)、特征变换、标准化参数）须在 `DEV` 结束
  时写入冻结文件；`PILOT` 与 `CONFIRM` 只用它推断，**不再训练**。因此 \(d_i\) 的定义
  不随训练随机性漂移（8.4、10.2）。
  *若审查组坚持使用多种子集成*，必须在冻结前把集成的种子列表与聚合规则写死为
  **一个确定性分类器**，此后同样不得重训或重选；本草案的主分析**不采用集成**。
- **重复训练的定位（仅探索性）**：`DEV` 阶段允许用预先冻结的种子列表做固定次数的
  重复训练，**只用于报告训练稳定性（均值与离散度）**；**不得**据此挑模型、挑种子、
  挑测试分数，也不得进入主分析或改变 \(d_i\)。这是消除原草案"重复训练"与"固定
  分类器"口径冲突的关键约束。种子冻结为：主种子 `H1-RM.3A9-MAIN-SEED-20261126`；
  稳定性报告种子列表 `[1, 2, 3, 4, 5]`（固定 5 次）；两者均为确定性常数，仅固定随机性，
  不携带信息。三组 pair 命名空间划分种子 `H1-RM.3A9-SPLIT-SEED-20261126` 独立于主种子。
- **辅助分类器**（可选，仅探索性）：小容量梯度提升。其结果只作敏感性参考，
  不参与主要终点，不用于挑选模型，也不替代冻结主模型。
- **防测试污染**：超参、特征子集、阈值、种子、聚合算子的选择**只发生在 `DEV`**；
  `PILOT` 只估方差；`CONFIRM` 在模型与协议冻结后一次性评估。

### 6.4 允许的敏感性分析（不改变主终点）

- query 级分析：把每条 query 作为一行，分组变量仍为 pair ID（**不是** query ID），
  聚类仍按 pair。它只改变特征分辨率，不改变统计单位。
- 按"目标是否被 observer 可见"分层的报告（见 9.4）。

## 7. E. 统计假设与主要终点

### 7.1 假设与方向

- \(H_0: \Delta_{\mathrm{BA}} \le 0\)；\(H_1: \Delta_{\mathrm{BA}} > 0\)（单侧）。
- \(\mathrm{BA} = (\mathrm{TPR}+\mathrm{TNR})/2\)，在平衡测试 bundle 上、阈值 0.5 计算。

### 7.2 指标层级

| 指标 | 角色 |
| --- | --- |
| \(\Delta_{\mathrm{BA}} = \mathrm{BA}_{C2}-\mathrm{BA}_{C1}\) | **唯一主要终点** |
| \(\mathrm{BA}_{C0}\)、\(\mathrm{BA}_{C1}\)、\(\mathrm{BA}_{C2}\) | 主要终点的组成部分；C0 为对照 |
| ROC-AUC | 辅助（排序能力） |
| TPR / FPR | 辅助（误报漏报分析） |
| 自然先验 accuracy / precision | 辅助（部署解释，见 9） |

本协议**不假设** \(\mathrm{BA}_{C1}\approx 0.5\)：普通 ACL filtering 本身就可能
改变搜索与观察轨迹，C1 高于随机是可能的真实基线，不能仅凭此判定实验无效（见 7.5）。

### 7.3 显著性与区间

- 显著性水平：**单侧 \(\alpha = 0.05\)**。
- 配对 bootstrap 给出 \(\Delta_{\mathrm{BA}}\) 的分布；报告 90% 双侧区间
  \([q_{0.05}, q_{0.95}]\) 与 95% 双侧区间 \([q_{0.025}, q_{0.975}]\)。
- 拒绝 \(H_0\) 的规则：90% 双侧区间下界 \(q_{0.05} > 0\)（等价单侧 0.05）。
- **统计显著 ≠ 实践显著**：拒绝 \(H_0\) 只说明 \(\Delta_{\mathrm{BA}}>0\) 得到数据
  支持；是否达到最小有意义正向增量 \(\delta\) 须另行报告（10.1），两者不得互相
  替代。
- **不得只报点估计**；任何 \(\Delta_{\mathrm{BA}}\) 都须附带区间与重采样次数。

### 7.4 多重比较

- 主要终点只有一个，无需多重校正。
- 辅助指标（C0 相关比较、AUC、TPR/FPR、自然先验指标）**一律声明为探索性**，
  不用于支持 H1 的主要结论；若审查组要求把某一辅助指标升格为确证性，须在冻结
  前指定并用 Holm 控制族系错误率。

### 7.5 检验适用条件与 C1 基线解释

- pair 间独立（不同 base ACL；见 4.2 的条件性说明）；
- pair 数足以支撑 bootstrap 百分位区间（见 10 样本量）；
- **不要求 \(\mathrm{BA}_{C1}\) 接近随机**。本研究检验的是 C2 相对 C1 的**增量**，
  并未预先证明 C1 本身不泄露；普通 ACL filtering 就可能影响搜索与观察轨迹。
  \(\mathrm{BA}_{C1}\) 一律**独立报告**为普通过滤机制的基线：

  | \(\mathrm{BA}_{C1}\) / \(\mathrm{BA}_{C2}\) | 正确解释 |
  | --- | --- |
  | 0.50 / 0.70 | 明显增量信号 |
  | 0.65 / 0.75 | **仍有增量信号**，不得因 C1 高于随机而判定实验无效 |
  | 0.70 / 0.70 | 未观察到增量 |
  | 0.75 / 0.70 | 增量假设不获支持 |

  C1 偏高时**应**检查数据管线是否存在标签泄漏（必要的完整性核查），但
  "C1 偏高"本身不构成结果作废的充分理由；只有在审计**证实**内部诊断、ACL 位、
  真值或 pair ID 混入攻击者输入时，才按停止条件 11.6 处理。
- H1 的支持与否**只依据预注册的主要终点** \(\Delta_{\mathrm{BA}}\) 及其按 pair 的
  区间（7.3、8），不附加"C1 必须为随机水平"这一额外门槛。
- 若 C1 已高而 C2 未进一步提高，如实报告"未检出 K-hit stop 的增量"，不得据此
  反推实验失败，也不得事后改目标、查询或模型。
- 3A.8 单 pair 中 C0/C1 的 observer trace 逐字节相同，只是**单个 fixture 的观察**，
  不足以推出所有 pair 的 \(\mathrm{BA}_{C1}\) 都应为随机水平。

## 8. F. 配对 bootstrap

### 8.1 单位与重采样

- **bootstrap 单位 = ACL pair**，有放回抽取，抽满与原测试集相同数量的 pair。
- 每次抽样**保留完整 A0/A1 配对**：抽中 pair p 就同时纳入其 A0-bundle 与
  A1-bundle。
- **C1 与 C2 使用同一批重采样 pair**，确保 \(\Delta_{\mathrm{BA}}\) 的配对结构
  与共同随机性被保留。
- 每次重采样重新计算 \(\mathrm{BA}_{C1}\)、\(\mathrm{BA}_{C2}\) 与
  \(\Delta_{\mathrm{BA}}\)。

### 8.2 次数与区间

- 重采样次数 **\(B = 10000\)（R3 冻结）**（依据：百分位 CI 尾部 \(q_{0.025}\) 的
  稳定性；此为下限约定，低于此值须另开勘误说明）。
- 主报告用百分位区间；BCa 可作为稳健性对照，但不得只挑更显著的一种报告。
- 同时给出 bootstrap 分布中 \(\Delta_{\mathrm{BA}} \le 0\) 的比例作为辅助参考。

### 8.3 缺失 / 异常 pair

- **禁止**依据观察结果选择性删除 pair。
- 结构失败（配对不变量破坏、C++ loader 拒绝、C0/C1/C2 条件不一致）是**停止
  条件**（见 10.2），不是"剔除后继续"的理由。
- 若某 pair 因纯技术原因（如文件损坏）无法参与，按 R3 冻结的纯结构性排除规则
  （16.8）处理，并报告排除数量与原因；不得按 BA 表现排除。

### 8.4 主分析的推断边界（固定分类器）

主分析采用**固定已训练分类器**的口径：这里的"分类器"特指 6.3 定义的**唯一冻结
主模型**（唯一主随机种子，C1 / C2 各一个），它在 `DEV` 结束时确定，`PILOT` 与
`CONFIRM` 只用它推断、**不再训练**；测试集 bootstrap 只对 `CONFIRM` pair 有放回
重采样。因此区间度量的是：

> 给定该冻结主模型，独立确认性 pair 抽样造成的不确定性。

它**不自动包含**模型训练、特征选择、超参数选择、聚合算子选择带来的不确定性；
开发阶段的多种子重复训练只报告稳定性，**不是**主分析的模型集合，也不改变
\(d_i\) 的定义。若要覆盖训练流程不确定性，需对**完整训练流程**做嵌套重采样
（每折重新训练），代价更高，本协议当前**不采用**；如审查组要求升格为确证性
推断，须在冻结前明确改用该口径（见 14），不得在看到测试结果后追加。报告时必须
同时写明所用口径，避免把"固定分类器下的测试集区间"表述为"整个实验流程的总
不确定性"。

## 9. G. 自然先验与平衡诊断集

### 9.1 两个不同的世界，必须分开报告

- **平衡 case-control 诊断集**：A0/A1 各半，用于测分类能力。此集上随机基线
  BA = 0.5，绝不能称为"攻击成功率"。
- **自然成员先验 \(p = 0.1\)**：真实部署中目标成员授权的自然先验。

### 9.2 换算（在冻结的 TPR/FPR 上）

\[
\mathrm{acc}_{\text{natural}} = p\cdot\mathrm{TPR} + (1-p)\cdot\mathrm{TNR}
= p\cdot\mathrm{TPR} + (1-p)(1-\mathrm{FPR})
\]

\[
\mathrm{precision}_{\text{natural}}
= \frac{p\cdot\mathrm{TPR}}{p\cdot\mathrm{TPR} + (1-p)\cdot\mathrm{FPR}}
\]

其中 \(p=0.1\) 冻结。低先验下即便 TPR 较高，precision 也可能很低——必须明确
报告，避免把平衡集上的高 BA 误读为部署中的高攻击成功率。

### 9.3 case-control 与自然先验的关系

平衡配对采样改变了类别先验，因此 BA（对先验不敏感）才是主要比较量；自然先验
指标是由 TPR/FPR **推导**的部署解释量，不是独立测量。二者不得混用同一准确率
数字。

### 9.4 目标可见性只是辅助分层，不是样本筛选条件

- **所有 pair 一律进入主分析**，不以目标是否进入 observer 可见范围为筛选条件；
  目标可见性只作为**预先声明的辅助分层指标**（6.4）报告比例与分层结果。
- 若某 pair 中目标未进入 observer 可见范围，其 bundle 可能缺少目标专有信号；
  但完整 observer trace 中仍可能存在其他与搜索停止、遍历长度有关的信号，因此
  **不预断**该 pair 的 A0/A1 一定相同，也不预断其分类结果"不可区分"。
  实际结果由分类器在锁定测试集上给出并分层报告。
- 禁止只在"成功观察到目标"的样本上做主分析，禁止为此更换目标、查询或 ACL
  pair；也禁止依据分层结果事后剔除某一层。

### 9.5 自然先验指标的解释边界（R3 纳入）

对 9.2 的自然先验 accuracy / precision 换算，明确限定如下：

> 在预先固定的分类器及其既定判定阈值下，对自然先验部署情形的指标推导；不代表
> 经过自然先验校准或阈值优化后的最优部署性能。

即：这些指标是把冻结模型在阈值 0.5 下的 TPR/FPR 代入 \(p=0.1\) 的**一次推导**，
既未针对自然先验重新校准阈值，也未在该先验下优化模型；因此不得表述为"部署最优
性能"或"攻击可达到的最佳表现"，只作辅助的部署解释量（7.2、7.4）。

## 10. H. 样本量与统计功效

### 10.1 参数（预先固定）

- 显著性水平：单侧 \(\alpha = 0.05\)；
- 目标功效：\(1-\beta = 0.80\)；
- **最小有意义效应 \(\delta=0.10\)（R3 冻结）**：定义为**预先设定的最小有意义正向
  增量**（BA 点），即"只有 C2 比 C1 高至少 0.10 BA 点才具备实际研究价值"。因
  \(H_1\) 是 \(\Delta_{\mathrm{BA}}>0\)，\(\delta\) 是**正向门槛而不是绝对值**；
  若 \(\Delta_{\mathrm{BA}}<0\)，无论绝对值多大都不构成支持 H1 的证据。
  该值在看到任何 PILOT / CONFIRM 数据**之前**固定，**不得由数据反推**；其性质为
  最小有意义效应（SESOI，研究者的价值判断而非数据估计量），完整论证见 16.2。
- **统计显著与实践显著分别报告**：统计显著 = 单侧检验拒绝 \(H_0\)
  （\(q_{0.05}>0\)，7.3）；实践显著 = 点估计 \(\Delta_{\mathrm{BA}}\ge\delta\)。
  两者是独立陈述，均须报告，不能互相替代；样本量公式中的 \(\delta\) 即此正向
  最小有意义增量。

### 10.2 方差未知 → CONFIRM 的具体 pair 数按冻结规则在 PILOT 后计算

**3A.8 只有一个 pair，不能用于估计总体方差。** 因此本阶段**不直接指定** CONFIRM
的 ACL pair 数量。但 R3 已把**计算方法、目标功效、\(\alpha\)、PILOT 最小样本量与
方差精度规则全部冻结**（16.3、16.4），故一旦取得合格 PILOT 方差，CONFIRM 样本量
由冻结公式唯一确定，无需再临时选择；若 PILOT 方差不合格，则按停止条件处理，
不得拍脑袋填数。

所需流程分**三个互不相交的阶段**，顺序不可颠倒（命名空间定义见 5.1）：

1. **开发阶段（`DEV`）**：调试数据管线，在 `DEV` 的分组 CV 上定稿特征聚合算子、
   \(C\) 网格与模型选择；在 `DEV` 结束时按 6.3 用**唯一主随机种子**训练并**冻结
   主模型**（C1 / C2 各一个），记录模型身份与代码 / 配置版本。此阶段的多种子
   重复训练只报告稳定性，不参与主模型选择。**模型冻结必须在 PILOT 之前完成。**
2. **方差先导阶段（`PILOT`）**：使用**已经冻结的主模型**，在全新的、与 `DEV`
   不相交的 `PILOT` pair 上**只为估计 \(\sigma_d^2\) 与流程稳定性**而运行；
   **不得**用 PILOT 结果调整特征 / 模型 / 超参 / 种子，也不用于声称 H1。
   **PILOT 最小有效 pair 数 = 51**（设计依据见 16.3：使 \(s_d^2\) 的相对标准误
   \(\mathrm{RSE}\approx\sqrt{2/(n-1)}\le 0.20\)）；低于 51 不得据其定样本量，
   须补足至 51 或按停止条件报告无法确定；PILOT pair 不得进入 CONFIRM。
3. **每 pair 差值的定义**（使 \(\sigma_d^2\) 可解释）：在 6.3 的**冻结主模型**下，
   令 \(I_{C,s}^{(i)}\in\{0,1\}\) 表示第 \(i\) 个 PILOT pair 在策略 \(C\)、ACL 状态
   \(s\in\{A0,A1\}\) 下的 bundle 是否被正确分类（按各自真值标签）。则

\[
d_i=\frac{I_{C2,A0}^{(i)}+I_{C2,A1}^{(i)}-I_{C1,A0}^{(i)}-I_{C1,A1}^{(i)}}{2},
\qquad
\Delta_{\mathrm{BA}}=\frac{1}{n}\sum_{i=1}^{n} d_i .
\]

   因 A0/A1 平衡，\(\frac{1}{2}(I_{C,A0}+I_{C,A1})\) 即该 pair 在策略 \(C\) 下的
   balanced accuracy 估计；\(\sigma_d^2=\mathrm{Var}(d_i)\) 是**跨 pair** 的配对
   差值方差。模型先冻结、再跑 PILOT，\(d_i\) 才不随训练随机性改变，方差才可解释。
4. **样本量估算**：pair 级配对设计的近似公式

\[
n_{\text{pairs}} \approx \frac{(z_{1-\alpha} + z_{1-\beta})^2\,\sigma_d^2}{\delta^2}
\]

   其中 \(z_{1-\alpha}=z_{0.95}=1.644854\)，\(z_{1-\beta}=z_{0.80}=0.841621\)，
   \((z_{1-\alpha}+z_{1-\beta})^2=6.182557\)；\(\delta=0.10\) 是 10.1 的正向最小
   有意义增量。代入冻结值后系数 \(6.182557/\delta^2 = 618.26\)，即
   \(n_{\text{CONFIRM}} \approx 618.26\,\hat\sigma_d^2\)（\(\hat\sigma_d^2\) 为 PILOT
   方差估计，须先满足 16.3 精度条件）。该公式给出的是**确认性测试集（`CONFIRM`）
   所需的 pair 数量**，**不是整个实验的总 pair 数**；DEV / PILOT / CONFIRM 的
   具体分配规则见 16.3、16.6。同时须满足 bootstrap 区间稳定的最小 pair 数要求
   （16.7）；若两者冲突，取较大者。完整数值推导见 16.4。
5. **确认性阶段（`CONFIRM`）**：用全新、未参与 `DEV` 与 `PILOT` 的 pair 组成锁定
   测试集，在冻结主模型上**一次性**评估，计算 \(\Delta_{\mathrm{BA}}\) 与按 pair
   的 bootstrap 区间。**若 PILOT 之后改动了任何模型 / 特征 / 超参 / 种子，原
   \(\sigma_d^2\) 即失效**，必须用新 PILOT pair 重新估方差，且 CONFIRM pair 仍须
   保持未参与。
6. 若 PILOT 无法提供稳定方差（pair 太少、分布退化），则**明确写出仍无法确定样本量**，
   不得拍脑袋指定数字。

## 11. I. 失败与停止条件

出现以下任一情况立即停止并报告，**不通过放宽条件制造 PASS**：

1. **查询失败 / 目标未进入搜索或 observer**：包括 harness 报错、某条 query 未产出
   trace、目标位未出现在任何 `distance_eval` 等情形；记录具体 pair / 组 / 查询，
   按 9.4 纳入主分析并分层报告，**不得换目标、不得换查询、不得事后剔除该 pair**。
   仅当失败为纯技术性（文件损坏、进程崩溃）且无法产生任何 bundle 时，才按 8.3
   的纯结构性排除规则处理并记录数量与原因。
2. **回调缺失 / 目标未触发 filter callback**：同样记录并纳入，不剔除样本；回调
   缺失本身是观察结果，不是排除条件。
3. observer schema 发生变化（字段增减、类型变化）：停止，先查观察边界是否被破坏。
4. C0/C1/C2 条件不一致（索引、查询、参数、ACL 实例不同）：停止。
5. pair invariant 失败（非目标位变化、A0/A1 不同源）：作废该 pair 并记为结构
   失败；若普遍失败则停止。
6. 私有诊断 / ACL 位 / 真值 / pair ID 进入攻击输入：停止并审计数据管线
   （与 7.5 的 C1 偏高审计判定标准一致）。
7. 样本量不足、未完成方差先导、或模型未在 PILOT 前冻结：不得进入确认性结论。
8. 测试集污染（CONFIRM 参与特征/模型选择、A0/A1 跨集合、DEV/PILOT/CONFIRM
   命名空间重叠或 pair 复用）：停止，结果作废。
9. PILOT 后改动模型/特征/超参/种子却沿用原 \(\sigma_d^2\)：停止，重估方差。
10. 统计结果不支持 H1：如实报告"未能拒绝 \(H_0\)"，不得事后挑选目标、查询、
    pair、种子或模型重跑。

**禁止事后挑选**：目标、查询、ACL pair、特征、模型、随机种子一律不得根据观察
结果重选。

## 12. J. 研究主张边界

- **逻辑 observer proxy ≠ 物理 page/block trace**。3A.7 已明确
  `is_physical_page_trace = false`；本协议的所有 BA/AUC 只在"该逻辑观察模型

- **统计可区分性 ≠ 完整身份恢复**：BA>0.5 只说明存在统计信号，不等于攻击者

   - 单固定索引 / 单目标使结论的条件性很强，跨索引 / 跨目标的外部效度未解决；
   - 目标"pivotal"（K-hit 是否真因目标位翻转而提前停）的发生率未知，可能使
     \(\Delta_{\mathrm{BA}}\) 高度依赖少数查询（需执行阶段分层报告）。

3. **推荐的分类器和特征方案？**

4. **样本量估算是否具备条件？**
   **计算方法已具备，具体数字待 PILOT。** 须先按 `DEV` → `PILOT` 顺序，在冻结主
   模型之后用**至少 51 个**独立 PILOT pair 估计 \(\sigma_d^2\)（16.3），再按 10.2 /
   16.4 的冻结公式直接计算 CONFIRM 集所需 pair 数；3A.8 的单 pair 严禁用于估方差。
   \(\delta=0.10\) 为正向最小有意义增量，统计显著与实践显著分别报告。

5. **是否可以进入先导实验？**
   **是（协议准入 READY，但本轮不启动）**：R2 文档审查已通过，R3 已把 14 的自由
   参数逐项冻结（14、16），DEV / PILOT / CONFIRM 三命名空间隔离与"先冻结模型、
   后估方差"顺序已落实。执行阶段可按冻结协议启动 DEV。本轮（R3 文档冻结）本身
   **不启动任何实验**。

6. **哪些结果将构成支持 H1 的证据？**
   - \(\Delta_{\mathrm{BA}}\) 点估计 > 0，且按 pair 配对 bootstrap 的 90% 区间
     下界 \(q_{0.05} > 0\)（单侧 0.05 拒绝 \(H_0\)）；这是**唯一**的主要统计判据；
     是否达到 \(\Delta_{\mathrm{BA}}\ge\delta\) 作为实践意义**另行报告**（10.1）；
   - \(\mathrm{BA}_{C1}\) 作为普通过滤基线**独立报告**，无论接近随机还是高于随机
     都不改变 H1 判据；C1 偏高时完成标签泄漏审计且**未发现**污染；
   - C0/C1/C2 条件一致、观察边界未被破坏、测试集未污染；
   - 分层报告中，增量不由"目标未访问"或少数异常 pair 单独驱动。

7. **哪些结果将迫使否定或缩小研究主张？**
   - 区间跨 0 或下界 ≤ 0（未能拒绝 \(H_0\)）：缩小为"该目标/该索引/该观察模型下
     未检出 K-hit 的增量可区分性"，不得宣称 H1 成立；**即使 \(\mathrm{BA}_{C1}\)
     很低或很高，也不改变这一判定**；
   - \(\mathrm{BA}_{C1}\) 偏高且 \(\mathrm{BA}_{C2}\) 未进一步提高：如实报告"未检出
     K-hit 增量"，不得把 C1 偏高本身当作实验失败，也不得事后改口径；
   - 标签泄漏审计**证实**内部诊断 / ACL 位 / 真值 / pair ID 混入攻击者输入：
     结果作废并修复管线（这是唯一由"C1 偏高"触发作废的情形）；
   - 增量只在目标可见的少数 pair 中出现：缩小主张到条件性情形；
   - 观察模型无法支持逻辑 proxy 到物理轨迹的映射：缩小为主张仅适用于逻辑观察代理。

### 16.2 \(\delta = 0.10\) 的论证（③ 设计选择 + ① 约束）

\(\delta\) 是**最小有意义效应（SESOI）**：它是研究者的价值判断，不是可由数据估计
的量，因此不存在"从数据推出的唯一正确 \(\delta\)"。本轮冻结 \(\delta=0.10\) BA 点，
依据如下，可逐条复核：

1. **量纲与锚点**：BA 在平衡集上的随机基线 = 0.5。\(\delta=0.10\) 即要求 C2 相对
   C1 至少多正确分类平衡测试 bundle 的 10 个百分点，等价于把可区分性从随机抬高
   五分之一。这是"可观察、可报告"的净增，不是量级不可分辨的微差。
2. **为什么不小于 0.10**：\(\delta\) 过小（如 0.02）会让样本量 \(n\propto 1/\delta^2\)
   爆炸（0.02 时系数约 15456，见 16.4），且低先验 \(p=0.1\) 下如此小的增量在部署
   解释量（9.2、9.5）上接近噪声，不足以支撑"K-hit stop 带来实质额外可区分性"。
3. **为什么不大于 0.10**：\(\delta\) 过大会把最小门槛抬到几乎不可能（\(\delta=0.20\)
   要求 BA_C2 比 BA_C1 高 20 点），等于预设结论；0.10 在"实践有意义"与"可检验"
   之间取中，且经统计显著 / 实践显著分别报告（10.1）后，\(\delta\) 只约束实践意义
   陈述、不替 \(H_0\) 检验做决定，因此选值不会伪装成显著性。
4. **方向约束**：\(\delta>0\) 与 \(H_1:\Delta_{\mathrm{BA}}>0\)（单侧）一致；\(\Delta<0\)
   无论多大都不是支持 H1 的证据。
5. **反数据反推**：\(\delta\) 在看到任何 PILOT / CONFIRM 数据之前固定（16.1 冻结
   日期早于执行阶段），不得因结果调整；任何改动须另开勘误并说明对 H1 的影响。

### 16.3 DEV / PILOT / CONFIRM 分配与 PILOT 最小样本量（①）

- 三命名空间在 pair 生成前由公开划分 seed `H1-RM.3A9-SPLIT-SEED-20261126`
  一次性确定，互不相交、随机流不同、顺序不可颠倒（5.1）；这是②预设常数。
- **PILOT 最小有效 pair = 51**：估计配对差值方差 \(\hat\sigma_d^2=s_d^2\) 时，
  样本方差的相对标准误对近似正态数据为 \(\mathrm{RSE}(s_d^2)\approx\sqrt{2/(n-1)}\)。
  取 \(n=51\Rightarrow\sqrt{2/50}=0.200\)，即方差估计 RSE ≤ 20%；\(n<51\) 时 RSE
  超过 20%（\(n=30\Rightarrow26.3\%\)，\(n=20\Rightarrow32.4\%\)），据此定样本量会
  被方差估计误差主导。故 51 是"方差估计精度足以支撑样本量计算"的最小可复核门槛。
- **方差精度不足规则**：若 PILOT 有效 pair < 51，或 \(d_i\) 分布退化（如绝大多数
  \(d_i=0\) 导致方差近零），则**不得**据其定样本量；须补足 PILOT pair 至 51 并复算，
  或按停止条件 11.7 明确报告"仍无法确定样本量"，不得拍脑袋填数。方差近零时还需
  检查是否 K-hit 根本未触发（pivotal 率，13.2），若是则如实报告机制未生效。
- **DEV / CONFIRM 具体 pair 数**：DEV 数量按分组 CV 折数与每折最小 pair 数确定
  （5 折 GroupKFold，记录于私有 manifest），不在此预设固定值；CONFIRM 由
  16.4 公式在 PILOT 后确定。三阶段总预算 = DEV + PILOT(≥51) + CONFIRM，逐项记录。

### 16.4 CONFIRM 样本量计算与目标功效（①）

- 单侧 \(\alpha=0.05\)，目标功效 \(1-\beta=0.80\)，\(\delta=0.10\)。
- 配对设计均值差的正态近似样本量公式（10.2）：
  \(n \approx (z_{1-\alpha}+z_{1-\beta})^2\sigma_d^2/\delta^2\)。
- **可复算常数**（标准正态分位数，Python `statistics.NormalDist` 复算）：
  \(z_{0.95}=1.644854\)，\(z_{0.80}=0.841621\)，
  \((z_{1-\alpha}+z_{1-\beta})^2=6.182557\)，
  \(\delta^2=0.01\Rightarrow 6.182557/0.01=618.26\)。
  故 \(n_{\text{CONFIRM}}\approx 618.26\,\hat\sigma_d^2\)（\(\hat\sigma_d^2\) 为合格
  PILOT 方差）。示例：\(\hat\sigma_d^2=0.1\Rightarrow n\approx62\)；
  \(\hat\sigma_d^2=0.25\Rightarrow n\approx155\)。
- \(d_i\in\{-1,-0.5,0,0.5,1\}\)（由 10.2 定义，4 个 0/1 指示量代数和除以 2），
  故 \(\mathrm{Var}(d_i)\le 1\)，样本量上界约 618 pair；这是有界性的直接结果，不是
  拍脑袋的上限。
- **与 bootstrap 取大**：CONFIRM 最终 pair 数 = \(\max(618.26\,\hat\sigma_d^2,\,
  30)\)。\(n_{\text{boot-min}}=30\)（③ 设计选择）为百分位 CI 稳定性的保守下限：
  B=10000 时尾部 \(q_{0.05}\) 有约 500 个重采样尾部样本支撑，30 个独立 pair 已能
  给出可读的按 pair 分布；低于 30 时区间对单个 pair 过敏感。该下限只保证区间可
  计算，不替代 0.80 功效要求；两者冲突取大者。
- 该公式是**正态近似**，对有界 \(d_i\) 在中等样本下稳健；它给的是达到 0.80 功效的
  近似 pair 数，最终以 CONFIRM 实测的按 pair bootstrap 区间做单侧检验（7.3），
  样本量公式不替代检验本身。

### 16.8 边界情况处理（②/③，延续 11）

| 情形 | 处理 |
| --- | --- |
| 查询失败 / 目标未进入 observer | 记录并按 9.4 纳入主分析、分层报告；不换目标 / 查询、不剔除（11.1） |
| 回调缺失 / 目标未触发 filter | 记录并纳入，不剔除；缺失是观察结果非排除条件（11.2） |
| 目标不可见 pair | 全部保留主分析，仅作辅助分层，不预断不可区分（9.4） |
| observer schema 变化 | 停止并查观察边界（11.3） |
| C0/C1/C2 条件不一致 / pair 不变量失败 | 停止或作废该 pair 记结构失败（11.4、11.5） |
| 纯技术性失败（文件损坏 / 崩溃） | 按 8.3 结构性排除，报告数量与原因，不按 BA 表现排除 |
| 私有信息混入攻击输入 | 停止并审计，证实污染才作废（11.6、7.5） |
