## 0. 本阶段定位与研究问题

### 0.1 从 3A.8 到 3A.9 的推进逻辑

3A.8 是一个**可行性**结论：在单个固定目标位置上，可以构造严格只差一个授权
位的反事实对 (A0, A1)，并可让两份 ACL 在同一索引、同一查询下实际运行 C0/C1/C2。
它观察到：C0/C1 的 observer trace 在 A0/A1 间逐字节相同；C2 不同。

**该现象尚不是统计证据。** 单个 ACL pair 不能给出方差、功效或可反驳的假设。
本研究的目标是把"观察到一个有意思的现象"推进为"可被独立样本验证、可被反驳
的统计假设"。

### 0.2 核心假设

- **H1（主要假设）**：在相同 HNSW 索引、查询与 ACL 过滤机制下，加入 K-hit stop
  （C2）比普通过滤搜索基线（C1）产生更高的**授权成员状态可区分性**。
- **主要比较量**：

\[
\Delta_{\mathrm{BA}} = \mathrm{BA}_{C2} - \mathrm{BA}_{C1}
\]

- **零假设**：\(H_0: \Delta_{\mathrm{BA}} \le 0\)
- **备择假设**：\(H_1: \Delta_{\mathrm{BA}} > 0\)（**单侧**）

BA = balanced accuracy，衡量攻击分类器区分目标成员授权状态的能力，
**不是**物理泄露量的直接测量。C0 保留为普通 `searchKnn` 对照，**不改变**
C1 与 C2 的主要比较关系。

### 0.3 三层结果必须分开（继承 3A.8）

| 层次 | 可得出的结论 | 本阶段状态 |
| --- | --- | --- |
| 配对完整性 | A0/A1 是否真的只差一个授权位 | 已验证（3A.8） |
| 观测可行性 | 目标是否进入 observer 可见范围 | 已验证（3A.8，单 pair） |
| Trace 敏感性 | 单比特变化是否伴随可观察轨迹变化 | 已观察（3A.8，**非**统计证明） |

本阶段要设计的是把第三层升级为**统计检验**的协议。第一、二层是准入前提，
不是攻击结果。

## 3. A. 统计单位与数据结构

### 3.1 定义

- **独立 ACL instance**：一次独立 CSPRNG 采样得到的 base ACL 位图（N=200），
  它是生成配对的唯一随机源。
- **ACL pair（配对）**：由一个 base ACL 派生的两份位图 \((A_0, A_1)\)，满足
  \(A_0[u]=0\)、\(A_1[u]=1\)、\(\forall i\ne u: A_0[i]=A_1[i]\)。pair 是**唯一
  的独立统计单位**。
- **观察样本（bundle）**：某一 ACL 状态下，同一组固定 6 条查询
  \(Q_1,\dots,Q_6\) 的 observer proxy trace 集合，作为**一个**特征向量。
  每个 pair 产生两个 bundle：A0-bundle（标签 0）与 A1-bundle（标签 1）。
- **pair ID**：仅用于分组（grouping），**绝不作为分类器特征**。

数据结构（概念示意）：

```
pair p                         ← 一个独立单位，一个分组标签
├── A0 bundle (label=0)
│   ├── Q1 observer trace
│   ├── ... 
│   └── Q6 observer trace
└── A1 bundle (label=1)
    ├── Q1 observer trace
    ├── ...
    └── Q6 observer trace
```

### 3.2 为什么六个 query 不能当六个独立样本

三条 query 共享同一 ACL 位图、同一索引、同一组搜索参数、同一目标成员状态。
它们**不是**独立 ACL instance。把它们当独立样本会把每 pair 的有效样本量从
1 虚增到 6（或 12），人为压窄置信区间、抬高显著性——这正是最容易把结果做
虚高的地方。本协议规定：

- bundle 内部 6 条 query 只用于**特征聚合**（见 6.2），不构成独立观测；
- 训练 / 验证 / 测试划分、bootstrap 重采样、功效计算**全部以 pair 为单位**；
- 若做了 query 级敏感性分析（见 6.4），其分组变量仍是 pair ID，**不是** query ID。

### 3.3 pair ID 的使用边界

pair ID 只出现在：分组标签、bootstrap 抽样单元、审计 manifest。
pair ID **不进入**任何特征向量、不进入模型、不进入任何可观察字段关联。

## 4. B. 数据集构造与随机性

### 4.1 每个 pair 的生成顺序（顺序本身是协议的一部分）

1. 目标选择**先于**任何 ACL 生成：用公开 seed 从完整成员集合确定 \(u=103\)。
   目标选择函数只接收公开量，不接收 ACL、位、距离、K-hit 位置、trace 或任何
   搜索结果。
2. 用 CSPRNG（`secrets.randbelow`，逐位）独立采样一个 base ACL（先验 \(p=0.1\)）。
   **不同 pair 的 base ACL 必须相互独立**；不得复用、不得由前一对派生。
3. 由该 base ACL 调用 `derive_target_pair` 同时派生 (A0, A1)，严格只翻目标位。
4. 校验不变量：成员数相等、`diff_indices(A0,A1) == [u]`、A0[u]=0、A1[u]=1、
   其余位逐位相同。任一失败则该 pair 作废并记为结构失败（见 10.2），**不得**
   通过换目标或改规则补救。
5. 用同一冻结 harness 对 A0、A1 分别运行 C0/C1/C2，写入**不同**输出目录。
6. 保存 internal diagnostics 与 observer proxy，但严格分层；只把 observer proxy
   交给后续特征构造。

### 4.2 随机性与可复现

- 目标选择：公开 seed，确定性、可复核。
- ACL 采样：系统 CSPRNG，**不可复现是特性而非缺陷**（保证 pair 间独立）；
  但为审计，须在私有 manifest 中记录每 pair 的派生 blob 摘要（仅用于完整性
  校验，**绝不**进入分类器或提交到仓库）。
- 索引与查询：冻结 seed=2026，所有 pair 共用同一确定性索引与查询集。因此
  pair 间的随机性**仅来自 ACL 采样**——这既保证了独立性，也意味着结论以该
  单一索引/查询为条件（见 11.2）。

### 4.3 私有材料的保存与防泄漏

- 所有私有 ACL blob、internal diagnostics、完整 manifest、trace 只在调用方
  指定的**私有临时目录**生成（执行阶段用 pytest `tmp_path` / 仓库外目录）。
- driver 只打印结构摘要，不打印位图内容、私有路径或授权计数。
- 提交前必须核对：`git status` 无任何 `*.bin` / `*.jsonl` / manifest；测试中已
  有 `test_private_artifacts_not_in_repository` 作为护栏，执行阶段必须保留同类
  检查。不得仅依赖 `.gitignore` 作为唯一防线。

### 4.4 版本、配置与环境记录（私有 manifest，不提交）

每个执行批次须在私有 manifest 记录：3A.4–3A.8 相关代码与 harness 的 commit SHA、
hnswlib 头文件 SHA（pristine 与 RM2 instrumented）、编译器及版本、全部公开 seed
与冻结常量、OS/CPU、运行时间戳。manifest 只用于复核，不进入仓库、不进入模型。

### 4.5 严禁提供给分类器的信息

`ACL bitmap`、任意授权位、目标真值、`internal_diagnostics` 全部字段、
pair ID、公开 seed 派生的目标排名。分类器**只能**接收 observer proxy 中
白名单字段的派生量。

## 5. C. 训练 / 验证 / 测试划分

### 5.1 划分方案（推荐：锁定测试集 + 开发集分组 CV）

- 按 **pair** 随机划分为：开发集（如 80%）与**锁定测试集**（如 20%）。
  划分用固定公开 seed，记录于私有 manifest。
- 测试集一旦锁定，**只评估一次**；不得用于特征选择、模型选择或超参调整。
- 在开发集上用**按 pair 分组**的重复交叉验证（`GroupKFold`，`groups=pair_id`）
  做模型与超参选择。由于 A0-bundle 与 A1-bundle 的 `group` 均为其 pair ID，
  它们**必然落入同一折**，不会跨集合。

### 5.2 为何不用一次性 60/20/20

在 pair 数量可能很小的情形下，单次 holdout 的划分方差过高，验证结论不稳定。
分组 CV 在开发集内更充分地利用样本，同时通过 `groups=pair_id` 严格保持配对
不跨折。锁定测试集仍提供一次性、无偏的最终评估。

若后续样本量足够大且审查组偏好简单设计，可改为一次性 60/20/20（train/val/test），
但**必须**同样按 pair 分组，且该变更须在冻结协议前决定，不得看了结果再改。

### 5.3 绝对禁止

- A0 在训练集、A1 在测试集（同一 pair 拆散）；
- 同一 pair 的 query 分散到不同集合；
- 根据测试集结果修改特征 / 模型 / 目标 / 查询；
- 先观察测试表现再挑选"表现最好"的目标位置或 query 子集。

## 6. D. 分类器与特征设计（只设计，不写代码）

### 6.1 攻击者可观察字段（白名单，来自 observer proxy）

允许进入特征构造的字段：

- `query_id`、`event_index`（R1 稠密观察序号）、`group`、`event_type`；
- 仅 `distance_eval` 事件额外携带：`external_id`、`level`、`dist_bits`。

**明确禁止**（即使它们出现在任何文件或派生量中）：
`extra`、`internal_id`、`auth_hits`、`khit_event_index`、`n_filter_ok`、
`n_filter_check`、`result_all_authorized`，以及任何 internal diagnostics 字段、
ACL 位图、pair ID。

说明：`group`（C0/C1/C2）是**分层维度**，不是特征——本协议为每种策略单独
训练/评估分类器（C1 一个、C2 一个，C0 作对照），不得把 group 混进输入。

### 6.2 特征构造（预先冻结，执行前不得改）

对每条 query 的 observer trace 计算固定统计量（仅用白名单字段）：

- 观察者事件总数；按 `event_type` 的计数（`distance_eval`、`candidate_consider`、
  `candidate_pop`、`stop_check`、`search_stop` 等；内部专用类型本就不在 proxy 中）；
- 目标可见性：`external_id == 101751` 是否出现在任一 `distance_eval`（0/1）、
  出现次数、首次与末次出现的观察序号；
- 若目标出现：其 `dist_bits`（按 float 位模式解释后的数值）与 `level`；若未出现，
  用固定哨兵值（协议冻结，不得按结果调整）；
- `search_stop` / `stop_check` 是否出现、次数、首次出现的观察序号；
- 末事件类型的 one-hot（取值域冻结为 proxy 实际可能出现的类型集合）；
- `distance_eval` 的 `level` 与距离分布摘要（min/max/mean）。

把 6 条 query 的上述量用**固定聚合算子**合并为一个 bundle 向量：
对每个数值特征取 `mean / min / max / sum / std` 中预先指定的子集，并加入
"目标可见的 query 数"（0–6）。聚合算子的选择须在冻结前定稿。

### 6.3 主分类器方案（预先固定）

- **主要分类器**：L2 正则化逻辑回归，输入为标准化后的 bundle 特征向量，
  正则强度 \(C\) 在**开发集**的分组 CV 中选取（候选网格预先冻结）。
  类别天然平衡（A0/A1 各半），判定阈值固定 0.5 用于 BA。
- **辅助分类器**（可选，仅探索性）：小容量梯度提升。其结果只作敏感性参考，
  不参与主要终点，不用于挑选模型。
- **随机性与重复训练**：固定随机种子列表（预先冻结）；每个配置重复训练固定
  次数，报告均值与离散度。禁止"跑多个模型挑最好的测试分数"。
- **防测试污染**：任何超参、特征子集、阈值的选择都只发生在开发集；测试集在
  模型与协议冻结后一次性评估。

### 6.4 允许的敏感性分析（不改变主终点）

- query 级分析：把每条 query 作为一行，分组变量仍为 pair ID（**不是** query ID），
  聚类仍按 pair。它只改变特征分辨率，不改变统计单位。
- 按"目标是否被 observer 可见"分层的报告（见 9.4）。

## 7. E. 统计假设与主要终点

### 7.1 假设与方向

- \(H_0: \Delta_{\mathrm{BA}} \le 0\)；\(H_1: \Delta_{\mathrm{BA}} > 0\)（单侧）。
- \(\mathrm{BA} = (\mathrm{TPR}+\mathrm{TNR})/2\)，在平衡测试 bundle 上、阈值 0.5 计算。

### 7.2 指标层级

| 指标 | 角色 |
| --- | --- |
| \(\Delta_{\mathrm{BA}} = \mathrm{BA}_{C2}-\mathrm{BA}_{C1}\) | **唯一主要终点** |
| \(\mathrm{BA}_{C0}\)、\(\mathrm{BA}_{C1}\)、\(\mathrm{BA}_{C2}\) | 主要终点的组成部分；C0 为对照 |
| ROC-AUC | 辅助（排序能力） |
| TPR / FPR | 辅助（误报漏报分析） |
| 自然先验 accuracy / precision | 辅助（部署解释，见 9） |

### 7.3 显著性与区间

- 显著性水平：**单侧 \(\alpha = 0.05\)**。
- 配对 bootstrap 给出 \(\Delta_{\mathrm{BA}}\) 的分布；报告 90% 双侧区间
  \([q_{0.05}, q_{0.95}]\) 与 95% 双侧区间 \([q_{0.025}, q_{0.975}]\)。
- 拒绝 \(H_0\) 的规则：90% 双侧区间下界 \(q_{0.05} > 0\)（等价单侧 0.05）。
- **不得只报点估计**；任何 \(\Delta_{\mathrm{BA}}\) 都须附带区间与重采样次数。

### 7.4 多重比较

- 主要终点只有一个，无需多重校正。
- 辅助指标（C0 相关比较、AUC、TPR/FPR、自然先验指标）**一律声明为探索性**，
  不用于支持 H1 的主要结论；若审查组要求把某一辅助指标升格为确证性，须在冻结
  前指定并用 Holm 控制族系错误率。

### 7.5 检验适用条件

- pair 间独立（不同 base ACL；见 4.2 的条件性说明）；
- pair 数足以支撑 bootstrap 百分位区间（见 10 样本量）；
- \(\mathrm{BA}_{C1}\) 不得显著高于随机：若 C1 已出现高 BA，属异常信号（见 10.2），
  因为 3A.8 中 C1 的 A0/A1 trace 逐字节相同——高 BA 意味着可能的标签泄漏或
  实验伪影，而非 H1 成立。

## 8. F. 配对 bootstrap

### 8.1 单位与重采样

- **bootstrap 单位 = ACL pair**，有放回抽取，抽满与原测试集相同数量的 pair。
- 每次抽样**保留完整 A0/A1 配对**：抽中 pair p 就同时纳入其 A0-bundle 与
  A1-bundle。
- **C1 与 C2 使用同一批重采样 pair**，确保 \(\Delta_{\mathrm{BA}}\) 的配对结构
  与共同随机性被保留。
- 每次重采样重新计算 \(\mathrm{BA}_{C1}\)、\(\mathrm{BA}_{C2}\) 与
  \(\Delta_{\mathrm{BA}}\)。

### 8.2 次数与区间

- 重采样次数 \(B \ge 10000\)（依据：百分位 CI 尾部 \(q_{0.025}\) 的稳定性；
  低于此值须说明理由）。
- 主报告用百分位区间；BCa 可作为稳健性对照，但不得只挑更显著的一种报告。
- 同时给出 bootstrap 分布中 \(\Delta_{\mathrm{BA}} \le 0\) 的比例作为辅助参考。

### 8.3 缺失 / 异常 pair

- **禁止**依据观察结果选择性删除 pair。
- 结构失败（配对不变量破坏、C++ loader 拒绝、C0/C1/C2 条件不一致）是**停止
  条件**（见 10.2），不是"剔除后继续"的理由。
- 若某 pair 因纯技术原因（如文件损坏）无法参与，须在冻结前定义纯结构性排除
  规则，并报告排除数量与原因；不得按 BA 表现排除。

## 9. G. 自然先验与平衡诊断集

### 9.1 两个不同的世界，必须分开报告

- **平衡 case-control 诊断集**：A0/A1 各半，用于测分类能力。此集上随机基线
  BA = 0.5，绝不能称为"攻击成功率"。
- **自然成员先验 \(p = 0.1\)**：真实部署中目标成员授权的自然先验。

### 9.2 换算（在冻结的 TPR/FPR 上）

\[
\mathrm{acc}_{\text{natural}} = p\cdot\mathrm{TPR} + (1-p)\cdot\mathrm{TNR}
= p\cdot\mathrm{TPR} + (1-p)(1-\mathrm{FPR})
\]

\[
\mathrm{precision}_{\text{natural}}
= \frac{p\cdot\mathrm{TPR}}{p\cdot\mathrm{TPR} + (1-p)\cdot\mathrm{FPR}}
\]

其中 \(p=0.1\) 冻结。低先验下即便 TPR 较高，precision 也可能很低——必须明确
报告，避免把平衡集上的高 BA 误读为部署中的高攻击成功率。

### 9.3 case-control 与自然先验的关系

平衡配对采样改变了类别先验，因此 BA（对先验不敏感）才是主要比较量；自然先验
指标是由 TPR/FPR **推导**的部署解释量，不是独立测量。二者不得混用同一准确率
数字。

### 9.4 目标未访问的 pair 也是结果

遵守 3A.8 边界：若某 pair 中目标未进入 observer 可见范围，其 bundle 不含目标
信号，A0/A1 可能相同——它们**保留在主分析中**（贡献"不可区分"，不抬高 BA），
并按"目标是否可见"分层报告比例。禁止只在"成功观察到目标"的样本上做统计，
也禁止为此更换目标或查询。

## 10. H. 样本量与统计功效

### 10.1 参数（预先固定）

- 显著性水平：单侧 \(\alpha = 0.05\)；
- 目标功效：\(1-\beta = 0.80\)；
- 最小有意义效应 \(\delta\)：须由研究者**在先导实验前**确定（例如 \(\delta=0.10\)
  BA 点），不得由数据反推；
- 主要效应定义：\(\Delta_{\mathrm{BA}}\) 的绝对值（BA 点）。

### 10.2 方差未知 → 当前不能定样本量

**3A.8 只有一个 pair，不能用于估计总体方差。** 因此本阶段**不指定** ACL pair
数量，并明确声明：**当前尚不具备可靠估计样本量的条件**。

所需流程：

1. **先导实验（pilot）**：用小样本（具体数量由研究者定，须记录）估计配对
   差值方差 \(\sigma_d^2\)，并调试全流程。先导数据**只用于方差与流程**，
   **不得**进入确认性测试集，也不用于声称 H1。
2. **隔离**：先导与确认性实验使用**不相交的 pair ID**、不同随机流，并分别
   标注代码版本 / 配置版本。先导后立即冻结主分析协议（特征、分类器、终点、
   区间方法），确认性阶段不得再改。
3. **样本量估算**：pair 级配对设计的近似公式

\[
n_{\text{pairs}} \approx \frac{(z_{1-\alpha} + z_{1-\beta})^2\,\sigma_d^2}{\delta^2}
\]

其中 \(\sigma_d^2\) 是单个 pair 对 \(\Delta_{\mathrm{BA}}\) 的配对差值方差，由先导
给出；\(z_{1-0.05}=1.645\)，\(z_{0.80}=0.842\)。同时须满足 bootstrap 区间稳定
的最小 pair 数要求；若两者冲突，取较大者。
4. 若先导无法提供稳定方差（pair 太少、分布退化），则**明确写出仍无法确定样本量**，
   不得拍脑袋指定数字。

## 11. I. 失败与停止条件

出现以下任一情况立即停止并报告，**不通过放宽条件制造 PASS**：

1. 目标未进入搜索或 observer：记录具体 pair / 组 / 查询，按 9.4 纳入分析，
   不得换目标。
2. 目标未触发 filter callback：同样记录并纳入，不剔除样本。
3. observer schema 发生变化（字段增减、类型变化）：停止，先查观察边界是否被破坏。
4. C0/C1/C2 条件不一致（索引、查询、参数、ACL 实例不同）：停止。
5. pair invariant 失败（非目标位变化、A0/A1 不同源）：作废该 pair 并记为结构
   失败；若普遍失败则停止。
6. 私有诊断进入攻击输入：停止并审计数据管线。
7. 样本量不足或未完成先导方差估计：不得进入确认性结论。
8. 测试集污染（测试集参与特征/模型选择、A0/A1 跨集合）：停止，结果作废。
9. 统计结果不支持 H1：如实报告"未能拒绝 \(H_0\)"，不得事后挑选目标、查询、
   pair 或模型重跑。

**禁止事后挑选**：目标、查询、ACL pair、特征、模型一律不得根据观察结果重选。

## 12. J. 研究主张边界

- **逻辑 observer proxy ≠ 物理 page/block trace**。3A.7 已明确
  `is_physical_page_trace = false`；本协议的所有 BA/AUC 只在"该逻辑观察模型
  成立"的条件下有意义，不能宣称对真实 OS/TEE 页观察者的结论。
- **单目标结果不能推广**：\(u=103\) 固定，结论只针对该预注册位置，不推广到
  所有 HNSW 节点。
- **统计可区分性 ≠ 完整身份恢复**：BA>0.5 只说明存在统计信号，不等于攻击者
  能恢复成员身份或任意 ACL 位。
- **核心是 C2 相对 C1 的增量**，不是"C2 能否分类"的绝对表现。
- **相关工作是已有方向**：FiT（页访问模式可泄露）、Onyx / O2N2（oblivious ANN
  隐藏访问模式）等已确立访问模式泄露与防护研究。本项目**不宣称首次发现** HNSW
  访问模式泄露；本研究的定位是检验 K-hit stop 这一特定机制是否**额外**增加
  目标授权状态的可区分性。

## 13. 协议结论（七项）

1. **当前统计设计是否足够严谨？**
   结构上足够严谨，可进入研究设计审查：配对关系、以 pair 为唯一统计单位、
   观察边界白名单、锁定测试集、配对 bootstrap、自然先验分离、停止条件均已明确。
   但它在**冻结前**仍有一批必须由研究者填写的自由参数（见 14），在填写并冻结
   之前不构成可执行协议；且本文件目前是 DRAFT，非预注册。

2. **仍未解决的统计问题？**
   - 配对差值方差 \(\sigma_d^2\) 未知 → 样本量未定（10.2）；
   - 特征聚合算子与超参网格的具体取值尚未填写（6.2、6.3）；
   - 单固定索引 / 单目标使结论的条件性很强，跨索引 / 跨目标的外部效度未解决；
   - 目标"pivotal"（K-hit 是否真因目标位翻转而提前停）的发生率未知，可能使
     \(\Delta_{\mathrm{BA}}\) 高度依赖少数查询（需执行阶段分层报告）。

3. **推荐的分类器和特征方案？**
   主分类器 = L2 逻辑回归（开发集分组 CV 选 \(C\)，阈值 0.5）；特征 = 6.2 的
   observer 白名单派生量经冻结聚合算子合成 bundle 向量；辅助梯度提升仅供探索。
   任何配置只在开发集选择，测试集一次性评估。

4. **样本量估算是否具备条件？**
   **不具备。** 需先做与确认性实验隔离的先导实验估计 \(\sigma_d^2\)，再按 10.2
   公式计算；3A.8 的单 pair 严禁用于估方差。

5. **是否可以进入先导实验？**
   **有条件可以**：须先通过研究设计审查，并在冻结文件中填齐 14 的自由参数、
   完成先导/确认隔离设计。本阶段本身不启动任何实验。

6. **哪些结果将构成支持 H1 的证据？**
   - \(\Delta_{\mathrm{BA}}\) 点估计 > 0，且按 pair 配对 bootstrap 的 90% 区间
     下界 \(q_{0.05} > 0\)（单侧 0.05 拒绝 \(H_0\)）；
   - \(\mathrm{BA}_{C1}\) 接近随机（无标签泄漏迹象）；
   - C0/C1/C2 条件一致、观察边界未被破坏、测试集未污染；
   - 分层报告中，增量不由"目标未访问"或少数异常 pair 单独驱动。

7. **哪些结果将迫使否定或缩小研究主张？**
   - 区间跨 0 或下界 ≤ 0（未能拒绝 \(H_0\)）：缩小为"该目标/该索引/该观察模型下
     未检出 K-hit 的增量可区分性"，不得宣称 H1 成立；
   - \(\mathrm{BA}_{C1}\) 异常高：高度怀疑标签泄漏或伪影，结果作废并审计管线；
   - 增量只在目标可见的少数 pair 中出现：缩小主张到条件性情形；
   - 观察模型无法支持逻辑 proxy 到物理轨迹的映射：缩小为主张仅适用于逻辑观察代理。
