# BASELINE_MATRIX.md — EXP-02-R0 攻击基线规格（仅规格，不实现）

本轮**不实现**任何攻击算法。下表定义 EXP-02-R1 若要执行时必须遵守的输入、划分、辅助知识与公平比较约束。所有字段标记 `[S]` = 服务端可见（基础威胁模型），`[R]` = 仅研究者/Agent 可见，**不得**进入攻击者特征。

---

## 1. B0–B4 输入与算法规格

| 编号 | 方法 | 输入字段 | 算法规格 | 目的 |
|---|---|---|---|---|
| **B0** | Majority / Random Guess | 标签分布（辅助知识，训练标签统计） | 多数类常量预测；随机基线用固定种子按训练集类别先验抽样 | 下界基线；检测数据集类别不平衡造成的虚高 |
| **B1** | Access Frequency / Simple Statistics | 每个文档 ID 的检索频次 `[S]`、每次调用返回数量 `[S]`、调用次数 `[S]` | 以频次向量/统计量直接训练线性分类器（与 B2–B4 同模型类）；不做图构造 | 检验「简单访问频率」是否已解释信号 |
| **B2** | SAGE-style Co-retrieval Graph | 每次调用的返回 ID 集合 `[S]`；**不使用** rank、顺序、任务分组 | 按 SAGE §V：关联矩阵 X，Jaccard 权重 W_jℓ=O_jℓ/(|Q_j|+|Q_ℓ|−O_jℓ)，对称归一化 S=D^−1/2WD^−1/2，谱嵌入 + KMeans(C)，SAGE-Dist 用类别比例+最优传输 / SAGE-Known 用已知标签+标签传播与锚点投票 | 复现扁平跨查询共现分析，作为核心对照 |
| **B3** | Task-grouped Co-retrieval | B2 字段 + 任务/会话分组标识 `[S]`（**须先确认架构确实暴露**） | 在同一任务内构造共检索图，跨任务不连边；任务级聚合为样本表示；**不含调用顺序** | 隔离「任务分组」本身的贡献 |
| **B4** | Ordered Agentic Trace | B3 字段 + 每次调用顺序/轮次 `[S]`（**须先确认**） | 在 B3 基础上加入序列特征（例如按调用顺序的 ID 集合序列、相邻调用重叠、步间转移）；模型容量与 B3 对齐 | 检验顺序信息是否带来超出共现的额外推断能力 |

明确排除的字段：`llm_query` `[R]`、`thought` `[R]`、`answer` `[R]`、`qid` 默认 `[R]`、语义化文档 ID 中的空间/团队前缀（必须替换为 opaque ID，见 §5）、文档内容 `[R]`。

**核心比较**：B4 相对 B2（以及中间对照 B3）是否在角色、有效权限范围、策略状态、撤权检测上给出**稳定、可解释**的增益。概念差异不算增益；更多字段、更多参数、更复杂模型带来的增益不算独立价值。

## 2. 数据划分与主体隔离

### 2.1 主体不泄漏（硬性）

- 对角色 / 权限范围 / 策略状态任务：**按用户（canonical user id）划分**，同一用户的所有轨迹只能出现在 train 或 test 之一。
- 对撤权检测：训练与测试同样按用户隔离；测试集只取含事件的用户的事件前后窗口，训练集取无事件用户。这样避免同一用户的相邻轨迹跨 split 泄漏。
- 同一文档 ID 可跨用户出现（这是共现信号来源），但**同一任务的相邻轨迹不得跨 split**；若按时间切分，必须在同一用户内部设置间隔窗口并报告泄漏检查。
- 当前数据限制：ACL Benchmark 的 golden QA 只有 `u1`–`u6` 6 个 asking_user，无法满足用户隔离。若进入 R1，必须使用 `identities.json` 中的 180 NPC 扩展主体池并在生成轨迹时记录 user_id；**不得用 6 人做用户隔离划分并宣称有效**。

### 2.2 划分比例与重复

- 建议 60/20/20（train/val/test），按用户分组打乱；至少 5 个随机种子，报告均值与标准差。
- 所有 B0–B4 使用**完全相同的划分**；任何重新划分必须在四个基线上同步执行并全部报告，不得只报告有利划分。
- 报告每个 split 的用户数、轨迹数、类别分布与事件数；类别缺失时标记 NOT_EVALUABLE，不插值。

## 3. 标签辅助条件

| 条件 | 内容 | 适用基线 |
|---|---|---|
| A0 | 无辅助标签，只用类别先验（B0 用） | B0 |
| A1 | SAGE-Dist 风格：已知类别数 C + 估计类别比例 π̂（来自独立样本，不含目标标签） | B1–B4 统一可用 |
| A2 | SAGE-Known 风格：1% 已知 ID-标签对，且仅当 ID 出现在观测集合时作锚点 | B1–B4 统一可用 |
| A3 | 完整监督标签（仅用于评估与训练分类器时的显式监督设定） | 若使用，必须在全部基线同步使用并标记 |

**公平性**：B2、B3、B4 必须在**相同辅助知识条件**下比较；若 B4 用 A2 而 B2 用 A1，增益不可归因于轨迹结构。SAGE 原论文的两种变体已在 DATA_AUDIT 记录，复现时按原设定，但与 B3/B4 比较时须对齐。

---

## 4. 公平比较约束

1. **信息量对等**：B2 不加 rank/顺序/分组；B3 只加分组、不加顺序；B4 才加顺序。禁止把 `llm_query`、`thought`、`answer` 或语义化 ID 前缀偷偷加入 B4。
2. **模型容量对等**：B1–B4 使用同一模型族与同一超参数搜索空间（例如逻辑回归的 C 网格、GNN 的层数/隐藏维度上限）；若 B4 因序列结构必须用不同模型，则同时给 B2/B3 相同参数预算，并报告参数量。
3. **辅助知识对等**：见 §3。
4. **随机性对等**：同一批种子、同一划分、同一初始化策略。
5. **增益判定**：B4−B2 的差值用配对 Bootstrap 置信区间（建议 2,000 次重采样，按用户为单位重采样），并在 ≥5 种子上报告。只有置信区间下界 > 0 且在主要指标上一致，才称为稳定增益；单点提升或单一数据集有效不构成结论（对应 NO-GO 条件 2 与 6）。
6. **不把任务类别当权限**：Task-category Accuracy 只作次要指标，不参与「授权推断是否成立」的判定。

---

## 5. 合成数据伪相关的控制（强制）

ACL Benchmark 的文档 ID 形如 `confluence:DATA:CONF-DATA-0001`，space key 确定性映射到团队（见 `acl_audit.json`）。因此：

- 生成轨迹时**必须**把所有文档 ID 替换为无语义的不透明随机 ID（例如 `d-8f3a…`），并保存映射表于**研究者侧**，绝不作为服务端输入。
- 全部 B0–B4 在同一 opaque ID 空间上运行。
- 另设一个诊断条件（不参与主结论）：保留语义化 ID，量化「命名空间解码」能贡献多少准确率。若 opaque 条件下性能大幅下降，则原始高准确率为合成伪相关，不得写成授权推断能力。
- 若某基线在 opaque ID 下仍高精度，需进一步检查是否只利用了频次/集合大小的生成规律（B1 对照）。

## 6. 评估指标

主要指标（按任务）：

| 指标 | 任务 | 定义 / 备注 |
|---|---|---|
| Role Macro-F1 | Role Inference | 按角色类别宏平均；类别不平衡时优先于此而非 Accuracy |
| Permission Scope Macro-F1 或合适多标签指标 | Effective Permission Scope | 多标签设定用 macro-F1 / example-based F1，必须说明阈值选择 |
| Policy-state Accuracy | Policy-State Inference | 转队前/后、临时授权开关等离散状态 |
| Revocation Detection AUROC | Revocation Detection | 二分类；报告正负样本数与时间窗口定义 |

次要指标：Task-category Accuracy、Recall@K（用于与 SAGE 的查询类别能力对照）。

**不可评估标记**：若数据缺时间戳、缺用户 ID、缺 ACL 真值、或某类别样本数不足，指标写 `NOT_EVALUABLE`，不填 0、不伪造结果。本轮 ASQ 单独使用时，四项主要指标全部 NOT_EVALUABLE；ACL Benchmark 单独使用时，四类推断的输入轨迹 NOT_AVAILABLE。

正式实验阶段要求多随机种子 + 配对 Bootstrap CI；本轮只制定设计，不产出数值。

## 7. 可执行性裁定（本轮）

| 条件 | 当前状态 |
|---|---|
| B0/B1 输入可从现有数据取得 | 部分：ASQ 有频次/数量；ACL 有真值但无轨迹 |
| B2 输入可从现有数据取得 | 理论上可（ASQ 返回 ID 集合），但没有角色/权限标签可评估 |
| B3/B4 输入合法性与可执行性 | **未定**：任务分组/调用顺序是否服务端可见尚未在目标架构中确认；ACL 语料上尚无 Agentic 轨迹 |
| B2 vs B4 对照在本轮能否执行 | **否**：缺少同时含轨迹与权限真值的数据；这是 `DECISION.md` 的唯一阻塞项 |

因此本文件是规格而非结果；任何把它写成「已验证 B4 增益」的表述都是越界。
