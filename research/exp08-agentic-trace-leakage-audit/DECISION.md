# DECISION.md — EXP-02-R0 最终决策

## 1. 最终结论

**HOLD**（不是 GO，也不是 NO-GO）。

核心研究问题——「被动外包检索服务能否从多步 Agentic RAG 轨迹推断授权范围或权限状态变化」——**目前既未被证实，也未被证伪**。现有数据各自只满足一半条件：ASQ 有多步轨迹但无任何用户/ACL 真值；Permission-Aware Enterprise RAG Benchmark 有可信的时点 ACL 与角色变更真值但没有 Agentic 检索轨迹。两者不能合法拼接。存在一个明确、有限、可判死的补充工作可以解除阻塞，因此按任务包标准判 HOLD，而不是无限追加审计，也不是为了保选题而改指标/换名字。

---

## 2. 关键证据

### 2.1 支持继续的证据（问题有真实研究空间）

1. **SAGE 未覆盖授权推断**：原文 §III-C 的攻击目标是记录语义标签 λ 与查询语义类别 ℓ（Eq.5），没有主体、策略、ACL 或状态变化概念；§VIII 明确系统若隐藏检索访问则不在威胁模型内。作者声称的性能是语义类别准确率，不是权限推断。
2. **服务端可见信号确实存在**：SAGE §III-B 逐字给出 ℒ_AP=(I₁,…,I_M)；「只需要识别跨查询重复的 ID，opaque/encrypted ID 若可链接不能阻止」。多步轨迹天然产生多组返回 ID 集合。
3. **可信 ACL 真值确实存在**：ACL Benchmark 实测 210 容器均有 `initial_acl`；49 个带时间戳事件为全量替换，脚本核验最终 ACL 与最后事件 **45/45 一致**；`groups.json` 19 条带时间戳成员变更；`u4` 在 `2026-07-01` 从 payments 转到 security；616 条 Golden QA 中有 52 条 `acl_time_travel`、148 条 `post_revocation_ask`。
4. **轨迹结构确实可提取**：ASQ 抽查集合 976 条轨迹，每条 1–25 次调用（中位 3），973/976 的 iteration 从 0 连续，7,101 个唯一 docid 中 97 个跨轨迹复现，足以构造共现图。
5. **相关工作没有完全覆盖该具体问法**：AFR 解决内容级非干涉；PP-RFANNS 显式刻画跨查询重叠泄露但不做授权/角色推断且静态数据库；ObliSC 用 TEE+ORAM 研究访问模式隐藏；DP-MultiRAG/Private-RAG 研究输出侧累积泄露。没有一个直接回答「B4 相对 B2 是否多知道授权范围」。

### 2.2 阻止 GO 的证据（硬阻塞）

1. **没有任何单一数据集同时具备轨迹与权限真值**。ASQ 无 `user_id`、无角色、无 ACL、无墙钟时间；ACL Benchmark 无检索轨迹。任务包禁止手动拼接或制造关联标签。
2. **合成伪相关无法在当前数据内排除**。ACL Benchmark 文档 ID 前缀（如 `CONF-DATA`）与 team 确定性映射（12 个 space→team 映射见 `acl_audit.json`）。在不做 opaque ID 控制前，任何角色推断都可能只是命名空间解码，命中 NO-GO 条件 4 的风险。
3. **B4 的核心输入尚不合法**。ASQ 的 `qid`（任务边界）是评测标识，不是协议字段；`iteration` 是否对应服务端可见的独立请求也未确认。若任务分组/调用顺序不暴露给服务端，B3/B4 相对 B2 的差异不成立，命中 NO-GO 条件 3 的风险。
4. **密码学落点不成立**。ObliSC 可在 TEE+ORAM 假设下做到完全遗忘，PIR/ORAM 类方案本就隐藏访问模式；在尚未量化泄漏、未证明传统方案有明确成本/功能局限之前，引入新 ZK/PIR/ORAM 贡献属于「先决定机制再找问题」，任务包明确禁止。

### 2.3 三问的直接回答

| 验收问题 | 回答 |
|---|---|
| 是否存在真正的授权推断信号？ | **未知**。可信真值存在，但唯一可用语料的 ID 与团队强耦合；未做 opaque ID 对照前不能把任何准确率称为授权推断 |
| B4 是否真的比 SAGE 式 B2 多知道一些东西？ | **未知且本轮不可测**。缺配对数据；且 B4 所需字段的服务端可见性未确认 |
| 是否有合理密码学落点？ | **现在没有**。泄漏未量化，传统隐藏访问模式方案存在且假设已知；不启动密码学设计 |

## 3. 已有工作覆盖范围

| 工作 | 已覆盖 | 未覆盖 |
|---|---|---|
| SAGE | 扁平跨查询共现 → 语义标签/查询类别；固定 pseudonymization 无效；理想 rotation 条件 | 授权范围、角色、ACL 状态变化、撤权检测；多步顺序/任务分组 |
| AFR | 授权先于检索的内容级非干涉；retrieve-then-filter 结构暴露 | 服务端元数据推断；权限状态变化 |
| PP-RFANNS | 过滤 ANN 的访问模式与跨查询重叠泄露定义 | 主体/策略/状态推断；动态更新不在范围 |
| ObliSC | 单服务器完全遗忘访问模式（TEE+ORAM，公开数据库） | 授权范围推断；重系统假设，不是现成方案 |
| DP-MultiRAG / Private-RAG | 多轮输出侧累积泄露与 DP 预算 | 服务端检索元数据与授权状态 |

结论：研究问题未被完全覆盖，但核心信号形式（跨查询共现/重叠）已被 SAGE 与 PP-RFANNS 明确利用。因此后续若要做，贡献必须落在「授权状态维度 + 多步结构的可证明增量」上，而不是换场景。

## 4. 最关键的未解决问题（唯一阻塞项）

**缺少「同一批主体上，同时具备 Agentic 多步检索轨迹与可信 ACL/角色状态真值」的数据。**

不是缺更多论文、不是缺更多指标、也不是缺密码学方案。ASQ 与 ACL Benchmark 都不能单独回答主要目标；它们之间的映射只能靠**在 ACL Benchmark 语料上重新生成轨迹**建立，而不能靠字段拼接。此阻塞项可由一个明确、有限的补充工作解除（见 §6）。

## 6. HOLD：唯一必要下一步工作

**在 ACL Benchmark 上用开源 Agent 独立生成带不透明文档 ID 的 Agentic 检索轨迹，然后执行 B2/B4 配对对照。**

具体边界（不得扩范围）：

1. 使用 ASQ 仓库公开的 `build_agent()` / `DataFrameExtractor` / PyTerrier retriever 流程，以 ACL Benchmark 的文档与 Golden QA / ACL 探针为 queryset；记录 `user_id`（用 186 人主体池，不止 `u1`–`u6`）、`asked_at`、session/task id、每次调用的 opaque docid 集合与 rank。
2. 生成前把所有文档 ID 替换为无语义 opaque ID；映射表只留研究者侧，不进入任何基线输入。
3. 先确认并书面记录三项架构事实：任务 id 是否随请求发送、每次检索是否为独立服务请求、用户标识是否对服务端可见。若任务分组/顺序不可见，B3/B4 只能作为上界诊断，不得作为服务端攻击结论。
4. 在同一数据、同一划分、同一辅助知识条件下运行 B0–B4；按 `BASELINE_MATRIX.md` 的用户隔离、多种子、配对 Bootstrap CI 与 opaque ID 控制执行。
5. 产出结果后回写本文件，改为 GO 或 NO-GO。

**判死标准（预先冻结，防止换指标保选题）**：

- 若 opaque ID 条件下 B4−B2 的主要指标配对 Bootstrap CI 下界 ≤ 0（角色、权限范围、策略状态、撤权四项中任两项如此）→ **NO-GO，停止本候选方向**。
- 若性能主要来自语义化 ID 命名空间解码（opaque 后大幅下降）→ **NO-GO，停止**。
- 若增益依赖 `llm_query`、`thought`、`answer`、未确认的 session 字段或明文查询 → **NO-GO，停止**。
- 若只有一个合成配置有效、换用户池或换事件类型即消失 → **NO-GO，停止**。
- 若上述均不成立且四项主要指标中至少两项稳定、可解释，才转 GO 进入 EXP-02-R1；GO 仍不代表论文选题确定。

## 7. NO-GO 依据（当前不适用，预先记录以防后续拖延）

本轮**不判 NO-GO**，因为没有证据触发任务包列出的六条 NO-GO：SAGE 式共现是否已解释全部有效信号尚未测；B4 相对 B2 增益尚未测；权限推断目前不依赖攻击者不可见字段（而是根本无配对数据）；人工强相关是风险且已给出控制方案而非已确认不可排除；可信权限历史**存在**；目前还不是「只有一个合成配置有效」。

若 §6 的补充工作触发任一判死标准，则按上条直接 NO-GO，不再更换名称、威胁模型、指标或数据集维持选题。
