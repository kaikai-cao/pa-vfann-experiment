# MINIMAL_EXPERIMENT_DESIGN.md — 最小可执行配对实验设计（R0.2.1a 修订版）

任务：EXP-02-R0.1 Phase 5 初稿 → EXP-02-R0.2 Phase 4 修订 → EXP-02-R0.2.1 Phase 3–4 统计任务拆分与独立性审计 → EXP-02-R0.2.1a Phase 1–4 统计口径精确修订。性质：**实验规格，本轮不执行**。

**修订缘由**：初稿把架构 A 定为"阴性对照"、架构 C 定为"唯一主场景"，这是逻辑跳步。R0.2 修正后，**首要检验对象是架构 A 的间接泄漏因果链**（ACL → 上下文 → 后续自适应检索 → 服务端可见轨迹变化）。R0.2.1 修正两处统计错误：(i) 把"跨主体角色推断"与"同主体权限状态变化检测"拆成两个 estimand，使用不同划分；(ii) 用原始文件实测独立统计单位，纠正"148 probes + 32 events = 样本量"的错误相加。**R0.2.1a 按独立验收意见再修三处口径**：(a) 19 个 `(user,doc,canary)` 目标键不是 19 个独立统计簇，独立簇记 `UNKNOWN`；(b) 49 事件的精确独立簇数无法从原始字段确认，记 `UNKNOWN`，只报告 4 组 reason 文本推断的继承链；(c) 区分 3 个 `move_date` 主体与 186 个具备静态 `team_id` 标签的主体，并纠正"组历史为空"的事实错误（14 组共 19 条历史，三个变化主体均有主体级记录）。本轮只改统计口径，不重审 ASQ 源码、不寻找后端、不生成轨迹。

设计前提：
- 数据：ACL Benchmark 提供主体、ACL、时点真值；ASQ 生成流程可复用其多步记录机制但需三项改造（自定义索引/retriever、ACL 拦截、主体身份字段）——见 `AGENT_GENERATION_AUDIT.md`。
- 观测模型：**必须先确定真实、可复核的服务端观测模型**（见 `OBSERVABILITY_AUDIT.md` §4 字段契约）。该模型可为架构 A（首选待检验）或某个具体架构 C；**不得预先指定 C**。所有 B0–B4 只使用该模型下确认可见的字段。
- 关联前置条件：逐主体/逐 session 的实验只有在服务端可可靠关联主体伪标识与 session 时才可评估；否则按 §6 规则标记不可评估。

## 1. 要分离的四类因素

| 因子 | 记号 | 操作化定义 |
|---|---|---|
| F1 任务语义 | T | 任务查询主题 / QA 类别（`multi_hop`、`temporal`、`acl_differentiated` 等） |
| F2 文档访问集合及跨调用共现 | D | 服务端可见的返回 docid 集合、跨调用共现、返回数量、轮次 |
| F3 ACL 状态变化 | P | 主体在时点的有效权限 / 角色 / 撤权前后状态 |
| F4 模型随机性 | R | 生成模型的采样随机性（`search_r1.py:165-166` `do_sample=True, temperature=0.7`） |

**目标**：判定 F3 是否通过 Agent 自适应检索在服务端可见轨迹（F2）中产生**可归因的差异**，且该差异超过 F1、F4 与 ID 命名空间伪相关。

## 2. 数据准备（本轮不执行，仅规格）

1. **语料与 ID**：ACL Benchmark `data/documents_manifest.jsonl` 12,214 文档；建立全局一致的随机 opaque 映射 `doc_id → OPQ-<rand>`，所有 B0–B4 共用。禁止把 `confluence:<SPACE>:...` 语义化 ID 喂给攻击者特征（对照 D 的上界测量除外）。
2. **轨迹生成**：用 ASQ 流程（`build_agent` + 自定义 retriever + ACL 拦截 + 主体字段扩展）生成多步轨迹。生成时**固定初始查询、固定模型、固定语料、控制/记录随机种子**，以便把差异归因于 ACL（见对照 A）。
3. **服务端可见字段**：只记录经 `OBSERVABILITY_AUDIT.md` §4 契约确认可见的字段（opaque docid 序列、返回数量、轮次、时间戳、主体伪标识、session 标识——后两者若不可见则按 §6 处理）。
4. **标签（仅研究者侧）**：角色 = `team_id`；有效权限范围 = 时点可访问容器/文档集合（`initial_acl` + 事件重建）；权限状态 = pre/post 撤权、pre/post role-change。标签与真实身份只用于构造真值与划分，**不进入攻击者特征**。

## 3. 对照设计（A/B/C/D，R0.2 重定义）

### 对照 A：同一任务、同一初始查询、不同 ACL 状态（核心因果检验）
- 固定任务内容、初始查询、模型、语料与随机种子；**仅改变主体 ACL 状态**（如 u4 转队前/后，或某容器撤权前/后）。
- **零点检验**：首轮返回集合在两个 ACL 状态下应相同（架构 A 服务端不感知 ACL）。若首轮就不同，说明存在未控制变量或未预料的直接信号，实验无效，须排查。
- **后续检验**：比较后续调用序列（opaque docid 序列、返回数量、轮次、时间）是否随 ACL 变化产生差异。
- **判据**：若后续轨迹在 ACL 变化前后完全一致，则架构 A 无服务端可见的权限状态信号 → 该项不可推断（此时才构成该架构下的阴性证据）。若有差异，进入对照 B/C 排除任务语义与随机性。

### 对照 B：不同主体、同一任务语义、相同有效权限范围
- 选不同主体，但任务语义相同、且**有效权限范围经重建后相同**。
- **目的**：若轨迹仍因主体身份而可分，说明信号来自主体伪标识或个体行为差异，而非权限范围 → 排除"身份捷径"。
- 与对照 A 互补：A 固定主体变权限，B 固定权限变主体。

### 对照 C：同一主体、相同 ACL 状态、不同任务语义
- 固定主体与 ACL，改变任务内容。
- **目的**：测量任务语义 F1 对轨迹的影响幅度，作为对照 A 观测到的差异的"语义基线"。若对照 A 的差异幅度 ≤ 对照 C 的语义基线，则差异可由任务语义解释，不构成授权推断证据。

### 对照 D：语义化 ID vs opaque ID
- 正式结果**只用 opaque ID**；语义化 ID（`confluence:<SPACE>:...`）**仅作伪相关上界**运行一次，量化"从 ID 字符串解码 team 标签"的虚高准确率。
- 若 opaque 条件下 B4−B2 增益消失、仅语义化 ID 下存在 → 增益来自命名空间解码，命中 NO-GO。

## 4. 基线（B0–B4）与公平比较

沿用 `BASELINE_MATRIX.md`，补充本实验约束：
- **输入字段统一**：所有方法只用该观测模型下确认可见的服务端字段（`returned_opaque_docids` 集合/序列、`result_count`、`call_order`、可见时间戳、主体伪标识、session 标识）。`query/thought/answer/真实身份/角色标签` **不得**进入攻击者特征。
- **信息量与容量匹配**：B2/B3/B4 用同等规模模型；B4 仅多"组内顺序"，不得额外给更多参数或训练轮次。B4−B2 差值是核心量。
- **随机性控制**：生成时记录/固定随机种子；评估时多 seed，把 F4 作为对照基线。
- **标签辅助**：若用 SAGE-Known 式锚点，B2 与 B4 必须用相同比例与相同锚点集合。

## 5. 主要检验问题与指标

### 5.1 任务包要求的主检验
1. **首轮轨迹是否一致**（对照 A 零点）——两 ACL 状态下首轮返回集合相同则为一致的零点。
2. **后续轨迹是否因 ACL 变化产生差异**（对照 A 后续检验）——量化差异幅度。
3. **差异是否超过任务语义（对照 C）、模型随机性（F4）与 ID 伪相关（对照 D）**——只有超过三者才可能归因于 ACL。
4. **B4 相对 B2 是否有稳定增益**——配对差值。

### 5.2 指标（按 estimand 归属，R0.2.1 修订）
- **任务 I（跨主体，主体不相交划分）**：Role Macro-F1；Effective Permission Scope 多标签宏观 F1 / 子集准确率。报告主体数并核对 §7.5 静态标签覆盖（186/186 有 team_id）——当前 `NOT_EVALUABLE`（无 Agentic 轨迹）。
- **任务 II（同主体纵向，按事件簇划分）**：Policy-state Accuracy；Revocation Detection AUROC。Bootstrap 以独立事件簇为单位，不得按单条 probe（见 §6.2）。
- **核心比较量**：`Δ = B4 − B2`（各指标配对差值），报告均值与配对 Bootstrap 95% CI 下界；须标明是任务 I 还是任务 II 的 Δ。
- **次要**：Task-category Accuracy、Recall@K。
- **不可评估**：主体/session 无法服务端关联、或查询明文可见（A2）/无外包服务端（A1）时，对应逐主体/逐 session 指标标 N/A；样本不足的主体不补造，独立簇不足按 §6.2 上报统计不足。

## 6. 两类统计任务（estimand 分开，R0.2.1 核心修订）

原规格把两种不同 estimand 混在一起，并同时声称"同一主体严格不跨 train/test"与"用同一主体事件前训练、事件后测试"——二者互斥，必须拆开。

### 6.1 任务 I：跨主体角色与权限范围推断

**Estimand**：对服务端**此前未见过的主体**，推断其角色类别或有效权限范围（多标签）。泛化目标是"主体总体"。

| 要求 | 规格 |
|---|---|
| 划分单位 | **以主体为单位** train/test 不相交；同一主体的所有轨迹、时间快照、session 必须留在同一 split |
| 主体伪标识作用 | 仅用于轨迹归组、划分与跨调用关联；**不得**把唯一伪标识 token 本身当作角色预测特征（否则模型只需记忆 token→标签） |
| 报告 | 各 split 的主体数、轨迹数、角色类别数、权限标签分布 |
| 不足处理 | 类别缺失或主体数量不足 → 标 `NOT_EVALUABLE`，不补造 |
| 禁止 | 复制轨迹、重复采样、把同一主体的多个 session 当成独立主体扩充样本量 |

**样本现实（R0.2.1a 修订）**：需区分两个不同口径——(i) **静态角色标签主体有 186 个**（全部有 `team_id`、9 类，且有 group membership，见 §7.5），这是任务 I 的候选样本池；(ii) 其中**角色变更主体仅 3 个**（u4/u019/u044，有 `move_date`），u019/u044 在 golden 中 0 条 QA。不得用"3 个变化主体"推导任务 I 只有 3 个可用主体。**任务 I 当前 `NOT_EVALUABLE` 的真正原因是没有任何 Agentic 轨迹**（ACL benchmark 有真值无轨迹、ASQ 有轨迹无 ACL 真值，禁止拼接），而非静态标签主体数量不足。角色变化分支（B）仍只有 3 主体且 2 无 QA，不支撑可信的跨主体角色变化泛化。

### 6.2 任务 II：同主体权限状态变化检测（纵向监测）

**Estimand**：攻击者已能通过稳定伪标识关联某主体的历史请求；当该主体 ACL 状态改变时，检测其**后续检索轨迹是否发生变化**。这是纵向监测，不是跨主体泛化。

| 要求 | 规格 |
|---|---|
| 事件前后 | 同一主体的事件前、事件后轨迹**允许跨时间使用**——这正是被动持久观察者的威胁模型 |
| 配对完整性 | 同一 ACL 变更事件的 pre/post 配对样本**不得拆散**到不同 train/test 集合 |
| 划分单位 | **按 ACL 事件或独立事件簇划分**训练与测试（不是按主体） |
| 滚动时间划分 | 若采用，必须明确训练事件时间**早于**测试事件时间 |
| 伪标识作用 | 是历史关联键，**不是角色标签，也不能直接作为权限状态的答案** |
| 报告 | 事件级、主体级、主体—容器级样本数（见 §7 统计独立性表） |

**Bootstrap 规则（任务 II）**：
- **不得按单条 probe 重采样**。先根据原始数据中的主体、容器、ACL 事件与探针关联关系识别重复/重叠样本。
- 以**独立 ACL 事件或更高层级的独立事件簇**为重采样单位。
- 若多个事件共享主体或容器，必须解释如何处理相关性（本数据确有此情况：20 条继承传播事件共享 4 个 reason 文本推断的根因、4 个容器各有 2 事件、u5 出现在 10 事件、u4 出现在 11 事件）。事件表**没有结构化父事件字段**，继承关系只存于 reason 文本，精确独立事件簇数 `UNKNOWN`（§7.2）。
- 若最终只能得到很少的独立事件簇，必须报告统计不足，**不得用 148 条探针的记录数量或 19 个目标键数量掩盖独立样本不足**。

### 6.3 两种划分不可混用（写死）

不得同时声称"同一主体严格不跨 train/test"（任务 I）与"用同一主体事件前训练、事件后测试"（任务 II）。报告任何指标前必须标明它属于任务 I 还是任务 II，并使用对应划分。任务 I 的 `NOT_EVALUABLE` 不因任务 II 可做而改变，反之亦然。

### 6.4 关联与不可评估硬规则

- 若服务端**无稳定主体伪标识** → 任务 II 逐主体权限状态变化**不可评估**，不得用研究者侧 `subject_id` 补齐。
- 若服务端**无 session 标识** → 须靠时间戳切分并量化误差（任务合并/割裂/串线，见 THREAT_MODEL §2.1）；若误差大到零点检验失效，则对照 A **不可评估**。
- 若执行模型为 A1（ASQ 默认本地检索、无外包服务端）→ 本实验只能验证因果机制，不得写成外包服务端泄漏；若为 A2（明文）→ 标 `QUERY-VISIBLE DIAGNOSTIC`。见 §2.2 与 `AGENT_GENERATION_AUDIT.md` Query Privacy 章节。

### 7.2 49 条 ACL 事件（6.1 要求，R0.2.1a 修订）

逐条读取的字段：`event_id`、`container`、`timestamp`、`reason`、`allow_users`、`deny_users`、`allow_groups`（**无** `deny_groups`、**无** `inherits_from`/`parent_event`/`root_event` 等结构化父事件字段）。

| 统计对象 | 数值 | 口径 |
|---|---|---|
| 原始记录数 | 49 | 49 个 `event_id` 全部唯一 |
| 不同时间戳数 | **21**（完整 timestamp；按日期为 20） | ≠ 独立事件数 |
| 不同根因 / 父事件数 | **UNKNOWN** | 事件表**没有**结构化根因字段；只能从 `reason` 文本前缀 "Inherited from …" 提取 |
| 已识别继承传播组数 | **4 组，各 5 条 = 20 条** | 根因 token：CONF-IDN-0002 / CONF-SEC-0002 / CONF-PAY-0002 / CONF-EXEC-0002；**这是 reason 文本推断，不是结构化字段** |
| 其余非传播事件 | 29 条，29 个不同 reason 文本 | 无重复 reason；彼此是否共享主体/容器/策略链未确认 |
| **精确独立事件簇数** | **UNKNOWN** | 不强行计算（见下方理由） |

- **不能把 21 个时间戳当 21 个独立事件**：不同根因可能落在同一时间戳（如 2026-07-01 同时发生 u4 转 SEC、PAY deny 两组链），同一策略变更也可能跨多个时间戳体现为连续变化；除 4 组已识别继承传播外，其余事件是否共享主体/容器/策略变更链仍需判断。可确认的依赖关系仅止于"4 组文本推断继承链"，精确独立簇数标 `UNKNOWN`，不给具体数字。
- **容器 / 用户**：49 条事件涉及 **45 个不同容器**；用户字段（`allow_users`/`deny_users`）仅出现 **7 个用户**：u1, u2, u3, u4, u5, u6, u175。
- **用户级 vs 组级**：22 条含 `allow_users`、13 条含 `deny_users`、48 条含 `allow_groups`（无 `deny_groups`）。绝大多数是**组级变化**（`allow_groups` 高频值：leads 20、security-cleared 20、project-aurora-tiger 11、team-identity 8、exec-staff 7…）。
- **同一主体出现在多事件**：u4 出现在 11 条、u5 在 10 条、u6 在 8 条、u175 在 3 条、u2 在 2 条。主体间高度相关，不可当独立样本。
- **同一容器多事件**：4 个容器有 2 条事件（`jira:project:SUP`、`github:repo:aurora-tiger-core`、`slack:channel:C0092`、`slack:channel:C0096`），其余 41 容器各 1 条。

- **实际受影响主体**：**UNKNOWN**。仅凭 `allow_users`/`deny_users` 字段出现的人数**不等于**全部受影响主体——组级变化通过组成员影响更多人，事件时刻组成员需由 `initial_members` + 带时间戳的 `history` 重建（见 §7.4）。事件字段语义为全量状态列表（evidence 记录 45/45 最终态=末事件），但事件时刻的逐主体有效权限范围未在原始文件给出快照，标 `UNKNOWN`。

### 7.6 结论

- 任务 I（跨主体角色推断）：**NOT_EVALUABLE**（186 主体有静态 `team_id` 标签，但 0 条 Agentic 轨迹；u019/u044 在 golden 无 QA 只影响角色变化分支，不影响静态标签覆盖面）。
- 任务 II（同主体状态变化检测）：撤权探针独立单位严重不足（1 主体 / 1 时点 / 19 目标键 / 0 事件关联 / 0 前后轨迹；独立簇 UNKNOWN）；time-travel QA 仅 u4、2 时点真值。**当前原始文件不足以检验主要假设**；须在生成的 opaque 轨迹上按独立事件簇重新构造，并明确事件—探针关联字段与 pre/post 配对。
- 本审计不否定架构 A 因果假设，但表明**统计独立单位是比记录数量更硬的约束**；也不把事实性勘误（组历史非空、静态标签 186）误当成可评估性提升——可评估性的硬阻塞仍是"无轨迹 + 无事件关联"。

## 8. 判死标准（写死，避免事后换指标）

进入 R1 后若出现以下任一，直接 NO-GO 停止该候选方向，不改名/换指标/扩威胁模型：
1. 在确定观测模型下，对照 A 显示 ACL 变化前后服务端可见轨迹无可归因差异（首轮零点一致且后续也一致）；
2. opaque ID 下 B4−B2 主要指标配对 Bootstrap CI 下界 ≤ 0；
3. 差异可由任务语义（对照 C）、模型随机性或语义化 ID 解码（对照 D）解释；
4. 差异依赖 query/thought/answer/真实身份/研究者侧 subject_id 等服务端不可见字段；
5. 主体或 session 无法在服务端可靠关联，且关键对照因此不可评估；
6. 角色变更主体样本经扩充后仍不足、且撤权检测也无稳定增益；
7. （R0.2.1 新增）无法找到符合查询隐私威胁模型的可复核 A3 后端，只能在 A1 本地或 A2 明文下做实验——此时不得写成查询隐私条件下的服务端泄漏结论；
8. （R0.2.1 新增）统计结论依赖把 148 探针 / 继承传播事件 / 同主体多次措辞当作独立样本，而非按独立事件簇重采样。
