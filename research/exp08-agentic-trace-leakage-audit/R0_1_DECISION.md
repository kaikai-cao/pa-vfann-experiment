任务：EXP-02-R0.1 复现性修复与实验可行性核验；经 EXP-02-R0.2、EXP-02-R0.2.1、EXP-02-R0.2.1a 独立审查后修订裁决理由。工作分支 `exp08-agentic-trace-leakage-audit`。起始提交 `05b58462293dd28064dcb433501a09f5cea8c68d`；R0.1 提交 `5247445872db7b266e8ada6776520be41bc4041d`；R0.2 提交 `14862ad2b775d1005f47d6ca3a734de0b61fca31`；R0.2.1 提交 `2623c3ed0b0c7f2aec77f6f28260de101bb7a82e`；本次为同分支 R0.2.1a 修订提交。

**修订缘由**：
- R0.2 修正了一处逻辑跳步——架构 A 存在"ACL→上下文→后续查询→服务端轨迹"的间接通道，不应在实验前因混有任务自适应行为而降为阴性对照；架构 C 也不能把 TEE/ORAM/PIR/加密过滤合并为单一可见性模型。
- R0.2.1 修正两处更硬的阻塞：(i) 源码审计确认 ASQ 默认是 A1 本地检索、明文查询直传本地 PyTerrier，**不存在外包服务端观察主体**，因此"服务端看不到查询明文"的旧假设不成立——须区分 A1/A2/A3 执行模型，且当前 `NO VERIFIED QUERY-PRIVATE RETRIEVAL BACKEND`；(ii) 原始数据实测表明 148 撤权探针只有 1 主体、19 目标、无事件关联字段，49 事件仅 21 时间戳且含 20 条继承传播事件——统计独立单位远小于记录数，两类 estimand 必须分开划分。本版据此重写裁决。
- R0.2.1a 按独立验收意见只修统计口径，不改裁决等级：19 个目标键是 distinct target keys 而非已证实的独立统计簇（独立簇 `UNKNOWN`）；49 事件的精确独立簇数无法从原始字段确认（`UNKNOWN`，只报告 4 组由 event_id 命名家族识别、reason 交叉印证的继承传播家族）；静态角色标签主体实为 186/186（非 3），3 个 `move_date` 主体只用于角色变化检测；并纠正"组历史为空"的事实错误（全局 14 组共 19 条历史，三个变化主体均有主体级记录）。详见 `MINIMAL_EXPERIMENT_DESIGN.md` §7。R0.2.1a.1 再补三处措辞（不重审数据）：继承依据补全为 event_id 命名家族 + reason、组覆盖限定为 membership coverage（含 all-hands 通用组）、Task II 从"独立簇严重不足"改为"独立簇 UNKNOWN + 无可确认关联/配对"。

## 1. 最终结论：**HOLD**（理由按 R0.2.1 三层状态修订）

**修订后的 HOLD 理由**：阻塞是三项并列的前置条件——(1) **确定真实、可复核的服务端观测模型**（含 A1/A2/A3 执行模型、字段契约与主体/session 关联）；(2) **找到符合查询隐私要求的 A3 检索后端**（当前无）；(3) **为两类 estimand 构造足够独立统计单位**（当前任务 I `NOT_EVALUABLE`；任务 II 的精确独立事件簇数量 `UNKNOWN`，当前没有可确认的 probe–event 关联和 pre/post 轨迹，因此 `NOT_EVALUABLE`）。三者均可由明确、有限的工作解决，故仍为 HOLD 而非 NO-GO。

这是**有界 HOLD**：五项前置一旦满足，下一步只有"生成 opaque 轨迹 + A/B/C/D 对照 + B2/B4 配对对照"这一个实验，判死标准已写死（`MINIMAL_EXPERIMENT_DESIGN.md` §8）。不得把 A1 因果机制验证或 A2 诊断结果包装成查询隐私条件下的服务端泄漏。

### 三种裁决条件（写死，避免事后移动门槛）
- **GO（只允许进入有限 R1）**：找到具体、可复核的查询隐私后端（A3），能支持多轮检索并暴露明确的服务端轨迹；主体/session 关联方式明确；至少一个主要评估任务具备足够独立统计单位。GO 仅允许进入有限 R1，不代表选题成立。
- **HOLD**（当前状态）：查询隐私后端、主体/session 关联、或独立事件簇仍有明确且可解决的阻塞。
- **NO-GO（针对当前实验路线）**：ASQ 默认检索器之外无法找到符合威胁模型的可复核后端；或具体后端隐藏了所有目标轨迹；或 ACL 原始数据无法提供必要真值配对；或独立统计单位不足以检验主要假设。

**关键边界**：若只是 ASQ 默认 BM25（A1 本地）不符合威胁模型，**不能直接宣称整个研究问题 NO-GO**——架构 A 的间接因果链仍待检验；但必须明确 **ASQ 不能直接作为查询隐私条件下的正式后端**。NO-GO 只针对"当前 ASQ 实验路线"，且命中后不得通过增加新架构类别、候选论文题目或指标挽救。

**不得因架构 A 或架构 C 中某一个不成立就更换名称或无限扩展威胁模型挽救候选方向。**

## 2. 修订后的架构判断

| 架构 | R0.1 初稿判断 | R0.2 修订判断 |
|---|---|---|
| A 客户端过滤 | 无直接信号 → 阴性对照 | **首选主场景（待检验）**：直接过滤结果不可见，但 ACL→上下文→后续自适应检索→服务端可见轨迹构成间接泄漏因果链，正是 Agentic RAG 新增泄漏面；是否可归因于 ACL 须对照实验判定 |
| B 服务端过滤 | 循环论证 → 排除 | 维持：攻击者已知 ACL = 把已知当推断；除非改写攻击者定义并单列 |
| C 加密/隐私保护过滤 | 唯一自洽主架构 | **降为候选类别**：TEE/ORAM/PIR/加密策略匹配可见性截然不同，未选定具体机制前不能认定可见字段，也不能写成唯一成立场景 |

核心研究问题（修订后）：在客户端执行 ACL 过滤、Agent 根据授权上下文多步自适应检索的条件下，外包检索服务能否仅凭跨调用可见轨迹推断主体权限范围或状态变化？这是**待检验假设**，非已成立创新点。

## 3. 服务端可观察字段契约（见 `OBSERVABILITY_AUDIT.md` §4）

10 项字段逐项判定为"可见 / 不可见 / 需要实现核验"：opaque docid、请求是否独立发送、返回 ID 与数量、rank 顺序、时间戳、稳定主体伪标识、session 标识、查询明文、查询向量、ACL 与角色标签。

- **三个标识严格区分**：主体伪标识（服务端可见稳定 token，跨会话关联同一主体，不含真实身份）／session 标识（区分同一主体不同任务）／真实身份（研究者侧，攻击者不可得）。研究者侧 `subject_id`/`qid`/`asking_user` **不是**服务端可见字段。
- **无稳定主体伪标识** → 逐主体权限状态变化推断**不可评估**，不得用研究者侧字段补齐。
- **无 session 标识** → 只能按时间戳阈值切分，误差含任务合并 / 割裂 / 串线，会污染对照 A 的零点检验。

## 4. 主体 / session 关联可行性结论

- 当前**无法确认**服务端是否提供稳定主体伪标识与 session 标识（THREAT_MODEL.md 默认不可见，需目标系统实现核验）。
- 因此**逐主体的权限状态变化检测在服务端视角尚不具备可靠关联条件**——这是与观测模型并列的第二个前置阻塞。
- 若最终两者都不可见，则本候选方向中"逐主体权限状态变化推断"必须标记为**不可评估**，不得降级为研究者侧字段驱动的伪实验。
- R0.2.1 实测、R0.2.1a 口径修订补充：即使假设关联可用，原始数据仍无法确认足量独立单位——148 撤权探针全为 u4（1 主体、1 时间点、19 distinct 目标键、**0** 可确认事件关联、**0** pre/post 轨迹配对；独立簇 `UNKNOWN`）；49 事件仅 21 时间戳且含 4 组由 event_id 命名家族识别、reason 交叉印证的继承传播家族（每组 1 根 + 5 传播，共 20 条传播记录；精确独立簇 `UNKNOWN`）。静态角色标签主体为 186/186，u019/u044 无 golden QA 只影响角色变化分支。详见 `MINIMAL_EXPERIMENT_DESIGN.md` §7。

## 6. 关键未解决问题（按优先级，R0.2.1 更新）

1. **查询隐私后端缺失（新增主阻塞）**：ASQ 默认 A1 本地检索，明文查询直传本地 PyTerrier、无外包服务端；当前 `NO VERIFIED QUERY-PRIVATE RETRIEVAL BACKEND`。无法找到合规 A3 后端时，只能做 A1 因果机制验证或 A2 `QUERY-VISIBLE DIAGNOSTIC`，不能写成查询隐私下的服务端泄漏。
2. **服务端观测模型未确定（主阻塞）**：pa-vfann 的 E1/E2/E3 与（假设的）外包检索服务的字段契约未逐项核验；架构 A 的间接泄漏因果链是否真实存在、后续轨迹是否可归因于 ACL，均须在该模型下用对照 A 检验。
3. **主体 / session 关联未确认（并列前置）**：服务端是否可见稳定主体伪标识与 session 标识；若无，时间戳切分误差是否可接受。
4. **统计独立单位不足（R0.2.1 实测 / R0.2.1a 口径修订，非"样本相对充足"）**：任务 I 跨主体推断 `NOT_EVALUABLE`（186/186 主体有静态 `team_id` 标签，但 0 条 Agentic 轨迹；u019/u044 无 QA 只影响角色变化分支）；任务 II 撤权探针 148 条仅 1 主体 / 1 时点 / 19 distinct 目标键 / 0 事件关联 / 0 前后轨迹，49 事件仅 21 时间戳且含 4 组由 event_id 命名家族识别、reason 交叉印证的继承传播家族（每组 1 根 + 5 传播，精确独立簇 `UNKNOWN`）——**不能用 148 probes + 32 events 相加充当样本量，也不能把 19 目标键或 21 时间戳当独立簇**。须按独立事件簇重建配对并补事件关联字段与 pre/post 轨迹。
5. **生成器依赖（工程）**：search_r1 本地权重 / gpt_oss API 密钥，进入 R1 须明确后端与成本。
