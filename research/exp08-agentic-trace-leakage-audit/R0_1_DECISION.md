# R0_1_DECISION.md — EXP-02-R0.1 裁决（R0.2 修订版）

任务：EXP-02-R0.1 复现性修复与实验可行性核验；经 EXP-02-R0.2 独立审查后修订裁决理由。工作分支 `exp08-agentic-trace-leakage-audit`。起始提交 `05b58462293dd28064dcb433501a09f5cea8c68d`；R0.1 提交 `5247445872db7b266e8ada6776520be41bc4041d`；本次为同分支修订提交。

**修订缘由**：独立审查指出 R0.1 初稿有一处逻辑跳步——在 `OBSERVABILITY_AUDIT.md` §1.2 承认架构 A 存在"ACL→上下文→后续查询→服务端轨迹"的间接通道后，却因信号混合任务自适应行为而在实验前把架构 A 降为阴性对照，并断言"仅架构 C 自洽"。混合信号应通过对照实验分离，不能在实验前判定无研究价值；且架构 C 把 TEE/ORAM/PIR/加密过滤合并为单一可见性模型也是错误的。本版修正裁决理由，不回避这一错误。

## 1. 最终结论：**HOLD**（理由已修订）

**修订后的 HOLD 理由**：真正的阻塞**不是**"必须先确认目标系统采用架构 C"，而是**必须先确定一个真实、可复核的服务端观测模型**——明确外包检索服务在 Agentic 多步执行中究竟可见哪些字段（含主体/session 关联能力）。该模型**可以是架构 A（客户端过滤），也可以是某个具体的架构 C**；不得为保留候选方向而预先指定 C，也不得因架构 A 曾被认为"无信号"而排除它。

这是**最后一次有界 HOLD**：观测模型一旦确定，下一步只有"生成 opaque 轨迹 + A/B/C/D 对照 + B2/B4 配对对照"这一个实验，判死标准已写死（`MINIMAL_EXPERIMENT_DESIGN.md` §7）。

### 三种裁决条件（写死，避免事后移动门槛）
- **GO**：存在一个明确、可复核的服务端观测模型（架构 A 或具体架构 C），且 A/B/C/D 对照能够在该模型下检验"ACL 引起的多步轨迹变化"。GO 仅允许进入有限 R1，不代表选题成立。
- **HOLD**（当前状态）：观测模型本身，或主体伪标识 / session 标识的服务端关联能力，尚未得到确认。
- **NO-GO**：在选定的具体观测模型下，权限状态不影响服务端可观察轨迹（如对照 A 首轮零点一致且后续也无差异），或实验无法排除任务语义、模型随机性与 ID 伪相关。

**不得因架构 A 或架构 C 中某一个不成立就更换名称或无限扩展威胁模型挽救候选方向。**

## 2. 修订后的架构判断

| 架构 | R0.1 初稿判断 | R0.2 修订判断 |
|---|---|---|
| A 客户端过滤 | 无直接信号 → 阴性对照 | **首选主场景（待检验）**：直接过滤结果不可见，但 ACL→上下文→后续自适应检索→服务端可见轨迹构成间接泄漏因果链，正是 Agentic RAG 新增泄漏面；是否可归因于 ACL 须对照实验判定 |
| B 服务端过滤 | 循环论证 → 排除 | 维持：攻击者已知 ACL = 把已知当推断；除非改写攻击者定义并单列 |
| C 加密/隐私保护过滤 | 唯一自洽主架构 | **降为候选类别**：TEE/ORAM/PIR/加密策略匹配可见性截然不同，未选定具体机制前不能认定可见字段，也不能写成唯一成立场景 |

核心研究问题（修订后）：在客户端执行 ACL 过滤、Agent 根据授权上下文多步自适应检索的条件下，外包检索服务能否仅凭跨调用可见轨迹推断主体权限范围或状态变化？这是**待检验假设**，非已成立创新点。

## 3. 服务端可观察字段契约（见 `OBSERVABILITY_AUDIT.md` §4）

10 项字段逐项判定为"可见 / 不可见 / 需要实现核验"：opaque docid、请求是否独立发送、返回 ID 与数量、rank 顺序、时间戳、稳定主体伪标识、session 标识、查询明文、查询向量、ACL 与角色标签。

- **三个标识严格区分**：主体伪标识（服务端可见稳定 token，跨会话关联同一主体，不含真实身份）／session 标识（区分同一主体不同任务）／真实身份（研究者侧，攻击者不可得）。研究者侧 `subject_id`/`qid`/`asking_user` **不是**服务端可见字段。
- **无稳定主体伪标识** → 逐主体权限状态变化推断**不可评估**，不得用研究者侧字段补齐。
- **无 session 标识** → 只能按时间戳阈值切分，误差含任务合并 / 割裂 / 串线，会污染对照 A 的零点检验。

## 4. 主体 / session 关联可行性结论

- 当前**无法确认**服务端是否提供稳定主体伪标识与 session 标识（THREAT_MODEL.md 默认不可见，需目标系统实现核验）。
- 因此**逐主体的权限状态变化检测在服务端视角尚不具备可靠关联条件**——这是与观测模型并列的第二个前置阻塞。
- 若最终两者都不可见，则本候选方向中"逐主体权限状态变化推断"必须标记为**不可评估**，不得降级为研究者侧字段驱动的伪实验。
