# THREAT_MODEL.md — EXP-02-R0 威胁模型规格

本文件定义的是**候选实验规格**，不是已验证事实。任何字段只有在具体系统实现中确实暴露给服务端时，才可进入攻击者输入。

---

## 1. 攻击者

**被动、持久观察的外包检索服务**（passive, persistent, honest-but-curious retrieval server）：

- 诚实执行协议，不注入查询、不篡改数据库或返回结果；
- 持久记录跨调用、跨会话的服务端视图；
- 没有解密密钥，不接触客户端本地状态；
- 可以持有独立获得的辅助知识（例如已知文档标签比例、少量已知 ID-标签对），但辅助知识必须逐项声明并计入基线公平性。

与 SAGE 的关系：SAGE 原文 §III-B 使用同样的 passive/persistent server-side adversary；差别在推断目标与是否利用多步结构，不在攻击者道德取向。

---

## 2. 可观察信息：逐项核实表

下表「基础模型」一栏是本轮采用的**保守基线**：只列入几乎必然由检索服务看到的最小集合；任何额外字段必须单独论证，不得默认加入。

| 候选字段 | ASQ 原始字段 | 基础模型中是否可见 | 逐项理由 / 条件 |
|---|---|---|---|
| 不透明文档 ID | `retrieved_docs.tsv: docid` | **是** | 检索请求返回给客户端必然经过服务端；ID 跨调用可关联是 SAGE 的前提。若使用每窗口独立 pseudonym 且阻断跨窗口链接，则本项被削弱（SAGE 附录 C-E） |
| 每次调用的返回 ID 集合 | 由 `qid, iteration` 分组的 docid 集合 | **是** | 与 SAGE 的 `I_i` 同型；本审计抽查集合中每次调用 3 篇（k=3） |
| 返回结果数量 | `len(rows per call)` | **是** | 服务端构造响应即可知；注意 ASQ 存在无检索结果的 qid（53 条） |
| 返回顺序 / rank | `rank` | **条件可见** | 若检索结果按排名返回给客户端，服务端通常知道；SAGE 明确不用排序，因此 B2 应禁用，B4 是否可用需与 B2 公平对照 |
| 调用顺序 / 轮次 | `iteration` | **条件可见** | 只有当客户端把每一步检索作为独立服务请求发出时可见；若客户端批量提交或缓存检索，则不成立。**不得仅因数据集有 iteration 列就认定服务端可见** |
| 时间戳 / 墙钟时间 | ASQ 中**不存在** | 否 | ASQ 只有序数 iteration；时间信息须在生成轨迹时另行记录，且只有服务端 API 日志确实记录时才可用 |
| 任务 / 会话标识 | `qid` | **否（默认）** | `qid` 是数据集评测标识，不是协议字段；只有在系统把 session/task token 随请求发送时才可见。B3/B4 若使用任务分组，必须先确认该架构事实 |
| 用户 / 主体标识 | 数据集无；ACL Benchmark 有 `asking_user` | **否（默认）** | 若检索服务按用户 API key 或租户标识路由，则可观察到「调用归属」（可能只是 pseudonymous subject）；这是架构相关扩展，必须单独声明 |
| 查询明文 / 文本 | `iter_queries.tsv: llm_query` | **否（仅 A3 合规后端下）** | R0.2.1 修订：不得再无条件默认不可见。ASQ 默认是 A1 本地检索（本地进程可见、无外包服务端），不是"服务端看不到"。只有当正式实验采用经 `AGENT_GENERATION_AUDIT.md` Query Privacy 章节核验通过的 A3 后端时，才可标为服务端不可见。若用 A2 明文 BM25，则服务端可见明文 → 退化为普通语义分类，只能作 `QUERY-VISIBLE DIAGNOSTIC`。见 §2.2 |
| 查询向量 | 数据集无 | **需区分**（明文/加密/受保护表示） | R0.2.1 修订：须区分明文向量、加密向量与其他受保护查询表示；明文向量有嵌入反演风险，属另一问题。判定依赖具体后端 |
| 相似度分数 / 距离 | 数据集无 | **否** | 与 SAGE 一致，基础模型不假设可用 |
| 过滤谓词 / 策略 token | 无 | 否（基础模型） | 服务端执行过滤的系统（如 AFR）会看到策略相关信号，属另一架构，另列 |

**硬规则**：任务包禁止「把研究者可见字段当成服务端可见字段」。因此 `llm_query`、`thought`、`answer`、`qid`（默认）全部排除在攻击者特征之外。

### 2.1 三个标识的严格区分（R0.2 新增，关键）

实验设计需要跨调用关联主体与任务，但基础模型默认这些标识不可见。必须区分三种标识，不得混用：

| 标识 | 作用 | 服务端可见性 | 是否含真实身份 |
|---|---|---|---|
| **主体伪标识** | 跨会话关联同一主体（如 API key 哈希、租户 ID） | **需要实现核验**——若存在则是稳定 token | 否，不可映射到真实姓名/角色真值 |
| **session / 任务标识** | 区分同一主体的不同 Agent 任务 | **需要实现核验**——默认否 | 否 |
| **真实身份**（`asking_user`、`subject_id` 等） | 研究者侧构造真值与划分 | **不可见**（攻击者不应获得） | 是（研究者侧） |

**后果（必须在实验规格中显式处理）**：
- **无稳定主体伪标识** → 逐主体的权限状态变化推断缺少关联条件，该项**不可评估**；不得把研究者侧 `subject_id` 当作服务端可见字段补齐。
- **无 session 标识** → 只能靠服务端时间戳做会话切分（间隔阈值 θ），误差包括：相邻任务间隔 <θ 导致**任务合并**、单任务内部停顿 >θ 导致**任务割裂**、并发交错导致**轨迹串线**。这些误差会污染"同一任务、不同权限"的对照零点检验。

详细字段契约（10 项逐项可见/不可见/需核验）见 `OBSERVABILITY_AUDIT.md` §4。

### 2.2 查询相关字段的隐私判定规则（R0.2.1 新增，关键）

R0.2.1 源码审计（`AGENT_GENERATION_AUDIT.md` Query Privacy 章节）确认：ASQ 默认检索是 **A1 本地执行**，`query` 明文从 Agent 经 `search_pipeline.search(query, qid)` 直传本地 PyTerrier Retriever，全程无网络边界、无外包服务端。因此"查询明文默认不可见"的旧假设**不成立**——不能因为日志不记录明文就推断服务端看不到。查询相关字段必须按下列规则逐项判定：

| 字段 | 判定规则（R0.2.1） |
|---|---|
| Agent 查询明文 | 只有确认**不进入服务端执行边界**（即 A1 本地，或经核验的 A3 后端）后，才可标为对服务端不可见；A2 明文检索下服务端可见 |
| 查询向量 | 必须区分明文向量 / 加密向量 / 其他受保护表示；三者的服务端可见性与反演风险不同，不得笼统标"不可见" |
| 查询令牌 / 密文 | 即使不含明文，也必须核验**长度、确定性、重复关系与跨请求可关联性**；确定性令牌会泄漏"重复查询"信号 |
| 查询长度 / 通信量 | 按具体系统实际暴露情况判断；无填充时长度/批次大小本身是信号 |
| 查询调用频率 | 若服务端能看到请求时间，则频率/节奏通常可见，须单独纳入观察面 |
| 后续请求间关联 | 不得把"查询内容被隐藏"等同于"查询不可关联"；隐藏内容但保留稳定令牌/会话关联仍是泄漏面 |

**正式实验门槛（写死）**：
- 若坚持"查询明文不可见"的核心假设，正式实验**必须**具备一个满足 `AGENT_GENERATION_AUDIT.md` Query Privacy 章节核验要求的具体查询保护后端（A3）。当前结论为 `NO VERIFIED QUERY-PRIVATE RETRIEVAL BACKEND`。
- 若使用 **A2 明文 BM25**，结果只能单独标记为 `QUERY-VISIBLE DIAGNOSTIC`，用于诊断任务语义对轨迹的影响，**不得**写成查询隐私条件下的服务端泄漏结论。
- 若只有 **A1 本地检索**，本地生成的日志**不等同于外包服务器的真实观察**；只能用于验证 Agent 生成与 ACL 因果机制（如对照 A 的零点与后续差异），不能冒充外包服务端实验。

## 3. 不可观察信息

1. 查询明文与查询嵌入（**仅在经核验的 A3 后端下成立**；ASQ 默认 A1 本地检索中明文对本地检索进程可见、且无外包服务端——见 §2.2。不得无条件列为不可观察）。
2. 文档内容与语义标签（服务端只见 ID）。
3. 真实 ACL、策略内容、当前有效权限集合。
4. 用户角色标签、部门标签（除非服务端按租户/API key 路由，此时只得到 pseudonymous 分组，不等于角色真值）。
5. Agent 内部推理（`thought`）、最终答案（`answer`）。
6. 客户端本地保存的状态、未传输给服务端的过滤结果（例如 PA-VFANN 的 `secret_filter` 模拟接口）。
7. 跨窗口 ID 链接（若部署了严格 ID rotation 且无其他元数据可链接）。

若某架构向服务端暴露额外信息（例如服务端执行 ACL 过滤、查询明文、用户 API key、稳定 session token），必须作为**扩展威胁模型**单独记录，并与基础模型分开报告；不得把扩展模型的结果写成基础模型的结论。

## 4. 系统架构假设（必须显式）

基础模型最接近 SAGE 的加密向量检索部署：

- 数据拥有者在客户端加密/编码内容，外包可检索索引；
- 检索服务处理每个检索请求并返回**跨请求可关联的文档 ID**；
- 查询以服务端不可读形式提交——**这是 A3 合规后端的假设，ASQ 默认（A1 本地检索）不满足，当前无已核验的 A3 后端**（见 §2.2）；
- Agent 在客户端本地执行多步推理，逐步发起检索；
- 服务端只能看到「何时收到一个请求、返回了哪些 ID、多少条、是否按 rank 返回」。

**执行模型对齐（R0.2.1 新增）**：本文件的基础模型对应 A3（受保护查询 + 外包服务端）。ASQ 上游默认是 A1（本地检索、无服务端）；A2（明文外包检索）不满足查询隐私。三者不可混用，任何结论必须标明是在哪个执行模型下得到。

**未决架构事实（阻塞 B3/B4 的合法性）**：

- 任务边界（session/task id）是否随请求发送？若不发送，服务端只能靠时间间隔聚类任务，B3/B4 的「任务分组」在攻击者视角不可实现。
- 每个 Agent 内部检索步骤是否对应独立服务请求？若客户端一次批量发出全部子查询，则「调用顺序」不可观察。
- 是否向服务端暴露用户标识（API key / tenant id）？若否，则即便推断出「某组轨迹属于同一主体」，也不能直接映射到 ACL Benchmark 的 `asking_user`。

本轮只审计数据，不验证具体系统实现；上述三项在 EXP-02-R1 前必须逐项确认，否则 B3/B4 只能作为**上界诊断**而非服务端攻击。

## 5. 目标推断任务

主要目标（必须严格区分，不能互相替代）：

1. **Role Inference**：推断用户角色类别（例如 ACL Benchmark 的 team / group 成员身份）。
2. **Effective Permission Scope Inference**：推断某主体在某时刻的有效授权范围（可访问的容器/文档集合或其摘要），多标签设定。
3. **Policy-State Inference**：推断授权状态（例如「处于转队前/后」「临时授权窗口开/关」）。
4. **Revocation Detection**：检测撤权事件是否发生（二分类或时序检测，AUROC）。

次要目标：

5. **Task-Category Inference**：推断 Agent 任务类别，用于与 SAGE 的查询类别/语义能力对照。

**明令禁止的混淆**：任务类别推断 ≠ 权限范围推断。即使 B4 能准确识别「这是财务相关任务」，也不能声称它推断了「该用户有权访问哪些文档」。只有在有 ACL 真值且控制命名空间伪相关后，主要目标的指标才有效。

## 6. 与 SAGE 威胁模型的差异

| 维度 | SAGE | 本候选问题 |
|---|---|---|
| 攻击者 | passive/persistent server，无密钥 | 同 |
| 可观察 | 无序返回 ID 集合序列 ℒ_AP=(I₁,…,I_M)；不用分数/排序 | 同样以返回 ID 为基础；额外候选：rank、调用顺序、任务分组——但均需架构确认 |
| 辅助知识 | 类别比例 π̂ 或 1% 已知 ID-标签对；已知 C | 可沿用同类辅助知识；角色/权限标签若有，必须来自可信 ACL 真值 |
| 推断目标 | 记录语义标签 λ、查询语义类别 ℓ | 角色、有效授权范围、策略状态、撤权；任务类别只作对照 |
| 时间维度 | 静态数据库、固定查询序列；无策略变化 | 引入权限变化事件与 `asked_at`；这是新增维度，但当前数据集无法直接提供对应轨迹 |
| ID 防御 | 固定 pseudonymization 无效（图同构）；理想 rotation 降低准确率（锚点条件敏感） | 同条件适用；且必须用 opaque ID 排除命名空间解码伪相关 |
| 多步结构 | 不使用顺序/分组 | B3/B4 的核心差异点；是否能带来超出共现的增益尚未验证 |

## 7. 威胁模型边界小结（R0.2 → R0.2.1 修订）

基础模型内的合法输入只有：返回 ID 集合、返回数量、（条件）rank、（条件）调用顺序、（默认否）任务分组、（需核验）主体伪标识与 session 标识。任何结论若依赖 `llm_query`、`thought`、`answer`、语义化 docid 字符串、研究者侧 `subject_id`、或未经确认的 session 字段，都不得写成「服务端泄漏」。

R0.2 的关键补充：架构 A（客户端过滤）中，ACL 过滤结果本身不可见，但它通过改变 Agent 上下文进而改变**后续检索请求**，形成一条服务端可见的**间接泄漏因果链**。这条链路是 Agentic RAG 相比单轮检索新增的泄漏面，属于**待检验假设**，不得在实验前因"混有任务自适应行为"而排除。真正的前置条件是确定真实、可复核的服务端观测模型（含 §2.1 的主体/session 关联），见 `OBSERVABILITY_AUDIT.md` §4 与 `MINIMAL_EXPERIMENT_DESIGN.md`。

R0.2.1 的关键补充：执行模型必须先对齐——ASQ 默认 A1（本地检索、无外包服务端）**不构成**外包服务端泄漏实验；A2（明文外包检索）只能作 `QUERY-VISIBLE DIAGNOSTIC`；只有经核验的 A3 后端才可能支撑"服务端看不到查询明文"的正式结论。当前为 `NO VERIFIED QUERY-PRIVATE RETRIEVAL BACKEND`。因此即便架构 A 的间接因果链成立，也缺少一个合规的查询隐私实验后端来验证它。见 §2.2 与 `AGENT_GENERATION_AUDIT.md` Query Privacy 章节。

**不可评估规则**：若主体伪标识或 session 标识在服务端不可可靠关联，逐主体的权限状态变化检测必须标记为**不可评估**，不得以研究者侧字段补齐。若查询明文对服务端可见（A2）或无外包服务端（A1），对应结果不得写成查询隐私条件下的服务端泄漏。
